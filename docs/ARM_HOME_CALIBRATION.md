# S1 양팔 기준 자세 보정

한 번에 한 팔을 선택한다. 사용자가 물리 자세와 집게 중간 벌림을 맞춘 뒤,
그 상태를 모터 raw 2048로 만드는 유지보수 절차다. **2048로 이동시키는 명령이 아니다.**
이 자세가 기구 모델에서 어떤 각도인지도 별도로 기록해야 한다.

## 도구와 범위

- 펌웨어: `home-assistant-s1-calibration` preset, INFO 식별값 `arm-calibration-v1`.
- 진입점: `tools/run/calibrate_arm_home.py`. `--arm left` 또는 `--arm right` 필수.
- 기본 실행: INFO와 선택한 팔의 EEPROM/현재값을 읽고 백업. 토크가 이미 0이어야 한다.
- `--center`: 기록된 기준 자세에서 선택 팔 ID 6→1 순서로 보정하고 읽어서 확인.
- `--verify-record`: 전원을 껐다 켠 후 이전 성공 기록과 EEPROM을 읽기 전용으로 비교.
- 다른 팔과 모바일 ID 7–10에는 읽기/쓰기하지 않는다. 부팅 시 모터 통신도 없다.
- 펌웨어 명령마다 `LEFT`/`RIGHT`를 명시하며, 보정 시도 기록은 팔별로 관리한다.
  버스 전송 계층도 ID 1–6의 READ, 레지스터 40의 값 0/128만 허용한다.
  목표 위치/속도, 토크 ON, broadcast, 임의 EEPROM 쓰기는 허용하지 않는다.

현재 공통 조회 펌웨어와는 호환되지 않는 **보정 전용 이미지**다. 팔을 바꿀 때 이미지를
다시 바꿀 필요는 없다. 보정 종료 후 새 영점에 맞춘 모델/범위를 준비해서 공통 제어기로 복귀한다.
보정 직후 예전 실행 프로필을 그대로 사용하지 않는다. 유지보수와 실제 동작용 공통 제어를 구분한다.

## 진행 순서

1. 모터 전원 OFF와 팔·리프트 지지 확인 후 기존 flash를 젯슨에 백업하고 보정 이미지 기록/검증.
2. 모터 전원을 켜고 선택한 팔의 토크 OFF를 읽어서 확인. 사용자가 기준 자세와 집게 중간을 맞춘다.
3. 선택한 팔의 40바이트 EEPROM과 위치를 두 차례 읽어 안정성을 확인하고, 디스크에 백업을 확정한다.
4. 기준 자세 설명을 포함한 새 파일에 `--center` 실행. 각 관절 보정 직전 자세·offset을 다시 확인한다.
5. 위치 2048±8, 토크 OFF, offset 두 바이트 외 EEPROM 불변을 확인한다.
6. 모터 전원을 껐다 켠 뒤 `--verify-record`로 보정 저장 여부를 확인한다. 다른 팔도 같은 절차로 진행한다.

```bash
# 기본: 읽기 백업만. 출력은 항상 새 경로를 사용한다.
python3 tools/run/calibrate_arm_home.py --arm left \
  --port /dev/serial/by-id/<STM32-포트> --output output/home-assistant/s1/left-home-before.json

# 사용자가 선택한 팔의 기준 자세를 확정하고 받친 후에만 실행한다.
python3 tools/run/calibrate_arm_home.py --arm left --center \
  --reference-note '<실제 기준 자세와 집게 상태 설명>' \
  --port /dev/serial/by-id/<STM32-포트> --output output/home-assistant/s1/left-home-centered.json
```

백업 실패·자세 변화·응답 불확실이면 중단하고 자동 재시도하지 않는다. MCU에서는 이미 시도한
관절을 같은 부팅에서 다시 보정할 수 없다. `incomplete_do_not_retry` 기록이 있으면
재시작으로 우회하지 말고 저장 기록과 실제 EEPROM을 읽어 대조한다.
모터 보정값을 설정하는 것은 전체 기구의 영점/방향/충돌 범위 검증 완료와 다르다.

## 새 Home 기준 범위 환산

2026-10-29 양팔 12개 모터의 보정과 모터 전원 재인가 후 EEPROM 일치를 확인했다.
환산 도구 `tools/setup/firmware/rebase_arm_home.py`와
검토 기록 `config/home_assistant/arm_home_rebase.review.json`을 추가했다.
기존 실행용 `config/bimanual_operational_limits.json`과 생성 C/ROS 사본은 변경하지 않았다.

STS 오프셋의 부호-크기 표현을 해석하여 `(이전 offset - 새 offset) mod 4096`으로
같은 물리 자세의 raw 변화량을 계산한다. 실측 전후 위치와 8 raw 이내로 일치해야 하며,
전원 재인가 증거가 정확한 보정 파일의 SHA256과 EEPROM에 연결되는지 검사한다.
전체 구간을 같은 값만큼 이동시켜 폭을 유지하고, 양 끝을 개별 modulo 처리하지 않는다.
따라서 어깨의 4095→0 경계를 통과하는 연속 구간도 유지한다.

**아래 범위는 과거 범위의 좌표계가 이번 보정 직전 좌표계와 같다는 가정 아래의 계산값이다.**
과거 기록에는 측정 당시 EEPROM offset이 없어 그 연결을 아직 증명할 수 없다.
또한 사용자가 일부 관절의 혼/링크를 분리 후 다시 조립했다고 확인했으며, 사용자는 해당 관절을 기억하지 못한다고 답했다.
링크 장착 각도 변경은 이번 EEPROM 변화량만으로 복원할 수 없다.

| 관절 | 왼팔 raw 변화량 | 왼팔 조건부 범위 | 오른팔 raw 변화량 | 오른팔 조건부 범위 |
|---|---:|---:|---:|---:|
| 몸통 회전 | -25 | 958–3016 | +1029 | 2137–4025 |
| 어깨 | -14 | 1885–4173 | -8 | 1851–4180 |
| 팔꿈치 | +173 | 459–2665 | -221 | 76–2302 |
| 손목 굽힘 | -162 | 8–2222 | -314 | 63–2124 |
| 손목 회전 | 0 | 587–2838 | +33 | 782–3003 |
| 집게 | +61 | 1933–3318 | -4 | 1903–3295 |

오른팔 몸통 회전은 새 Home 2048이 환산 하한 2137보다 89 raw(약 7.8°) 작다.
Home을 포함시키려고 범위를 임의 확장하지 않는다. 이 불일치는 환산 가정 또는 현재 조립의
작업 범위를 확인해야 한다는 의미이며, Home 자체가 물리적으로 위험하다는 판정은 아니다.
다른 관절의 Home 포함 여부 역시 전체 구간의 현재 사용 가능성을 증명하지 않는다.
과거 방향 `[+1,+1,-1,-1,+1,-1]`은 좌표 관례로 유지하고, 새 Home과 URDF 영점 관계는 별도다.

실행 예:

```bash
python3 tools/setup/firmware/rebase_arm_home.py \
  --left-centered output/home-assistant/s1/left-home-centered-20261029-001.json \
  --left-persistence output/home-assistant/s1/left-home-persistence-20261029-001.json \
  --right-centered output/home-assistant/s1/right-home-centered-20261029-001.json \
  --right-persistence output/home-assistant/s1/right-home-persistence-20261029-001.json \
  --output output/home-assistant/s1/new-home-range-review.json
```

출력은 `REVIEW_ONLY_NOT_RUNTIME_LIMITS`, `firmware_limit_authorized=false`이며 기존 런타임
로더가 거부하는 별도 기록 형식이다. 관련 테스트 31개 통과: 오프셋 부호/랩 경계,
잘못된 팔·보정 해시·전원 재인가 기록·위치 변화 검출, 범위 폭 유지, 실행용 프로필 혼용 차단.
사용자 요청에 따라 관절 범위 확정은 보류하며, 이를 상위 계층 소프트웨어 개발의 선행 조건으로 두지 않는다. 실제 구동용 범위 반영은 완료되지 않았다.

## 현재 조립 기준 손측정 재개

이후 사용자가 지금 범위를 측정하기로 변경하여 양팔 토크 OFF와 보정 EEPROM 유지를
다시 읽어서 확인했다. `measure_arm_range.py`는 설치된 보정 전용 펌웨어의 INFO/SCAN만
사용하므로 펌웨어 교체나 모터 쓰기가 필요 없다. 관련 테스트 26개 통과.

한 번에 한 팔·한 관절의 범위를 기록한다. 사용자 정정에 따라 다른 관절을 조정하며
선택 관절의 최대 사용 범위를 측정하도록 변경했다. 현재 자세에서 시작할 수 있고
Home 복귀도 요구하지 않는다. 팔 무게를 받치고 충돌·케이블 당김 전의 편한 끝점을
천천히 방문한다. 물리적 하드스톱까지 억지로 밀지 않는다.

선택 관절의 표본 간 1초 초과 공백, 256 raw 초과 변화, 어느 모터든 토크 ON,
EEPROM 변화 또는 통신 실패는 미완료 기록으로 처리한다. 다른 관절의 위치 변화는
선택 관절 범위에 포함하거나 측정 실패로 처리하지 않는다. 테스트 28개 통과.

임의 시작 자세의 첫 raw 표본을 turn 0으로 두고 이후 연속 변화를 추적한다.
이 구간이 물리 Home과 어느 회전 가지로 연결되는지는 `home_branch_verified=false`로
명시하며, 실제 실행용 범위로 반영하기 전에 확인해야 한다. 이번 기록은 다른 관절 자세를
바꿔서 도달한 단일 관절의 범위이며, 각 관절 끝값을 동시에 취해도 충돌이 없다는 증거가 아니다.
표본 검사는 느린 손동작을 전제로 하며 표본 사이의 보이지 않은 전체 회전을 독립적으로 보증하지 않는다.

입력 `finish`는 최소 표본/이동량을 검사하고 `captured_pending_operator_review`로 저장한다.
입력 `abort`, 시간 제한 10분 또는 오류는 `incomplete_do_not_use`로 저장한다.
결과 JSON과 연속 표본 JSONL 및 보정 파일 해시를 함께 보존하며 실제 구동 허가는 부여하지 않는다.
초기 도구로 완료한 왼팔 몸통/어깨 기록은 보존하고, 변경된 도구는 왼팔 팔꿈치부터 적용한다.

### 왼팔 측정 결과와 오른팔 재사용 결정

왼팔 6개 관절을 기록한 뒤 사용자가 오른팔 측정 대신 왼팔 범위를 그대로 쓰도록 요청했다.
진행 중이던 오른팔 몸통 기록은 `abort`로 중단했으며 완료 측정으로 취급하지 않는다.
`config/home_assistant/arm_ranges.development.json`에 양팔의 동일한 범위를 저장했다.
오른팔은 `measured_on_this_arm=false`, 출처는 사용자 요청에 따른 왼팔 복사로 표시한다.
양팔의 보정 파일 해시와 실제 모터 offset은 서로 구분해 보존한다.

| 관절 | 양팔 공통 개발용 연속 raw 구간 | 총 범위 |
|---|---:|---:|
| 몸통 회전 | 1017–3112 | 184.1° |
| 어깨 | 1875–4229 | 206.9° |
| 팔꿈치 | 138–2245 | 185.2° |
| 손목 굽힘 | -105–2175 | 200.4° |
| 손목 회전 | -723–2927 | 320.8° |
| 집게 | 1936–3182 | 모터 회전량이며 집게 개구 폭은 아님 |

집게는 raw 증가 방향이 열림이다. 사용자는 최대 열림 3182를 명시적으로 확인했고,
후속 관측 2621은 방향 확인을 위한 중간 열림이었다고 정정했다. 닫힘 1936은
지시한 빈 집게 닫힘→열림 손측정의 반대쪽 끝점 근거로 남긴다.

표의 음수와 4095 초과 값은 연속 좌표다. 끝점 각각을 modulo로 잘라 저장하지 않는다.
12개 복사 항목의 일치, 측정 해시, 각 구간에서 modulo→연속좌표 후보가 하나 이하인 것을
검사했다. Home 회전 가지 확인, 오른팔 실제 범위 및 다관절 조합 충돌 검증과는 구분한다.
프로필의 하드웨어/펌웨어 허가는 false다. 기존 schema 1 런타임은 손목 음수 구간을
수용하지 않으므로 파일 이름만 바꿔 실행용으로 넣지 않는다. 새 프로필은 아래 별도 경로로 연동했다.

### 연속 좌표 프로필 연동과 오프라인 검증

`development_ranges.py`가 새 프로필의 좌표·단위·방향·실측/복사 출처·보정 해시를 검증한다.
`generate_development_ranges.py`가 같은 파일에서 C 헤더와 ROS 패키지 사본을 생성하며,
새 프로필 내용의 SHA256으로 검증 이미지의 식별 해시를 만든다. 과거 실행용 표는 유지한다.
호스트 모의 검증에는 `operational_limits_for_simulation`을 사용한다. 이 범위로
`motion_authorized=True`를 요청하면 양팔/왼팔 어댑터 모두 거부한다.

`point_move_samples`는 현재 엔코더 12개와 목표 엔코더 12개로 명시적 연속 경로를 만든다.
목표의 가까운 회전 가지가 범위 밖이면 반대쪽 긴 경로로 치환하지 않고 거부한다.
정확히 반 바퀴인 모호한 요청도 거부하며, 시간에 비해 빠른 요청을 거부한다.
이 기능은 점대점 요청용이며 이미 지정된 복잡한 궤적을 무조건 최단 회전으로 고치는 기능은 아니다.

검증용 펌웨어 `home-assistant-s1-ranges` / `0x0002490A`는 새 C 표를 실행기의 범위·목표 변환에
연결하고, 모터 전송 전 연속 좌표 이동량을 검사하도록 구성했다. 한 출력당 최대 8 raw이며
호스트 점대점 생성은 5 ms당 최대 4 raw 이내로 제한한다. 이는 좌표 변화 한도이지
실제 속도·가속도·추종 성능의 검증 완료를 뜻하지 않는다.
물리 서보의 4095↔0 경계 통과가 미검증이라 해당 전이는 기본적으로 거부한다.
모의 검사에서만 명시적으로 경계 통과를 허용해 연속 계산을 확인한다.

```bash
python3 tools/setup/firmware/generate_development_ranges.py --check
cd firmware/stm32_g474_single_arm
cmake --preset home-assistant-s1-ranges
cmake --build --preset home-assistant-s1-ranges
```

**이 이미지는 출력 차단 검증용이며 배포하지 않았다.** 프로토콜에서 ARM/ENABLE/이동 요청을
거부하고 양쪽 모터 버스의 전송 계층에서도 쓰기를 차단한다. 기존 보정 펌웨어는 그대로다.
새 헤더나 복사 JSON이 원본과 다르면 빌드가 실패한다.

검증 결과:

- 실제 C 좌표 변환으로 27,476개 구간 내 좌표를 modulo 왕복, 양방향 한 칸 전이와 경계 검증.
- 범위 밖 목표에서 출력 배열 불변, 과도한 한 번의 이동과 미검증 경계 통과 거부.
- 200→500이 +300으로 단조롭게 이동하는 401개 점의 모의 경로가 실제 호스트 사전 검사를 통과.
