# 고정 위치 집기 촬영 도구

왼팔만 연결하는 경우에는 전용 펌웨어와 [왼팔 단독 도구](LEFT_ONLY_PICK_DEMO.md)를 사용한다. 아래 내용은 양팔이 연결된 기존 모드 기준이다.

카메라 없이 손으로 맞춘 **오른팔 관절 자세**를 저장하고 재생한다. 베이스와 물체는 집기 촬영 중 고정한다. 베이스 텔레옵 촬영과는 독립된 시연이다. 왼팔도 기존 양팔 제어기에 연결되어 있어야 하며, 재생 중에는 시작 자세를 유지한다.

## 실행 조건

- 현재 resident 팔 펌웨어 `0x00024908`, 보정 해시 `0x2D90167E`와 저장소의 관절 범위를 그대로 사용한다. 버전·보정·정지 상태가 다르면 거절한다. 과거 `0x00024809` 또는 바퀴 전용 `mobile-base-teleop-v4`를 이 도구와 혼용하지 않는다.
- 바퀴 전용 텔레옵 펌웨어에서는 팔을 구동할 수 없다. 실제 STM32 버전을 먼저 확인하고 필요한 펌웨어 전환은 별도로 수행한다. 도구는 펌웨어를 설치하거나 정지 잠금을 자동 해제하지 않는다.
- 다른 텔레옵·ROS 브릿지를 종료하고 STM32 포트를 단독 사용한다. Jetson에는 Python 3.10 이상과 `pyserial`이 필요하다. ROS·카메라·인식 모델은 필요 없다.
- 수동 저장 및 재생 초기화는 **양팔 토크를 해제**한다. 양팔과 물체를 지지한 상태에서 시작한다. 종료·연결 상실·오류 정지도 토크 해제를 동반할 수 있다.
- 기존 관절 한계는 모바일 조립체의 충돌 여유를 검증한 결과가 아니다. 이 도구는 자동 충돌 검사나 집기 성공 판정을 하지 않는다. 실제 확인한 작업공간과 경로에서 사용한다.

아래 명령은 저장소 또는 배포 묶음의 최상위 폴더에서 실행한다. 기본 팔은 오른팔이다. `auto`가 장치를 찾지 못하거나 여러 보드가 있으면 `--port /dev/serial/by-id/...`를 **하위 명령 앞에** 지정한다.

## 1. 팔 펌웨어 확인

```bash
python3 tools/run/fixed_pick_demo.py inspect
```

식별 정보만 조회하며 ARM·위치 명령·토크 변경은 보내지 않는다. resident 바이너리 통신 모드로 전환할 수 있다. 바퀴 전용 펌웨어이면 시간 초과가 날 수 있다. 이때 반복 구동하거나 호환 검사 값을 바꾸지 않고 설치된 펌웨어를 확인한다.

## 2. 직접 자세를 맞추어 저장

```bash
python3 tools/run/fixed_pick_demo.py teach --arm right --file output/right-pick.json
```

양팔을 받친 상태에서 오른팔을 손으로 맞춘 뒤 아래 이름을 입력한다. 매번 새 측정 3회를 비교하여 움직임이 적을 때 마지막 실제 측정값을 저장한다.

| 입력 | 맞출 자세 |
|---|---|
| `home` | 기본 자세, 그리퍼 열림. 왼팔도 이후 촬영 때 유지할 자세로 둔다. |
| `approach` | 물체 위 접근 자세, 같은 그리퍼 열림 유지 |
| `grasp` | 실제 집는 위치, 그리퍼 열림 |
| `closed` | grasp와 같은 팔 위치에서 물체에 맞게 그리퍼만 닫음 |
| `lift` | 물체를 들어 올린 자세, 같은 닫힘 유지 |
| `show` | 저장한 자세 이름 확인 |
| `done` | 자세 관계와 관절 경로 검사 후 종료 |
| `q` | 현재까지 저장하고 종료 |

각 자세는 즉시 파일에 저장된다. 같은 파일로 teach를 다시 실행하면 이어서 저장할 수 있다. 동일한 자세 이름을 입력하면 그 자세만 다시 측정한다. 열린 그리퍼 상태를 home/approach/grasp에서 같게, 닫힌 상태를 closed/lift에서 같게 유지한다. 한쪽 팔만 사용할 때도 양팔의 값을 수집하므로 반대팔도 움직이지 않게 받친다.

## 3. 구동 없이 파일 검사

```bash
python3 tools/run/fixed_pick_demo.py check --file output/right-pick.json
python3 tools/run/fixed_pick_demo.py play --file output/right-pick.json
```

두 명령 모두 장치를 열지 않는다. 자세 누락·잘못된 수치·범위 초과·보정 불일치·그리퍼 순서를 검사하고 구간별 예상 시간을 표시한다. 관절 속도는 최대 0.20 rad/s로 제한한 완만한 경로를 생성한다. 이 결과는 관절 경로 검사이며 실제 물체 집기나 충돌 없음의 증거가 아니다.

## 4. 촬영용 재생

양팔을 저장한 home에 맞추고, 베이스와 물체 위치를 고정한다. 처음에는 물체 없이 경로를 확인한 뒤 같은 배치에서 촬영한다.

```bash
python3 tools/run/fixed_pick_demo.py play --file output/right-pick.json --execute
```

`home → approach → grasp → closed → lift` 순서로 이동한다. 각 구간의 실제 도착 확인 후 다음으로 진행하며, 카메라와 베이스는 제어하지 않는다. 최초 현재 자세가 저장한 양팔 home과 0.05 rad 이상 다르면 출발하지 않는다.

모터를 활성화하기 직전 마지막 관절 측정에서도 home 조건을 다시 검사한다. 경로를 만든 뒤 출발점이 0.01 rad 이상 변하면 출발을 거절한다. 구간 사이에는 이전 명령값을 그대로 이어가므로, 측정 오차 때문에 닫힌 그리퍼를 잠깐 열거나 반대팔 목표를 바꾸지 않는다. 실제 측정값은 위치 오차와 피드백 상태 확인에 사용한다.

들어 올린 뒤에는 **시간 제한 없이 자세를 유지**하며 다음 입력을 기다린다. 이때도 제어기 통신과 피드백을 계속 확인한다.

팔 전용 펌웨어는 유한 동작이 끝나면 관절 측정을 멈추므로, 대기 중에도 **같은 관절 목표의 짧은 유지 구간**을 이어 보내 측정을 계속한다. 그리퍼와 반대팔 목표는 바꾸지 않고, 토크 해제를 통한 재측정도 하지 않는다. `return`/`run` 입력은 진행 중인 유지 구간의 도착 확인 후 실행한다. `q`, Ctrl+C, 입력 연결 종료는 유지 구간 중에도 취소한다.

- `return` + Enter: 닫은 상태로 원래 집는 위치까지 돌아온 뒤 그리퍼를 열고, 접근 자세를 거쳐 home으로 복귀한다. 물체를 놓을 원래 자리도 그대로 유지한다.
- home에서 `run` + Enter: 같은 집기 동작을 다시 재생한다.
- 양팔과 물체를 받친 뒤 `q` + Enter 또는 Ctrl+C: 정지·토크 해제 후 종료한다. `q`와 입력 연결 종료는 이동 중에도 제어기 통신 사이마다 확인한다. 터미널/SSH 연결 상실도 정지 경로로 처리한다.

`run`과 `return`은 자세 유지 안내가 나온 뒤 입력한다. 이동 중에 미리 입력한 재생·복귀 명령은 버려서, 나중에 예상치 못한 동작을 시작하지 않게 한다.

최종 자세에 도달했다고 실제 집기가 성공했다고 기록하지 않는다. 실행 이력과 정지 응답은 자세 파일 옆의 `*.last-run.json`에 저장된다. 종료는 resident 정지 잠금을 설정하므로 새 프로세스로 다시 시작하기 전 보드 상태를 확인한다. 같은 세션의 `return` / `run` 반복은 재초기화하지 않는다.

## 현재 검증 범위

소프트웨어 모의 검사와 실제 Jetson·모터 시험을 구분한다. 실제 자세는 아직 수집하지 않았고, 출고된 집기 성공본이나 자동 자율 집기 기능은 아니다. 원격 연결과 설치 펌웨어 확인 후 실측 자세를 저장해 검증해야 한다.

2026-10-15 재검토에서 구간 전환 시 그리퍼/반대팔 목표 변경, 초기 검사 이후 출발 자세 변경, 이동 중 취소 입력 지연을 재현해 수정했다. 관련 회귀와 기존 팔 제어·단독 포트 소유권 검사 89개를 통과했다. 모터를 연결하지 않은 소프트웨어 검사 결과다.

## 촬영 흐름 재검토 — 2026-10-16

| 재현한 문제 | 수정 내용 | 적용 위치 |
|---|---|---|
| 팔 전용 펌웨어에서 촬영 자세를 유지하다가 측정값이 만료되어 종료됨 | 동일 관절 목표의 유지 구간을 이어서 측정을 계속함. 신선도 제한은 그대로 유지 | 집기 Python 도구 |
| 터미널 입력 한 묶음에서 Space 뒤의 이동 키가 정지를 덮어씀 | 같은 묶음에서는 종료와 Space를 이동 키보다 우선 처리 | 텔레옵 Python 도구 |
| SSH 종료 신호 또는 SIGTERM에서 STOP 처리 없이 프로세스 종료 | 정상 종료와 같은 STOP·응답 확인·포트 정리 경로로 연결 | 터미널 및 웹 텔레옵 Python 도구 |
| 모바일 통합 펌웨어에서 관절 관측 후 다음 동작을 시작할 때 각도 기준 재설정 실패 | 허용되지 않는 0-count 검사 창을 기존 초기화와 같은 1-count 창으로 수정 | STM32 소스. 모바일 프로필이 설정된 경우에 해당 |

촬영 흐름·기존 회귀 215개를 통과했다. 실제 호스트 어댑터를 사용한 가상 시간 60초 자세 유지, 집기→복귀→재집기, 대기 중 취소·입력 종료·피드백 유실·STOP 응답 유실을 포함한다. 텔레옵은 실제 자식 프로세스에 SIGHUP/SIGTERM을 전달하되 직렬 포트와 HTTP 서버는 모의 객체를 사용했다. 브라우저 키 해제·창 이탈·연결 만료·이전 명령 거절과 펌웨어 watchdog도 기존 검사를 통과했다.

STM32 팔 펌웨어는 Release 교차 빌드에 성공했다. 위 수정은 로컬 소스에 반영했으며 **Jetson 배포나 STM32 설치는 수행하지 않았다**. 배포 묶음에 들어 있는 `patches/mobile-arm-reentry.patch`는 통합 펌웨어용 소스 수정본이며 자동으로 설치되지 않는다. 바퀴 전용 펌웨어와 팔 전용 펌웨어는 여전히 서로 다른 실행 조건이다.

보조 PC C 검사 17개는 기존 기본 설정인 Debug / 시작 ID 8에서 통과했다. 시작 ID 7로 실행하면 ID 8에 고정된 기대값 때문에 5개가 실패하며, Release에서는 `assert`가 제거되어 기존 테스트 코드의 빌드도 실패한다. 이는 이번에 수정하지 않은 테스트 구성의 제한이다. 실제 촬영용 ID 7 텔레옵의 펌웨어 검사는 위 215개에 포함된 별도 C 하네스로 수행했고, 팔 펌웨어 교차 빌드도 ID 7로 수행했다. 실제 로봇의 ID를 8로 바꾸지 않는다.

검사는 실제 제어 주기 지연, 모터 방향, 물체 접촉, 충돌 없는 동선을 증명하지 않는다. 자세 간 관절 보간이므로 손으로 지나간 중간 경로가 자동으로 재현되지 않으며, 실제 자세와 경유 경로 확인이 남아 있다.

## 같은 묶음의 베이스 촬영 도구

`tools/run/teleop_mobile_base.py`와 `base_teleop_web.py`도 함께 제공한다. `--port`는 실제 STM32 장치 경로로 지정한다. `--run`은 터미널 키 입력, `--web`은 브라우저 조작이며 두 옵션 모두 바퀴 구동을 활성화한다. 옵션 없이 포트만 지정하면 INFO 조회만 한다. 웹 접속 주소는 실행 터미널에 표시되며 원격 접속은 기존 SSH 포트 전달 또는 명시적인 `--bind` 설정을 사용한다.

터미널 조작은 W/S 전후, A/D 좌우, Q/E 회전, Space 정지, X/Esc/Ctrl+C 종료다. 웹 조작은 키/버튼을 누르고 있는 동안 계속 이동하며 놓거나 창을 벗어나면 정지 요청을 보낸다. 촬영 길이에 따른 자동 종료는 없다. 연결 만료 후에는 키를 놓고 페이지를 새로고침해야 한다.
