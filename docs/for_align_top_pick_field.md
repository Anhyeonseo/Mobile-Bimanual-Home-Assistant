## 0. 오늘 할 것

**물체가 카메라 시야 왼쪽 구석에 있을 때, 베이스가 왼팔 기준으로 옆으로 이동한 뒤 왼팔로 집는다.**

- 성공 기준: 정렬 → 집기 시연 **1회 이상 영상으로 남기기**, 시도마다 기록표(7절) 채우기
- 결과는 "시연 n회 중 n회"로만 말한다. 성공률이나 일반 성능으로 쓰지 않는다.

### 동작 원리 (한 번만 읽기)

```
광각 사진 한 장 → 물체 base 좌표 (x 앞, y 왼쪽 +)
이동량 = 물체 y − 왼팔 목표 y (14.8 cm, 11/18 성공 위치)
  · 차이 3 cm 이하 → 이동 없음
  · 30 cm 초과     → 거절 (움직이지 않음)
  · 그 외          → 이동량 ÷ 속도 만큼 천천히 옆으로 (예상 0.7 cm/s) → 영속도 → STOP 확인
```

**펌웨어 제약:** 바퀴 이동 모드 뒤에는 팔을 쓰기 전에 **제어기 리셋이 반드시 필요**하다. 그래서 한 사이클은 이렇게 된다.

```
«카메라 검사» → «베이스 좌우 정렬» → SWD 리셋 → «픽 스테이션 초기화» → «카메라 검사» → «실물 파지»
```

## 3. 단계 A — 방향 확인, 카메라만 (10분)

**바퀴를 움직이기 전에 좌표 부호부터 확인한다.** 팔·바퀴 모두 움직이지 않는다.

1. 물체를 카메라 화면 **가운데**에 둔다. 작업 «최상단 · 카메라 검사», 요청란에 물체 이름(예: `지우개`) → 요청
2. 이벤트 기록에서 **`왼팔 기준 정렬: 물체 base 좌표 x … cm, y … cm`** 줄을 찾아 y를 적는다 (`A1`)
3. 물체를 **로봇 기준 왼쪽으로 약 10 cm** 옮긴다 (로봇 뒤에서 앞을 볼 때 왼쪽. 카메라 화면에서도 왼쪽)
4. 다시 «카메라 검사» → y를 적는다 (`A2`)

판정:
- **A2 − A1 ≈ +10 cm** → 부호 맞음. 다음 단계로.
- **반대(−10 cm)이거나 크기가 크게 다름** → **중단.** 바퀴를 움직이지 않는다. 사진과 기록을 저장하고 확인한다.
- "3차원 위치를 확인하지 못해" → 물체 전체가 보이게 두고, 비슷한 물체를 치우고 다시

---

## 4. 단계 B — 첫 이동, 작게 (30분)

1. 물체를 놓고 «카메라 검사»를 해서 **"왼쪽으로 5–10 cm 이동"**이 나오는 자리를 찾는다. 그 자리에 테이프로 표시. y를 적는다 (`y_before`)
2. 작업 «최상단 · 베이스 좌우 정렬», 같은 물체 이름, 확인란 체크 → **«정렬 이동 요청»**
3. **옆에서 지켜본다.** 진행 순서: 촬영 → 탐지 → 후보 → 제어기 준비(수십 초) → 이동(약 10초) → 정지
   - 물체 **반대쪽으로** 가거나, 멈추지 않거나, 기울어지면 → 화면 **«작업 중단»**, 그래도 안 서면 **모터 전원 차단**
4. 결과 문구 "베이스를 왼쪽으로 약 n cm 이동하고 정지를 확인했습니다"를 확인한다. 화면 상태는 "베이스 정렬 후 제어기가 정지 상태입니다"로 바뀐다. **정상이다.**
5. SWD 리셋 (2-1과 같은 명령) → 화면 **«픽 스테이션 초기화»**
6. «카메라 검사» → 새 y를 적는다 (`y_after`)

계산:
- 실제 이동 = `y_before − y_after`
- 예상 이동 = 정렬 요청 때 표시된 이동량
- **비율 r = 실제 ÷ 예상**

판정:
- r이 0.8–1.2 → 속도값 그대로. 단계 D로.
- r이 그 밖 → 단계 C
- **실제 이동이 거의 0** (바퀴가 안 돎) → raw 100이 바퀴 최소 출력보다 낮은 것이다. 중단하고 현서와 상의한다. (raw를 올리면 펌웨어 정책 상한 100과 충돌할 수 있다.)

---

## 5. 단계 C — 속도 보정 (필요할 때만, 15분)

1. 노트북에서 [config/home_assistant/base_lateral_alignment.development.json](../config/home_assistant/base_lateral_alignment.development.json)을 연다
2. 이번에 움직인 방향의 값만 고친다: **새 `speed_m_per_s` = 기존 값 × r**
   - 예: 왼쪽 0.0067, r = 0.75 → 0.0050
   - `speed_basis`에 "현장 YYYY-MM-DD, 예상 a cm, 실제 b cm" 한 줄을 남긴다
3. 화면 터미널을 끄고(Ctrl-C) `bash tools/run/open_pick_station.sh`로 **다시 배포**
4. 단계 B를 한 번 더 해서 r이 0.8–1.2인지 확인

오른쪽 방향은 단계 D에서 처음 쓸 때 같은 방법으로 확인한다.

## 6. 단계 D — 시연 (60분)

### 6-1. 한 사이클

| 순서 | 화면 작업 | 확인 |
|---|---|---|
| 1 | 물체를 **화면 왼쪽 구석**에 둔다 (이동량 15–25 cm) | 테이프로 자리 표시 |
| 2 | «최상단 · 카메라 검사» | y, 이동량 기록 (`y_before`) |
| 3 | «최상단 · 베이스 좌우 정렬» + 확인란 | 이동·정지를 지켜봄. **영상 시작** |
| 4 | SWD 리셋 → «픽 스테이션 초기화» | |
| 5 | «최상단 · 카메라 검사» | 결과에 **"허용 범위 안 · 이동 없음"**이 나와야 함 (`y_after`) |
| 6 | 5에서 범위 밖이면 3–5를 **한 번만** 더 | 두 번째도 밖이면 중단, 기록 |
| 7 | «최상단 · 실물 파지» + 확인란 | 기존 집기. 잡았는지 직접 판정 |
| 8 | 물체를 받치고 내려놓기 → «다음 시험 준비» 또는 초기화 | |

### 6-2. 시도 목록

| 번호 | 배치 | 목적 |
|---|---|---|
| D1 | 왼쪽 구석, 지우개(세워서) | 본 시연 |
| D2 | 왼쪽 구석, 다른 물체 | 물체가 바뀌어도 되는지 |
| D3 | 왼쪽 구석, 다른 거리(앞뒤 5 cm 차이) | 앞뒤 위치 차이 |
| D4 | **목표보다 오른쪽** (화면 가운데~오른쪽) | 오른쪽 이동 확인, 필요하면 5절로 속도 보정 |

시간이 남으면 D1을 반복해서 영상을 더 남긴다.

## 8. 하지 않는 것

- 물체를 든 채로 정렬 (확인란은 빈 그리퍼 확인이다)
- 정렬 후 리셋 없이 바로 집기
