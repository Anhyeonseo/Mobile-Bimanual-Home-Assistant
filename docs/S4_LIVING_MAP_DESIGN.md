## 2026-11-13 운용 중 자동 부분 갱신

사용자는 `movement-fused-v1`을 다음 검증의 기준으로 선택했다. 가구를 옮겼을 때
사용자가 변경을 신고하거나 SLAM을 재실행하지 않는다. **최초 지도에 등록된 가구**의
같은 개체임이 확인되면 평소 관측으로 새 위치를 회피하고 옛 위치가 비었음을 확인한 뒤
해당 영역만 자동 저장한다. 미관측 구역은
마지막 기억을 유지하며, 현재 경로나 목적지에 필요한 구역은 재관측한다.

사용자 후속 결정에 따라 **새로 나타난 모든 물체는 기본적으로 임시 장애물**이다.
의자/탁자로 인식되거나 오래 정지해 있어도 자동으로 가구 목록·저장 지도에 추가하지
않는다. 새 가구는 사용자가 `가구 추가`를 요청해 해당 구역을 추가 촬영/매핑한 뒤
등록한다. 집 전체 SLAM 재실행은 요구하지 않는다. 기존 가구의 이동과 새 가구의
등장은 분류 이름만으로 구분하지 않으며, 동일성이 애매하면 임시 장애물로 유지한다.

기존 `adaptive_mapping.py`에 `LivingMap`을 추가했다. 기존 `AdaptiveMap`의 센서
검사·광선 계산·변경 영역 판정을 재사용하고 아래 상태를 분리한다.

- **실시간 지도:** 라이다 또는 깊이 hit를 즉시 추가한다. 이름 없는 물체도 막는다.
  가림·시간 경과만으로 지우지 않는다. 높이 관측이 불충분해도 hit 추가는 가능하며,
  기존 점유를 지우는 데에는 해당 높이의 빈 공간 관측이 필요하다.
- **저장 지도:** 등록된 가구 ID에 대한 현재의 검증된 추적/재식별 근거가 있고,
  현재 가구 분할의 관측 voxel과 현재 기하 hit가 겹치는 칸만 위치 변경 후보로
  삼는다. 현재 `RGBDFurnitureMapper.observations`를 사용하며 누적 instance
  형상·이름·상자 영역을 현재 관측으로 재사용하지 않는다. 움직이는 물체로 판별한
  칸은 승격에서 제외한다. 등록되지 않은 가구·분류되지 않은 장애물은 실시간 층에
  유지한다. `register_furniture`는 최초 지도 승인 또는 사용자 요청의 부분 매핑
  결과만 받는다. 등록 목록과 현재 칸 소유권도 지도와 함께 저장한다.
- **확인 중인 변경:** 초기 개발 정책은 기존 가구의 새 위치 3회 이상/2초 이상, 옛 점유 제거
  2회 이상/0.25초 이상이다. 1.5초 넘는 관측 간격, 가림 또는 반대 관측은 해당
  확인을 다시 시작한다. 이는 정지·통신 timeout이 아니며 실측 최적값도 아니다.
- **자동 저장:** 기존 `WorldStore`의 한 SQLite 트랜잭션에 현재 지도·이전 두 지도·
  변경 근거를 함께 저장한다. 원본 지도, 보정, 주행 외형과 보호 구조물 구성을
  바인딩한다. 재시작은 저장 지도만 복원하며 임시 장애물·확인 횟수·신선한 센서
  상태·이동 권한을 복원하지 않는다. 저장 실패도 이미 관측한 새 장애물을 없애지 않는다.

등록된 가구의 옛 영역만 자동으로 저장 지도에서 제거한다. 등록되지 않은 기존 점유와
보호 구조물은 유지하며, 새로운 임시 장애물은 빈 공간 관측으로 해제할 수 있다. 현재 가구 인식 결과가 늦거나 문맥이 맞지 않으면 의미 정보만 제외하고 현재 기하를
계속 반영한다. 사람 인식 실패를 통행 허가로 사용하지 않는다. 사람 추적/동적 마스크의
실물 공급, 가구 재식별 및 기존 별칭의 새 위치 연결은 별도 실물 연결 항목이다.

현재 `FurnitureMemory`의 voxel 겹침 연관은 `identity_verified=False`인 추정이므로
이 근거만으로 새 위치를 승인하지 않는다. 코드의 검증된 동일성 입력 계약이 실제
재식별 모델 완성을 의미하지 않는다. 앱의 새 가구 추가/부분 매핑 UI 연결도 남아 있다. 두 번의 관측은 독립 capture라는 뜻이며 서로 다른 시점만으로 인식 정확도를 보증하지 않는다.

`LivingMapNavigation`은 기존 모의 `RobotApplication`/실행기/소유권을 사용한다.
경로 밖의 변경은 실행을 끊지 않는다. 경로에 영향이 있으면 정지 확인 후 새 센서와
새 위치로 재계획하며, 상위 요청 ID와 목적지는 유지한다. 경로가 없으면 기다리고
지도나 위치가 바뀔 때 다시 시도한다. 취소·실제 실행 오류·전체 작업 시간 만료는
자동 재시도하지 않는다. 조작 단계(집기·놓기)는 재전송하지 않는다.
이 연결은 모의 실행 한정이다. 실제 Nav2, 앱 진행 표시, 하중 유지와 재관측 동작의
실물 연결이 완료됐다는 뜻이 아니다.

실제 지도 원점은 depth voxel 격자와 일치하지 않았다. `projected_grid`는 임의 원점에서
겹치는 voxel 열을 검사하도록 수정했다. hit는 겹침으로 반영하고 free는 겹친 모든
열의 관측을 요구한다. 라이다 ray도 지도 상대 좌표에서 추적한다. 원점을 반올림하여
물체를 이동시키거나 기존의 중복 팽창 계산을 복원하지 않는다.

재현 명령:

```bash
python3 tools/diagnostics/review_s4_sensor_capture.py --living-map-review \
  --slam-review output/s4-room-mapping-20261113-lidar-final-v1 \
  --body-review output/s4-room-mapping-20261113-movement-fused-v1 \
  --output output/s4-room-mapping-20261113-living-map-v2
```

출력 폴더는 새 경로여야 한다. 결과는 **실제 136×189 지도 격자에 합성 변경을 주입한
로컬 검사**다. 실제 탁자가 이동한 영상은 아니다. 등록된 가구의 합성 동일성 근거를
입력해 새 위치 반영·옛 위치 확인 후
해제·가림 유지·사람 임시 층·저장 후 재시작을 확인했다. 원본 지도 해시는 불변이며
모터 명령은 0회다. PC 처리 시간은 젯슨 지연 검증으로 쓰지 않는다.

### 남은 S4 진행 순서

2026-11-13 사용자 요청으로 아래 실물 작업은 잠시 보류했다. 완료 상태를 변경하지
않으며, [S5 자연어 재사용 검토](history/S5_LANGUAGE_REUSE_REVIEW.md)의 로컬 준비로 전환한다.

1. **현재 지도에서 주행 연결 확인:** 가능한 중심점 표시에서 나아가 실제 방향별
   연결 경로·회전 중 외형·접힌 팔 자세를 확인한다. 기록 경로의 207개 깊이/외형
   경계 불일치는 사라졌다고 처리하지 않는다.
2. **실시간 자동 갱신 연결:** 현재 위치와 촬영 시각을 맞춘 라이다/RGB-D를 공급하고,
   앞/뒤 가림을 보존한다. 필요한 부분을 볼 수 있는 관측 동작, 시간 초과와 정상
   장애물 대기의 UI 구분, Nav2 경로 갱신을 연결한다. 저장 지도와 옛 static layer를
   max 합성해 제거한 가구가 다시 생기는 일이 없어야 한다.
3. **감독하의 국소 변경 시험:** 사람 통과, 의자 이동, 낮은 탁자 이동, 가림을 각각
   수행한다. 새 위치 차단·옛 위치 해제·사용자 재SLAM 없이 같은 목적지 도착을
   확인한다. 전원 재연결 뒤 수정 지도 복원과 최신 관측 재획득도 확인한다.
4. **가구 위치와 작업 위치 연결:** 같은 가구인지 불명확하면 별칭을 임의 이전하지
   않고 목적지 주변을 다시 관측한다. 새 가구 추가는 사용자 요청의 부분 매핑으로
   등록하는 앱 흐름을 연결한다. S4b의 관측→베이스 정렬→높이→새 촬영→집기→
   운반→놓기를 전원선이 허용하는 구역에서 검증한다.
5. **완료 범위 기록:** 로컬 통과를 실물 완료로 올리지 않는다. 배터리가 필요한
   집 전체 자동 탐색은 사용자 결정대로 보류하고, 텔레옵 지도와 국소 배송을 진행한다.

## 2026-11-12 기준: Mini 1이 통과할 수 있는 지도

RGB-D와 2D 라이다의 통합 목적은 **라이다 측정 높이 밖의 형상을 보완하는 것**이다.
RGB의 가구 이름은 위치 설명에 쓰며, 이동 가능 판정의 전제나 장애물 제거 조건으로 쓰지 않는다.

- 라이다가 탁자 다리 사이를 빈 공간으로 보더라도, 상판·돌출부가 로봇의 통과 높이에 겹치면 깊이 관측으로 차단한다.
- 바퀴뿐 아니라 본체·팔·리프트·카메라·운반 물체가 포함된 현재 주행 외형을 기준으로 한다. 수평 외형과 여유 폭을 반영하고, 팔·리프트·하중이 바뀌면 외형과 경로를 다시 계산한다.
- 깊이 volume의 전체 높이를 일괄 투영하지 않고, 지도 바닥부터 해당 외형의 높이(수직 여유 포함)까지 겹치는 voxel만 투영한다. 로봇보다 충분히 높은 구조물이나 그 위 미관측 영역 때문에 길을 불필요하게 막지 않는다. 경계 voxel은 부분적으로 겹쳐도 포함한다.
- 해당 높이 구간을 충분히 보지 못하면 미확인으로 남긴다. 라이다 free나 RGB 인식 실패만으로 통과 가능을 만들지 않는다. 가구 이동에 따른 새 장애물 추가와 옛 위치 해제에도 같은 높이 범위를 사용한다.
- 기본 의미 지도는 냉장고·소파·책상/탁자·침대·수납장 등 주요 가구 중심이다. 바구니·휴대용 선풍기 등의 별도 이름표는 생략해도 원본 깊이 형상은 유지한다. 소파 아래 물건을 이름상 따로 나열할 필요는 없으며, 실제 소파 확인 없이 임의로 소파로 재분류하지 않는다.

현재 코드는 기존 `navigation_fusion`, `projected_grid`, `AdaptiveMap`을 재사용한다.
낮은 상판 차단, 충분히 높은 상판 아래 통과, 필요한 높이만의 관측 범위, 이름 없는 작은 장애물과 몸체 폭을 로컬 검사했다.
이는 소프트웨어 검사다. 이번 실측 기록의 지도 내보내기에서 사용한 반경 0.22 m·높이 1.2 m는 임시값이며, 실물 전체 외형 검증값으로 사용할 수 없다.
실측 RGB-D의 상부 형상 미리보기와 의미 인식은 완료했지만, 자기 몸체 제거·현재 주행 자세 외형·전체 높이의 빈 공간 관측을 연결한 실물 통행 지도는 아직 인수 전이다.

## 사용 흐름

1. 앱의 **집 지도 만들기**를 누른다. 센서 상태, 현재 위치, 운반 자세가 준비되어야 탐색을 시작한다. 필요한 경우 앱은 “카메라 연결을 확인해 주세요”처럼 고칠 수 있는 원인을 보여준다.
2. 로봇은 주변부터 관측하고, 확인된 안전한 바닥 안에서 다음 관측 위치를 고른다. 미리 정한 집 모양이나 방문 순서는 쓰지 않는다. 지도에서 관측된 영역, 남은 미확인 영역, 로봇의 진행 상태를 보여준다.
3. 라이다로 바닥 평면과 위치를 추정하고 상단 깊이 카메라로 상판·돌출부 등 높이 형상을 기록한다. RGB 인식과 분할 결과를 깊이에 연결해 책상·소파 등의 이름과 관측된 모양을 덧붙인다. 모르는 물건도 깊이 장애물로는 반영한다.
4. **일시정지**는 실제 정지 확인까지 “멈추는 중”으로 표시한다. **이어하기**는 현재 센서와 위치를 다시 확인한 뒤 실행한다. 앱 화면을 닫는 것은 취소가 아니며 재접속하면 상태를 보여준다. 서버가 재시작되면 자동 재출발하지 않는다.
5. 탐색 가능한 구역을 돌아본 뒤 출발점으로 돌아가 지도 검토로 전환한다. 닫힌 문, 가려진 곳, 지나갈 수 없는 곳은 남겨 둔다. “집 전체 100%”라는 보장 대신 실제 지도 범위의 관측률을 표시한다. 사용자는 방 이름을 수정하거나 그대로 저장할 수 있다.
6. 평소 요청은 “거실 탁자에 있는 리모컨 가져와”처럼 한다. 이동 중 주변이 달라졌으면 필요한 곳만 다시 확인하고 경로를 갱신한다. 가구 하나를 옮겼다는 이유로 처음부터 집 지도를 다시 만들도록 요구하지 않는다.

## 지도와 기억을 나누는 기준

| 자료 | 용도 | 갱신 조건 |
|---|---|---|
| 라이다 위치 추정 지도와 pose graph | 현재 위치, 방 사이 연결, 루프 연결 | SLAM 추정과 재위치 추정이 유효할 때 |
| 깊이 3D 관측 기록 | 높이 형상, 재투영, 관측 근거 | 노출 시각의 카메라 위치·보정값과 함께 기록 |
| 주행용 2D 지도 | 바퀴뿐 아니라 팔·리프트·적재물을 포함한 통과 여부 | 전체 운반 높이의 깊이를 투영하고 라이다와 결합 |
| 실시간 주변 장애물 | 사람, 옮겨진 의자·탁자, 경로 변경 | 현재 센서로 즉시 추가, 독립된 빈 공간 관측으로 제거 |
| 방·가구 의미 정보 | 사용자의 장소 이름과 물체 검색 | RGB 분류와 관측 형상, 사용자 이름 확인. 위치 변경 시 다시 관측 |

저장한 3D 기록은 과거 관측이다. 앱을 다시 켰다고 관측 시각을 새로 찍거나 주행 안전 자료로 재사용하지 않는다. SLAM 루프 보정으로 좌표가 달라지면 예전 전역 voxel을 그대로 더하지 않고 새 좌표에 재등록한 자료로 재구축한다. 일반적인 가구 이동과 SLAM 좌표 수정은 서로 다른 사건이다.

## 탁자가 옮겨졌을 때

- 새 위치의 라이다 또는 깊이 장애물은 곧바로 경로 검사에 반영한다. 인식 모델이 “탁자”라고 부를 때까지 기다리지 않는다.
- 옛 위치는 **현재 라이다가 빈 공간을 관측하고, 로봇의 전체 높이 구간도 깊이로 비어 있음을 확인**한 경우에만 지운다. 서로 다른 시각의 관측 두 번을 요구한다. 가림, 깊이 결측, 인식 실패, 센서 시간 초과는 빈 공간의 근거가 아니다.
- 벽 등 보호한 구조물은 이 국소 지우기 절차로 제거하지 않는다. 위치 추정 품질이 나쁘면 지도 수정과 이동을 중지하고 다시 위치를 확인한다.
- 가구의 과거 관측 형상은 기록으로 남긴다. 확인된 빈 영역과 겹치는 현재 형상만 비운다. 멀리 떨어진 같은 종류의 가구를 무조건 같은 물체라고 합치지 않는다. 사용자 이름을 자동 이동시키려면 추가 동일성 확인이 필요하다.
- 경로 중심선뿐 아니라 운반 외형의 여유까지 고려해 영향 범위를 판단한다. 지도 버전이 바뀌면 기존 계획은 무효화한다. 현재 구현은 기존 실행기의 취소·전체 정지 확인을 재사용하고, 정지가 끝난 뒤 새 지도를 적용한다.
- 현장 실행 어댑터는 정지 후 최신 위치와 주변 관측을 공급하고 새 경로를 만들어 요청을 이어야 한다. 집기나 놓기까지 진행하던 작업은 물체·하중·상판도 재확인한다. 취소된 명령을 그대로 재전송하지 않는다. 이 자동 재관측·재계획 연결은 실물 어댑터 인수 항목이며, 현재 로컬 UI가 물리 로봇에서 수행한다고 표시하지 않는다.

## 이번 로컬 구현의 범위

| 구현 | 검증 범위 |
|---|---|
| `home_survey.py` 관측 기반 다음 위치 선정 | 보이는 부분만 계획기에 전달. 숨겨진 집 모양이 달라도 같은 관측이면 같은 다음 위치. 기존 작업 실행기·소유권·정지 재사용 |
| 앱 자동 탐색 | 시작·정지 확인·이어하기·검토·저장. 재시작 후 PAUSED, 명시적으로 이어하기. 가상 센서와 가상 이동이며 실제 SLAM 자동 주행 아님 |
| 실제 SLAM 저장/복원 | 합성 라이다를 실제 slam_toolbox에 입력하고 별도 프로세스에서 그래프 복원. 자동 탐색 앱과 실물 센서 연결은 미인수 |
| `semantic_mapping.py` | 기존 DINO/SAM 어댑터 재사용, RGB 범주와 정렬된 깊이 형상 연결, 모델 버전·RGB/깊이 해시·카메라 변환 저장 |
| `replay_home_scan.py` | native-depth와 선택적 RGB·aligned-depth·분할 기록을 함께 재생해 지도/3D/의미 정보를 보관. 모델 추론 결과 재생을 새 추론으로 표시하지 않음 |
| `adaptive_mapping.py` | 현재 라이다 ray와 기존 깊이 volume 결합. 오래된 입력·중복 입력·잘못된 문맥 거부, 장애물 추가·확인 후 제거·보호 구조물 유지 |
| 기존 실행기와 지도 갱신 연결 | 진행 중 경로 취소 → 전체 정지 확인 → 지도 적용 → 최신 위치 요구. 실물 자동 재출발 권한 없음 |

이 단계에서 학습 모델의 가정 환경 정확도, 유리·반사체 검출, 실물 전방/후방 시야, 계단·낙차 검출은 보장하지 않는다. 이런 입력을 확인하지 않고 단순히 앱 버튼만 물리 모터에 연결하지 않는다. 전방 카메라만으로 뒤쪽 이동의 높이 공간이 확인되지 않는 경우 회전해서 관측하거나 미확인으로 남겨야 한다.

## 현장에서 연결할 순서

기존 S4 인수 문서의 바퀴·정지·센서·운반 외형 확인 후, 실제 캡처 작업자가 SLAM 위치와 노출 TF를 고정해 지도 작업자에 전달한다. RGB 추론은 별도 작업자로 돌려 주행 정지 루프를 막지 않으며 최신 프레임만 제한된 큐로 처리한다. 현재 주행 안전 검사는 인식 모델 없이도 작동해야 한다.

그다음 작은 구역의 자동 탐색, 좁은 문·막힌 길·가려진 상판, 탐색 중 취소, 센서 끊김, 저장 후 재시작을 확인한다. 마지막으로 탁자를 옮기고 새 위치 차단/옛 위치 해제/경로 갱신을 확인한 뒤 물체를 든 운반 작업에 연결한다. 지도 저장 성공만으로 실제 자율 탐색이나 배송 성공을 판정하지 않는다.

## 전원을 나눠 연결할 때의 저장·재개

앱의 **저장하고 종료**는 일반적인 지도 완성/저장과 다르다. 탐색 도중에도 누를 수 있으며, 진행 중 이동을 기존 실행기로 취소하고 전체 정지를 확인한 뒤 저장한다. 저장이 끝나기 전에는 종료 준비 완료를 표시하지 않는다. 현재 앱은 가상 실행이므로 “저장 완료 · 가상 실행 종료 준비 완료”로 표시하며 실제 컴퓨터나 모터 전원을 끄지 않는다.

저장 내용은 지도, 탐색 위치/진행 기록, 방 이름, 가구·RGB 의미 관측, 보관된 깊이 voxel, 그리고 실제 SLAM 작업자가 제공한 pose graph 두 파일이다. 시뮬레이션에는 pose graph가 없다고 명시하며 replay 모드의 체크포인트는 두 파일 없이 저장할 수 없다. 이동하지 않는 관측 지점마다 자동 저장하고, 종료 요청 때 최신 내용을 한 번 더 저장한다.

같은 SQLite 저장소에 원자적 트랜잭션과 FULL 동기화를 사용한다. 모든 자료의 해시와 이를 가리키는 포인터를 함께 확정한다. 현재 저장본과 이전 두 세대를 유지하고 중복 자료는 공유한다. 저장 중 프로세스가 종료되면 미완성 저장본은 사용하지 않는다. 최신 세대의 해시가 맞지 않으면 이전의 온전한 세대로 돌아간다. 파일시스템/저장장치 전체 손상까지 복구하는 백업은 아니므로 외부 백업을 대체하지 않는다. 저장 실패 시 앱은 전원을 유지하고 다시 저장하도록 안내한다.

재시작하면 저장된 지도는 표시하지만 동작은 PAUSED 상태다. **이전 지도 이어 만들기**를 누른 뒤 현재 부팅에서 새로 관측한 위치, 센서, 팔·리프트 상태와 정지를 확인해야 재개한다. 지난 부팅의 위치나 타임스탬프를 새 상태로 바꾸어 쓰지 않는다. 위치를 찾지 못하거나 센서 상태가 나쁘면 이동하지 않고 기다리며, 확인 시간이 지나면 다시 이어하기를 요청하도록 안내한다. 보정값이나 지도 좌표계가 바뀌면 바로 재개하지 않는다. 로컬 모드에서는 현재 가상 로봇의 위치를 읽으며, 저장된 마지막 위치로 가상 로봇을 옮기는 편법도 사용하지 않는다.

현장 연결 시 남은 부분은 실제 센서/제어기에서 `ResumeEvidence`를 공급하는 어댑터, 지도 작업자 정지 후 SLAM 직렬화 연결, 젯슨의 정상 OS 종료 및 모터·리프트 안전 상태 인수다. 실제 장치의 안전 종료 확인 없이 앱이 “전원을 뽑아도 된다”고 표시하지 않는다. 현재 로컬 시험은 OS 종료 명령이나 모터 명령을 보내지 않는다.

## 2026-11-12 기록 지도와 현재 외형 비교

- SSH 조회 전용 `--prepare-hold`로 양팔 12개·리프트 1개 위치를 읽었다. `executed:false`이며 이동·토크 변경은 하지 않았다. 양팔·리프트 torque 1, 리프트 raw 3694였다.
- 공식 원본 STL 해시를 검사한 뒤 기존 S2 변환·Home 보정·바닥 기준을 재사용했다. 본체, 바퀴 3개, 리프트, 양팔 마운트와 모든 arm visual, D415, LDS-01을 포함했다. 표시용 축약 mesh는 치수 계산에 사용하지 않았다.
- 현재 관절각·리프트 최하단 참조에서 모델 외형: 전후 0.3790 m, 좌우 0.4248 m, 바닥 기준 최고점 1.1116 m, 회전 전체를 감싸는 반경 0.28435 m. 이 값은 설치 외형의 실측 증명은 아니며 전원선·추가 받침·CAD에 없는 부품은 포함하지 않는다. 리프트 높이는 명시적 최하단 참조이며 raw 값으로 전원 재연결 후 영점을 재구성하지 않았다.
- 기존 기록 검토 도구에 `--traversability`를 추가했다. 기록 SLAM 궤적 일치와 원본 mesh 해시를 검사하며, 원본 라이다 지도를 변경하지 않고 상부 깊이 및 몸체 여유의 비교 그림·수치만 저장한다. 3 cm 여유는 이번 검토의 명시적 가정이며 제동 거리나 실측 보정값이 아니다.
- 결과: 기존 라이다 free 중 상부 깊이와 겹치는 674개 칸(5 cm 격자). 상부 검토 높이는 라이다 측정면 +5 cm부터 모델 최고점 +3 cm까지다. 이는 높이 보완 효과의 후보이며 완전한 주행지도 면적이나 실물 장애물 수가 아니다.
- 원본 저장 위치: `output/s4-traversability-20261112/`. 현 자세를 과거 환경 기록에 대입한 비교이므로 역사적 모든 프레임의 팔 자세를 증명하지 않는다. 자기 몸체 제거, 낮은 장애물·전체 높이 ray 기반 빈 공간 확인, 실제 주행 검증은 별도다. 밝게 남은 칸도 통과 가능으로 인증하지 않았다.

## 2026-11-12 통행 검토의 과도한 확장 수정

사용자가 넓게 칠해진 접근 제한을 지적했다. 이전 검토는 모든 높이의 장애물을 전체 외형의 회전 원으로 확장하고, 5 cm 셀에 반경을 올림한 결과와 미관측 영역까지 같은 빨간색으로 표시했다. 이는 실제 물체 영역이나 로봇의 고정 방향 통과 가능성을 표현하기에 과도했다.

- 검토 도구는 원본 STL 삼각형을 높이 구간으로 잘라 부품별 XY 외형을 계산한다. 낮은 라이다 관측에는 하단 형상을, 상부 깊이 관측에는 그 높이에 겹치는 몸체 부분만 적용한다. 긴 삼각형이 높이 구간을 가로지르는 경우도 절단 교점을 사용한다.
- 특정 방향에서의 로봇 외형을 반영하고 부품 사이 공간을 합쳐 채우지 않는다. 여유 3 cm는 유지하되 셀 단위로 올려 키우지 않는다. 관측 voxel과 SLAM 셀의 크기·원점 차이로 필요한 면적 반영은 유지한다.
- 주황은 관측 형상, 연한 빨강은 로봇 **중심** 위치의 여유 영역, 회색은 미관측으로 구분한다. 빨간 여유 영역 전체가 실제 장애물이라는 뜻이 아니다. 미관측 영역에는 빨간색을 덧칠하지 않는다.
- 동일 기록·자세에서 라이다 free에 겹치는 중심 제한 후보가 3,558칸에서 3,080칸으로 13.4% 감소했다. 그림의 회색 표시 변경과 실제 후보 감소는 구분한다.
- 결과는 `output/s4-traversability-20261112/height-matched-review/`. 표시된 마지막 기록 방향에 한정된 비교이며 회전 중의 쓸림·상부 미관측 공간은 검증하지 않았다. 활성 주행 지도나 제어기를 교체한 것은 아니다.

## 2026-11-12 주거 물체 인식 보완

기존 DINO/SAM, RGB-D 좌표 변환, FurnitureMemory를 유지하고 다음 검토 경로를 추가했다.

1. 명시적으로 확인한 지도 바닥 높이가 있을 때 의미 마스크의 바닥 근처 점을 분리한다. 현재 검토는 바닥 위 6 cm를 바닥 경계 구간으로 보고, 유효 마스크 점 중 65%를 넘으면 바닥 지배 마스크로 재관측 대상에 둔다. 이 값은 의미 분할의 초기 정책이며 주행 장애물이나 라이다 지도 삭제 기준이 아니다. 바닥 높이 입력이 없는 기존 경로에는 적용하지 않는다.
2. 한 마스크가 깊이 검사를 통과하지 못해도 같은 프레임의 다른 정상 가구는 보관한다. 그림에는 실제 채택된 검출만 표시한다.
3. 선택적 `--household-review`는 공식 SigLIP 2 base (`google/siglip2-base-patch16-224`, revision `75de2d55ec2d0b4efc50b3e9ad70dba96a7b2fa2`)로 원래 물체 영역과 주변 12%를 포함한 영역을 각각 분류한다. 두 영역의 순위가 일치하고 각 1·2위 logit 차이가 0.5 이상일 때만 재분류 후보로 쓴다. 이 점수는 정답 확률이 아니다. 집 영상은 외부로 전송하지 않으며, 추론은 고정 revision의 로컬 safetensors 모델로 수행한다.
4. 서로 다른 큰 가구 이름이 충돌하면 `unclassified_furniture`로 형상을 보존한다. 이것은 냉장고를 수납장으로 확정한 것이 아니다. 작은 물건과 바닥·벽도 분류 후보에 포함해 모든 영역을 큰 가구로 억지 분류하지 않도록 한다.
5. 저장된 시점별 카메라 변환으로 서로 다른 capture 수와 관측 방향 그룹을 구분한다. 8 cm 이동 또는 10° 방향 차이로 그룹을 나누는 검토 정책이며, 같은 이미지 반복이 독립된 확인이 되지 않게 한다. 여러 시점에서 반복됐어도 물체 종류나 동일성을 실측 검증했다는 뜻은 아니다.

`--semantic-floor-filter`는 재분류 없이 깊이 검사만 적용하는 비교 옵션이다. 기준 결과는 기존 6장(`s4-recorded-semantics-20261112-05`)이며 같은 capture ID와 원본 깊이로 전후를 비교한다. 별도 12장 묶음에는 원래 6장과 겹치는 장면이 있으므로 독립적인 새 집 평가로 세지 않는다.

주거 공간 이해의 다음 확장은 다양한 시점의 외관·형상 연결, 사용자 가구 이름의 지속성, 실제 옮긴 가구의 추적이다. 물체 이름/마스크 개선과 지도 위치 오차 개선은 따로 평가한다. 센서 외부 보정·SLAM 정합 오차가 이름 재분류로 없어지는 것은 아니다.

참고: [SigLIP 2 공식 모델](https://huggingface.co/google/siglip2-base-patch16-224), [ConceptGraphs의 여러 시점 RGB-D 기반 객체 지도](https://concept-graphs.github.io/).

### 저장 영상 비교 결과

- 원래 6장: 탁자 2개(하나는 바닥 오인식), 의자 후보 2개, 옷장 후보 1개였다.
- 깊이 검사만 적용: 바닥을 탁자로 저장하던 1개 항목이 제외됐고 실제 탁자의 4회 관측은 유지됐다.
- 교차 분류 적용: 실제 탁자 4회 / 관측 방향 3개 그룹 유지. 두 의자 후보는 이 묶음에서 의미 지도에 추가되지 않았다. 회색 가구는 옷장·수납장·냉장고가 엇갈리므로 종류 미확정 상태다.
- 겹치는 수납 가구 가설은 원래 인스턴스를 보존한 채 단일 검토 항목으로 묶는다. 관측 voxel의 작은 집합 대비 60%, 큰 집합 대비 10% 이상 겹치고 양쪽 모두 유일한 후보일 때만 묶는다. 여러 물체에 걸친 넓은 마스크는 합치지 않는다. 원래 6장의 검토 지도는 탁자 1개와 종류 미확정 가구 1개로 정리된다.
- 12장 추가 묶음은 기존 6장과 2장이 겹치며 10장이 새로 평가됐다. 탁자는 9회 / 방향 3개 그룹, 종류 미확정 가구는 2회 / 방향 2개 그룹이다. 의자 후보가 2회 다시 나왔지만 같은 방향 1개 그룹이라 미확정으로 남는다. 의자 오인식이나 냉장고 분류가 해결됐다고 판정하지 않는다.
- 원시 결과·비교 그림·해시는 `output/s4-household-semantics-20261112/`. 다른 집이나 독립 정답 라벨이 있는 평가가 아니므로 정확도 백분율을 주장하지 않는다. 형상과 이름 분리는 주행 깊이 장애물을 지우거나 지도 좌표를 보정하지 않는다.

### 다음 실물 단계와 모델 비교 순서 — 2026-11-12

사용자 결정에 따라 다음 실물 단계는 관측 범위를 넓힌 지도 생성용 수집이다.
라이다와 RGB-D 원본·취득 시각을 함께 보존하고, 시멘틱 모델 선정은 지도 생성 후
같은 영상과 고정된 지도 좌표를 대상으로 비교한다. 현재 SigLIP2 보완 결과를 최종 모델
선정으로 간주하지 않는다. 비교 대상은 주요 주거 가구의 분류, 바닥 오인식, 중복 물체,
관측 형상의 지도 정합이며 분류 개선을 측량 정확도 개선으로 합산하지 않는다.
RGB-D 높이 장애물 처리는 이 모델 선정과 독립적으로 유지한다.

새 수집은 기존 수동 조종 화면과 원본 기록 도구를 재사용한다. 이번 화면에는 이전의
작은 고정 지도를 표시하지 않으며, 지도 생성과 연결 품질 평가는 수집 종료 후 수행한다.
한 구간의 기록·종료는 실제 전원 재연결 후 지도 이어하기 검증을 대신하지 않는다.

### 전원선 조건에 따른 S4 실물 범위 조정 — 2026-11-12

사용자가 배터리 도착 전에는 텔레옵으로 구간별 지도를 만들고 S4를 진행하기로 결정했다.
집 전체 자동 탐색의 실물 검증은 배터리 도착 이후로 이관한다. 기존 자동 탐색 구현을
삭제하거나 실물 완료로 표시하지 않는다. 목적지 주행·모바일 집기 등 나머지 S4 검증도
이 결정만으로 완료되거나 면제되지 않는다.

사용자는 플러그 이동 때 젯슨과 모터 전원이 함께 꺼진다고 확인했다. 각 구간은 조종
종료와 바퀴 정지를 확인한 뒤 원본·지도·SLAM 그래프를 저장하고 검증한다. 전원 차단
전에 팔·리프트의 기계적 지지와 젯슨의 정상 OS 종료를 확인한다. 화면의 기록 종료만으로
플러그를 뽑아도 된다는 뜻은 아니다. 재부팅 후에는 센서·현재 자세·정지 상태를 새로
조회하고, 겹치는 공간의 관측으로 기존 지도 위치를 다시 찾은 뒤 다음 구간을 연결한다.
저장된 마지막 위치나 바퀴 적산값을 새 부팅의 위치로 간주하지 않는다.

실제 전원 재연결 후 새 구간을 기존 SLAM 그래프에 추가하고 RGB-D를 같은 지도 좌표에
등록하는 검증은 아직 남아 있다. 기존 그래프 저장·동일 셀 복원 검사와 구분한다.

### 2026-11-15: 등록 가구 위치 교체와 Nav2 외곽 여유

다중 RGB-D 관측으로 같은 가구의 새 위치를 확인한 경우, 등록된 가구 형상과
그 가구에 연결된 원본 라이다 셀은 새 위치의 기여분으로 교체한다. 옛 위치를
다시 촬영할 때까지 동일 가구의 복제 형상을 남기는 이전 방식은 이 경우에
적용하지 않는다. 원본 지도와 이력은 보존하고 운용 지도에서만 차감한다.
확인 조건은 기존 appearance+geometry 재식별, 동일 reference revision,
중복 없는 3개 이상 촬영 증거이며, 실제 위치 기억은 기존 2초 이상 관측 확인을
거친다. 미등록 상부 물체·가구 영역 밖 라이다·실시간 센서 장애물은 유지한다.
새 가구 형상이 이전 셀과 겹치면 최종 합성 지도에는 계속 장애물로 남는다.

현재 원본 라이다의 가구 귀속은 등록 형상의 XY 볼록 영역 안에 있는 원본
점유 셀을 사용한다. 개별 다리의 시각적 인스턴스 분할을 했다는 의미는 아니다.
다른 물체가 함께 등록된 영역에서는 귀속 정밀도 한계가 있으므로 독립 상부
관측과 실시간 라이다·깊이 장애물 층은 함께 유지한다. 전체 낡은 맵을 지우는
방식이 아니며, 위치가 확인되지 않은 물체는 관측 부재만으로 삭제하지 않는다.

Nav2 외곽은 원본 고정 리프트/장착대 다각형의 각 변에 수직인 방향으로
3cm 여유와 기존 격자 오차 여유를 한 번만 더한다. Nav2의 X/Y 부호별
footprint_padding에 이 값을 전달하면 대각선 방향 여유가 과도하게 커지므로
미리 계산한 다각형을 전달하고 추가 padding은 0으로 한다. 실제 외형·속도·
진행 방향 15cm 침입 정지 검사는 유지한다.
