# 생활 공간의 지도 만들기와 변경 반영

2026-11-11. 대상은 ALOHA Mini 1 기반 가정용 로봇이다. 사용자는 SLAM 명령, 좌표계, 지도 파일을 다루지 않는다. 집 지도는 마지막으로 확인한 기억이며, 현재 통행 가능 여부는 동작 중 센서로 다시 판단한다.

## 2026-11-12 기준: Mini 1이 통과할 수 있는 지도

RGB-D와 2D 라이다의 통합 목적은 **라이다 측정 높이 밖의 형상을 보완하는 것**이다.
RGB의 가구 이름은 위치 설명에 쓰며, 이동 가능 판정의 전제나 장애물 제거 조건으로 쓰지 않는다.

- 라이다가 탁자 다리 사이를 빈 공간으로 보더라도, 상판·돌출부가 로봇의 통과 높이에 겹치면 깊이 관측으로 차단한다.
- 바퀴뿐 아니라 본체·팔·리프트·카메라·운반 물체가 포함된 현재 주행 외형을 기준으로 한다. 수평 외형과 여유 폭을 반영하고, 팔·리프트·하중이 바뀌면 외형과 경로를 다시 계산한다.
- 깊이 volume의 전체 높이를 일괄 투영하지 않고, 지도 바닥부터 해당 외형의 높이(수직 여유 포함)까지 겹치는 voxel만 투영한다. 로봇보다 충분히 높은 구조물이나 그 위 미관측 영역 때문에 길을 불필요하게 막지 않는다. 경계 voxel은 부분적으로 겹쳐도 포함한다.
- 해당 높이 구간을 충분히 보지 못하면 미확인으로 남긴다. 라이다 free나 RGB 인식 실패만으로 통과 가능을 만들지 않는다. 가구 이동에 따른 새 장애물 추가와 옛 위치 해제에도 같은 높이 범위를 사용한다.
- 기본 의미 지도는 냉장고·소파·책상/탁자·침대·수납장 등 주요 가구 중심이다. 바구니·휴대용 선풍기 등의 별도 이름표는 생략해도 원본 깊이 형상은 유지한다. 소파 아래 물건을 이름상 따로 나열할 필요는 없으며, 실제 소파 확인 없이 임의로 소파로 재분류하지 않는다.

현재 코드는 기존 `navigation_fusion`, `projected_grid`, `AdaptiveMap`을 재사용한다.
낮은 상판 차단, 충분히 높은 상판 아래 통과, 필요한 높이만의 관측 범위, 이름 없는 작은 장애물과 몸체 폭을 로컬 검사했다.
이는 소프트웨어 검사다. 이번 실측 기록의 지도 내보내기에서 사용한 반경 0.22 m·높이 1.2 m는 임시값이며, 실물 전체 외형 검증값으로 사용할 수 없다.
실측 RGB-D의 상부 형상 미리보기와 의미 인식은 완료했지만, 자기 몸체 제거·현재 주행 자세 외형·전체 높이의 빈 공간 관측을 연결한 실물 통행 지도는 아직 인수 전이다.

## 사용 흐름

1. 앱의 **집 지도 만들기**를 누른다. 센서 상태, 현재 위치, 운반 자세가 준비되어야 탐색을 시작한다. 필요한 경우 앱은 “카메라 연결을 확인해 주세요”처럼 고칠 수 있는 원인을 보여준다.
2. 로봇은 주변부터 관측하고, 확인된 안전한 바닥 안에서 다음 관측 위치를 고른다. 미리 정한 집 모양이나 방문 순서는 쓰지 않는다. 지도에서 관측된 영역, 남은 미확인 영역, 로봇의 진행 상태를 보여준다.
3. 라이다로 바닥 평면과 위치를 추정하고 상단 깊이 카메라로 상판·돌출부 등 높이 형상을 기록한다. RGB 인식과 분할 결과를 깊이에 연결해 책상·소파 등의 이름과 관측된 모양을 덧붙인다. 모르는 물건도 깊이 장애물로는 반영한다.
4. **일시정지**는 실제 정지 확인까지 “멈추는 중”으로 표시한다. **이어하기**는 현재 센서와 위치를 다시 확인한 뒤 실행한다. 앱 화면을 닫는 것은 취소가 아니며 재접속하면 상태를 보여준다. 서버가 재시작되면 자동 재출발하지 않는다.
5. 탐색 가능한 구역을 돌아본 뒤 출발점으로 돌아가 지도 검토로 전환한다. 닫힌 문, 가려진 곳, 지나갈 수 없는 곳은 남겨 둔다. “집 전체 100%”라는 보장 대신 실제 지도 범위의 관측률을 표시한다. 사용자는 방 이름을 수정하거나 그대로 저장할 수 있다.
6. 평소 요청은 “거실 탁자에 있는 리모컨 가져와”처럼 한다. 이동 중 주변이 달라졌으면 필요한 곳만 다시 확인하고 경로를 갱신한다. 가구 하나를 옮겼다는 이유로 처음부터 집 지도를 다시 만들도록 요구하지 않는다.

## 지도와 기억을 나누는 기준

| 자료 | 용도 | 갱신 조건 |
|---|---|---|
| 라이다 위치 추정 지도와 pose graph | 현재 위치, 방 사이 연결, 루프 연결 | SLAM 추정과 재위치 추정이 유효할 때 |
| 깊이 3D 관측 기록 | 높이 형상, 재투영, 관측 근거 | 노출 시각의 카메라 위치·보정값과 함께 기록 |
| 주행용 2D 지도 | 바퀴뿐 아니라 팔·리프트·적재물을 포함한 통과 여부 | 전체 운반 높이의 깊이를 투영하고 라이다와 결합 |
| 실시간 주변 장애물 | 사람, 옮겨진 의자·탁자, 경로 변경 | 현재 센서로 즉시 추가, 독립된 빈 공간 관측으로 제거 |
| 방·가구 의미 정보 | 사용자의 장소 이름과 물체 검색 | RGB 분류와 관측 형상, 사용자 이름 확인. 위치 변경 시 다시 관측 |

저장한 3D 기록은 과거 관측이다. 앱을 다시 켰다고 관측 시각을 새로 찍거나 주행 안전 자료로 재사용하지 않는다. SLAM 루프 보정으로 좌표가 달라지면 예전 전역 voxel을 그대로 더하지 않고 새 좌표에 재등록한 자료로 재구축한다. 일반적인 가구 이동과 SLAM 좌표 수정은 서로 다른 사건이다.

## 탁자가 옮겨졌을 때

- 새 위치의 라이다 또는 깊이 장애물은 곧바로 경로 검사에 반영한다. 인식 모델이 “탁자”라고 부를 때까지 기다리지 않는다.
- 옛 위치는 **현재 라이다가 빈 공간을 관측하고, 로봇의 전체 높이 구간도 깊이로 비어 있음을 확인**한 경우에만 지운다. 서로 다른 시각의 관측 두 번을 요구한다. 가림, 깊이 결측, 인식 실패, 센서 시간 초과는 빈 공간의 근거가 아니다.
- 벽 등 보호한 구조물은 이 국소 지우기 절차로 제거하지 않는다. 위치 추정 품질이 나쁘면 지도 수정과 이동을 중지하고 다시 위치를 확인한다.
- 가구의 과거 관측 형상은 기록으로 남긴다. 확인된 빈 영역과 겹치는 현재 형상만 비운다. 멀리 떨어진 같은 종류의 가구를 무조건 같은 물체라고 합치지 않는다. 사용자 이름을 자동 이동시키려면 추가 동일성 확인이 필요하다.
- 경로 중심선뿐 아니라 운반 외형의 여유까지 고려해 영향 범위를 판단한다. 지도 버전이 바뀌면 기존 계획은 무효화한다. 현재 구현은 기존 실행기의 취소·전체 정지 확인을 재사용하고, 정지가 끝난 뒤 새 지도를 적용한다.
- 현장 실행 어댑터는 정지 후 최신 위치와 주변 관측을 공급하고 새 경로를 만들어 요청을 이어야 한다. 집기나 놓기까지 진행하던 작업은 물체·하중·상판도 재확인한다. 취소된 명령을 그대로 재전송하지 않는다. 이 자동 재관측·재계획 연결은 실물 어댑터 인수 항목이며, 현재 로컬 UI가 물리 로봇에서 수행한다고 표시하지 않는다.

## 이번 로컬 구현의 범위

| 구현 | 검증 범위 |
|---|---|
| `home_survey.py` 관측 기반 다음 위치 선정 | 보이는 부분만 계획기에 전달. 숨겨진 집 모양이 달라도 같은 관측이면 같은 다음 위치. 기존 작업 실행기·소유권·정지 재사용 |
| 앱 자동 탐색 | 시작·정지 확인·이어하기·검토·저장. 재시작 후 PAUSED, 명시적으로 이어하기. 가상 센서와 가상 이동이며 실제 SLAM 자동 주행 아님 |
| 실제 SLAM 저장/복원 | 합성 라이다를 실제 slam_toolbox에 입력하고 별도 프로세스에서 그래프 복원. 자동 탐색 앱과 실물 센서 연결은 미인수 |
| `semantic_mapping.py` | 기존 DINO/SAM 어댑터 재사용, RGB 범주와 정렬된 깊이 형상 연결, 모델 버전·RGB/깊이 해시·카메라 변환 저장 |
| `replay_home_scan.py` | native-depth와 선택적 RGB·aligned-depth·분할 기록을 함께 재생해 지도/3D/의미 정보를 보관. 모델 추론 결과 재생을 새 추론으로 표시하지 않음 |
| `adaptive_mapping.py` | 현재 라이다 ray와 기존 깊이 volume 결합. 오래된 입력·중복 입력·잘못된 문맥 거부, 장애물 추가·확인 후 제거·보호 구조물 유지 |
| 기존 실행기와 지도 갱신 연결 | 진행 중 경로 취소 → 전체 정지 확인 → 지도 적용 → 최신 위치 요구. 실물 자동 재출발 권한 없음 |

이 단계에서 학습 모델의 가정 환경 정확도, 유리·반사체 검출, 실물 전방/후방 시야, 계단·낙차 검출은 보장하지 않는다. 이런 입력을 확인하지 않고 단순히 앱 버튼만 물리 모터에 연결하지 않는다. 전방 카메라만으로 뒤쪽 이동의 높이 공간이 확인되지 않는 경우 회전해서 관측하거나 미확인으로 남겨야 한다.

## 현장에서 연결할 순서

기존 S4 인수 문서의 바퀴·정지·센서·운반 외형 확인 후, 실제 캡처 작업자가 SLAM 위치와 노출 TF를 고정해 지도 작업자에 전달한다. RGB 추론은 별도 작업자로 돌려 주행 정지 루프를 막지 않으며 최신 프레임만 제한된 큐로 처리한다. 현재 주행 안전 검사는 인식 모델 없이도 작동해야 한다.

그다음 작은 구역의 자동 탐색, 좁은 문·막힌 길·가려진 상판, 탐색 중 취소, 센서 끊김, 저장 후 재시작을 확인한다. 마지막으로 탁자를 옮기고 새 위치 차단/옛 위치 해제/경로 갱신을 확인한 뒤 물체를 든 운반 작업에 연결한다. 지도 저장 성공만으로 실제 자율 탐색이나 배송 성공을 판정하지 않는다.

## 전원을 나눠 연결할 때의 저장·재개

앱의 **저장하고 종료**는 일반적인 지도 완성/저장과 다르다. 탐색 도중에도 누를 수 있으며, 진행 중 이동을 기존 실행기로 취소하고 전체 정지를 확인한 뒤 저장한다. 저장이 끝나기 전에는 종료 준비 완료를 표시하지 않는다. 현재 앱은 가상 실행이므로 “저장 완료 · 가상 실행 종료 준비 완료”로 표시하며 실제 컴퓨터나 모터 전원을 끄지 않는다.

저장 내용은 지도, 탐색 위치/진행 기록, 방 이름, 가구·RGB 의미 관측, 보관된 깊이 voxel, 그리고 실제 SLAM 작업자가 제공한 pose graph 두 파일이다. 시뮬레이션에는 pose graph가 없다고 명시하며 replay 모드의 체크포인트는 두 파일 없이 저장할 수 없다. 이동하지 않는 관측 지점마다 자동 저장하고, 종료 요청 때 최신 내용을 한 번 더 저장한다.

같은 SQLite 저장소에 원자적 트랜잭션과 FULL 동기화를 사용한다. 모든 자료의 해시와 이를 가리키는 포인터를 함께 확정한다. 현재 저장본과 이전 두 세대를 유지하고 중복 자료는 공유한다. 저장 중 프로세스가 종료되면 미완성 저장본은 사용하지 않는다. 최신 세대의 해시가 맞지 않으면 이전의 온전한 세대로 돌아간다. 파일시스템/저장장치 전체 손상까지 복구하는 백업은 아니므로 외부 백업을 대체하지 않는다. 저장 실패 시 앱은 전원을 유지하고 다시 저장하도록 안내한다.

재시작하면 저장된 지도는 표시하지만 동작은 PAUSED 상태다. **이전 지도 이어 만들기**를 누른 뒤 현재 부팅에서 새로 관측한 위치, 센서, 팔·리프트 상태와 정지를 확인해야 재개한다. 지난 부팅의 위치나 타임스탬프를 새 상태로 바꾸어 쓰지 않는다. 위치를 찾지 못하거나 센서 상태가 나쁘면 이동하지 않고 기다리며, 확인 시간이 지나면 다시 이어하기를 요청하도록 안내한다. 보정값이나 지도 좌표계가 바뀌면 바로 재개하지 않는다. 로컬 모드에서는 현재 가상 로봇의 위치를 읽으며, 저장된 마지막 위치로 가상 로봇을 옮기는 편법도 사용하지 않는다.

현장 연결 시 남은 부분은 실제 센서/제어기에서 `ResumeEvidence`를 공급하는 어댑터, 지도 작업자 정지 후 SLAM 직렬화 연결, 젯슨의 정상 OS 종료 및 모터·리프트 안전 상태 인수다. 실제 장치의 안전 종료 확인 없이 앱이 “전원을 뽑아도 된다”고 표시하지 않는다. 현재 로컬 시험은 OS 종료 명령이나 모터 명령을 보내지 않는다.

## 2026-11-12 통행 검토의 과도한 확장 수정

사용자가 넓게 칠해진 접근 제한을 지적했다. 이전 검토는 모든 높이의 장애물을 전체 외형의 회전 원으로 확장하고, 5 cm 셀에 반경을 올림한 결과와 미관측 영역까지 같은 빨간색으로 표시했다. 이는 실제 물체 영역이나 로봇의 고정 방향 통과 가능성을 표현하기에 과도했다.

- 검토 도구는 원본 STL 삼각형을 높이 구간으로 잘라 부품별 XY 외형을 계산한다. 낮은 라이다 관측에는 하단 형상을, 상부 깊이 관측에는 그 높이에 겹치는 몸체 부분만 적용한다. 긴 삼각형이 높이 구간을 가로지르는 경우도 절단 교점을 사용한다.
