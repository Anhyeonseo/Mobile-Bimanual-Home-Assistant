# S2 — ALOHA Mini 1 좌표와 관측 연결

2026-11-05. 대상은 **공식 ALOHA Mini 1 + SO-ARM101 follower 양팔**이다.
Mini 2/AM-ARM200 규격과 기존 시뮬레이션의 임의 장착 치수를 사용하지 않는다.
현재 상태는 **명목 좌표 연결·양팔 기준 자세 대응·관측 도구 구현 완료, 마지막 실물 통합 조회 대기**다.
[최신 결과와 실행 절차](S2_HANDOFF.md)를 우선 참고한다. 아래 상세 기록은 진행 당시의 판단을 포함한다.
정밀 수락은 S3로 미뤘으며, 실제 통합 조회까지 끝난 것으로 표시하지 않는다.

S2의 결과는 카메라에서 관측한 표면점과 양팔의 고정 TCP를 같은 `base_link`에서
표현하는 좌표 프로필이다. 파지 위치 선정·그리퍼 접촉 폭/힘·충돌 회피·동작 실행은
S3에서 다룬다. S2 프로필은 이동 권한을 부여하지 않는다.

## 최신 진행 범위 결정 (2026-11-05, 사용자 지정)

- 리프트는 최저·중간·상단·복귀의 근사 실물 확인과 구동/정지 기록을 바탕으로
  현재 환산값을 유지한다. 추가 정밀 측정은 반복하지 않으며 실제 오차가 커질 때 재검토한다.
- 카메라는 현재 명목 설치 모델을 유지하고, 정밀 외부 보정은 S3 실제 집기 테스트에서 수행한다.
- 양팔 기준 자세 대응은 지금 진행한다. 기존 EEPROM의 2048 보정값과 관절 범위를
  변경하지 않고, 알려진 모델 자세에서 읽은 엔코더값으로 소프트웨어 각도 오프셋을 기록한다.
- 고정 TCP는 공식 링크 기하·팔 장착 변환·관절 영점·방향으로 계산한다. S2에서는
  실물과의 큰 불일치만 확인하고, 다수 자세의 독립 정밀 측정은 S3 작업 오차 검증과 연계한다.
- 아래의 기존 정밀 수락 기준은 참고용으로 보존한다. 보류한 측정값을 합성하거나
  기존 엄격한 `commission` 검사를 통과한 것으로 표시하지 않는다. 개발용 연결과 정밀 수락을 구분한다.

### 그대로 적용하면 틀리는 값

1. **현재 Home=2048은 공식 URDF의 0 rad와 같은 뜻이 아니다.** 혼을 다시 끼운 뒤의
   대응각을 별도로 계산한다. 기존 팔 macro의 2026년 7월 Home 각도도 재사용하지 않는다.
2. Mini 1 CAD의 `left_base/right_base`와 독립 SO101 URDF의 `base_link`는 서로 다른
   원점이다. 이름만 이어 붙이지 않는다. 공식 내부 형상을 사용하고, 실물 TCP 대응점으로
   각 팔의 장착 변환을 검증할 수 있다. 현재 개발값은 두 공식 모델의 공통 베이스 STL 좌표와 visual 원점으로 도출했다. 독립 정밀 검증은 S3에서 진행한다.
3. Mini 1 CAD URDF의 관절 한계가 모두 0으로 내보내져 있고 리프트 0도 실제 최저점이
   아니다. 이를 운용 범위나 원점으로 복사하지 않는다.
4. 기존 전체 모의 모델의 팔 간격 0.28m, 이동량 0.50m, 리프트에 붙은 카메라 등은
   모의 전용이다. 이번 좌표 모델은 사용자가 확인한 **베이스/고정 기둥 D415**를 따른다.

이전 리프트 관측(약 90→26cm, 30,717 counts, 환산 약 85.34mm/회전)은
`lift_geometry.measured.json`에 그대로 보존했다. 공식 84mm/회전을 적용하면 같은
회전량은 약 62.99cm, 하단 26cm 기준 상단 약 88.99cm다. 당시 상단이 근삿값이었으므로
이번에는 정확히 읽은 높이로 검증한다. 기존 펌웨어/구동 프로필의 환산값은 변경하지 않았다.

### 베이스 원점 정의 (2026-11-05)

`base_link`의 명목 원점은 공식 Mini 1의 세 바퀴 관절 원점(회전축 중심)의 평균으로
정한다. CAD 좌표로 `[-0.0000684667, 0.0001346667, 0.0422] m`이며, CAD −Y가
로봇 +X(앞쪽 카메라 장착면 방향), CAD +X가 로봇 +Y(왼쪽), CAD +Z가 로봇 +Z다.
이 정의는 베이스에 고정되며 리프트 높이와 무관하다. 주행에서 쓸 `base_footprint`는
바닥 투영 기준으로 구분한다. 바퀴 축 높이의 `base_link`를 바닥 높이 0으로 혼용하지 않는다.

명목 CAD→base 변환은 `installation.development.json`의 `nominal_base_from_cad`에
기록했다. 이 단계는 좌표 정의이며 실제 설치 확인·카메라 보정 완료가 아니다.
설명용 좌표 뷰어와 리프트 끝점 뷰어는 이 원점을 함께 사용한다. 전체 형상·바닥·
카메라 예시·팔 장착 예시에 같은 강체 변환을 적용해 상대 배치를 유지했다.
기존 수락 프로필은 자체 베이스 정의를 보존하며 자동 변환하지 않는다. 실제 설치의
수락/런타임 좌표 연결은 독립 측정과 검증 후 진행한다.
실물 보정에서는 접근 가능한 표적/지그의 이 원점에 대한 오프셋을 사용하므로,
로봇 내부의 가상 원점에 직접 표식을 붙일 필요는 없다.

## 실물에서만 확인할 항목

### 사용자 결정에 따른 현재 진행 순서 (2026-11-05)

- D415를 앞쪽 더듬이의 경사진 정면에, 카메라 윗면이 그 면의 위쪽 끝과 맞도록
  고정했다는 사용자 확인을 받았다. 장착 완료는 기록하되 위치·각도 외부 보정과
  독립 오차 확인은 아직 미완료다. 보정 표적의 베이스 기준 위치를 독립적으로
  정한 뒤 촬영해야 하며, 크기만 아는 표적을 임의 위치에 놓는 것으로 대체하지 않는다.
  체커보드/ArUco 출력물 자체는 필수 조건이 아니다. RGB-D 점과 독립적으로 알려진
  로봇 기준 형상도 사용할 수 있으나, 현재 사용자는 프린터·자/줄자가 없으므로
  CAD 초기값 연결을 먼저 진행한다. 바닥 한 면은 높이·롤·피치만 제한하며 평면 내
  위치·요는 별도 기준이 필요하다. 미확인 팔 영점을 정답 좌표로 사용하지 않는다.
  D415는 공식 RealSense 주변기기 STL/Xacro로 교체했다. 본체 99×23×20.05mm와
  RGB/Depth 광학 좌표·바닥 나사 기준을 구분한다. 공식 명목 센서 변환도 장치별
  보정값과 같지 않으므로, SDK 보정값 및 장착 오차 확인 전에는 실물 수락값으로 쓰지 않는다.
  출처와 해시는 `d415_official_geometry.json`에 별도로 고정했다.

- 리프트의 기존 최저·최고 위치는 공식 부품 조립체의 기계적 하단·상단 끝점과
  같다는 사용자 확인을 설치 기록에 반영했다. 끝점 높이를 다시 재도록 요청하지 않는다.
  기존 26cm/약 90cm 기록은 보존한다. 이후 사용자가 지정한 접촉부인 베이스 판 윗면과
  더듬이 받침 아랫면에 대해 원본 STL 삼각형 접촉을 계산했다.
  `tools/diagnostics/s2_viewer/lift-contacts.json`의 CAD 결과는 상판 높이 약
  왼팔 장착판 23.49/87.87cm, 오른팔 장착판 23.56/87.94cm, 이동량 약 64.38cm다. 이 값은 지정 접촉면 기준이며 전체 기구의
  충돌 검사나 실물 수락값이 아니다. 정적인 STL의 전체 높이나 URDF의 0인 한계를
  이동량으로 쓰지 않으며, 기존 실측/운용 환산값을 이 결과로 덮어쓰지 않는다.
  사용자 지정 높이 기준은 바닥부터 SO-ARM이 결합되는 위쪽 장착판 윗면이다.
  중앙 T 연결판 기준 22.85/87.24cm는 이전 기준이며 이제 사용하지 않는다.
  공식 좌우 팔 장착 XY에서 해당 장착면 평면을 평가한다. 원본 삼각형 19718/17518을
  기준으로 평면을 찾으며, 원점·면·좌표와 양쪽 높이를 보고서에 별도로 저장한다.
  공식 CAD의 좌우 높이 차이는 약 0.70mm다. 사용자가 바닥부터 베이스 밑판
  아랫면까지 약 28mm임을 실측·확인했다. CAD 바닥 여유 7.30mm를 실물에 적용했던
  차이 20.70mm를 바닥 기준에 반영하면 좌측 25.56/89.94cm, 우측 25.63/90.01cm다.
  이는 CAD 접촉 계산에 실측 바닥 기준을 적용한 값이며, 개별 끝점의 정밀 실측값은
  아니다. `lift-floor-reference.json`에 계산 출처와 확인 기록을 저장한다.
  28mm 측정은 바퀴 지름·모터 축 위치를 결정하지 않으므로 원본 바퀴/모터 CAD는
  이동시키지 않는다. 현재 보기에서 바퀴는 CAD 참고 위치이며 실측 바닥과 차이가
  남는다고 표시한다. 양팔 영점·카메라 외부 보정·리프트 원점 검증은 별도다.
  위쪽 접촉은 세로 슬라이더 윗끝과 더듬이 받침의 두꺼운 밑단이다. 이전 Z 구간
  선택은 이 밑단을 누락해 최대점을 22.75mm 높게 그렸으므로 폐기했다. 현재는 위쪽
  받침과 아래쪽 베이스 판의 연결된 부품 전체(두께·측벽 포함)를 사용한다. 하단은
  재계산해도 같은 위치이며, 이 두 고정부에 대한 최초 접촉만 확인했다.
  사용자가 수정된 최저·최고 접촉 형상을 확인했다(2026-11-05). 형상 검토는 완료하되,
  이 확인만으로 모터 회전 환산 검증이나 재시작 후 원점 연결을 완료 처리하지 않는다.
- 양팔 방향은 `arm_ranges.development.json`의 기존 부호를 재사용한다.
  몸통/어깨/팔꿈치/손목 굽힘/손목 회전/집게 순으로 양팔 모두 `+,+,-,-,+,-`다.
  이것은 기존 제어 좌표의 부호다. 공식 SO101 각 축으로의 대응은 별도 소프트웨어
  검토 항목으로 남긴다. 오른팔 기록이 왼팔에서 복사됐다는 출처도 보존한다.
- 양팔 2048 자세와 공식 모델 영점의 대응은 사용자 요청으로 나중에 진행한다.
  지금 별도의 방향 재측정이나 영점 자세 맞추기를 요구하지 않는다. 그 전에도
  베이스 기준점/최종 카메라 설치 보정은 진행할 수 있다.
- 아래 표는 전체 수락 절차를 설명하는 기존 기준이다. 위 결정은 **현재 수집 순서와
  자료 재사용 정책**을 바꾸며, 미수집 확인점을 측정 완료로 대체하지 않는다.
  현행 `commission` 입력은 여전히 두 기준각 자료를 요구하므로, 과거 제어 부호만으로
  합성 확인점을 생성하거나 최종 실측 수락을 통과시키지 않는다.

아래는 **한 번의 설치 보정 순서**다. 모터값·계산·파일 작성은 도구에서 처리하고,
사용자는 기준점/자세를 맞추고 실제 높이·표적 위치를 확인한다. 숫자를 추정해서
빈칸을 채우거나 프로그램의 예측값을 정답으로 재입력하지 않는다.

| 순서 | 사용자가 확인할 일 | 필요한 이유와 수집량 |
|---|---|---|
| 1. 설치 확인 | 공식 비율로 출력한 부품인지, 다른 패드/브래킷이 있는지 확인. 베이스 정면과 원점을 표시하고 D415 최종 고정 | 출력 형상은 규격 사용. 변경 부품과 설치 방향만 실물 확인. 베이스 Z는 수직으로 정의 |
| 2. 양팔 영점·방향 | 각 관절을 공식 모델의 알려진 기준 자세 두 곳에 맞춤. 두 자세는 10° 이상 차이 | 팔당 6축의 엔코더값을 읽어 현재 2048과 공식 0 rad의 차이 및 부호 계산. 오른팔도 독립 확인 |
| 3. 리프트 기준 | 같은 상판 윗면의 최저·중간·상단 높이, 최저점 복귀 확인. 재시작 후 같은 기준점 재확인 | 4개 높이 표본 + 원점 재설정 확인. 공식 84mm 환산과 원점 유지를 검사 |
| 4. 고정 카메라 | 베이스 기준 위치를 독립적으로 아는 표적을 여러 위치에 배치 | 보정용 6점 + 별도 확인용 3점. 실제 작업 거리/높이에 분산. 서로 다른 3거리의 깊이도 확인 |
| 5. 양팔 끝 교차 확인 | 각 팔의 고정 TCP 위치/축을 확인할 수 있는 표적·지그를 여러 자세에서 관측 | 팔당 장착 계산용 6자세 + 독립 확인용 3자세. 리프트 높이를 20cm 이상 달리한 구간 포함. 카메라·팔 계산·실제 표적 위치와 축 비교 |

관절 기준각은 **공식 모델의 각도**이지 현재 2048을 무조건 0°로 간주한 값이 아니다.
이미 기록된 방향은 비교 자료로 활용하되, 재조립한 양팔에 자동 확정하지 않는다.
기준 자세 사진/각도 지그로 대응을 확인하고, 두 번째 알려진 각도로 부호와 환산을 검사한다.
기존 실물 운용 범위 파일은 유지하며 이번 수락 검사는 범위를 완화하거나 다시 설정하지 않는다.

TCP 방향은 확인 자세에서 두 축이 식별되는 지그/표적 또는 독립 측정으로 확인한다.
카메라와 팔 계산이 서로 맞는 것만으로 통과하지 않고, **독립적으로 정의한 베이스 좌표와
TCP 축 방향**을 비교한다. 회전행렬은 도구/측정 지그에서 생성한다. 사용자에게 행렬을
눈대중으로 적도록 요구하지 않는다. 원본 표적 측정 자료도 로컬에 보관한다.

공식 고정 TCP를 그대로 쓰면 도구 오프셋을 새로 추정하지 않는다. 실제 측정 표적이 다른
위치에 붙으면 `reference_from_tcp`에 그 장착 오프셋을 명시해야 한다. 움직이는 집게의
가운데나 물체별 파지점을 이 고정 기준점과 혼동하지 않는다. 개구 폭/접촉점 모델은 S3
물체별 집기 수락에 포함하며 이번 고정 기준점의 좌표 수락으로 대체하지 않는다.

D415 내부 보정은 장치의 intrinsics/extrinsics/depth scale을 사용한다. 공장 보정을
다시 수행하는 것이 기본 절차는 아니다. 장치 식별값은 해시로, 사용한 스트림 설정과
공장 보정 정보도 프로필에 연결한다. 해상도/정렬 기준/보정 정보가 바뀌면 재확인한다.
깊이 확인값은 **optical Z(광축 방향 거리)**이며 카메라부터 점까지의 사선 거리가 아니다.

수집은 정지한 자세에서 이루어진다. live reader가 실제 촬영시각과 양팔·리프트의
읽은 시각을 같은 시계로 변환하고, 연결 재시작을 새 session으로 처리하는지도 현장에서
확인한다. 오래된 값이나 서로 다른 시계에 같은 숫자를 붙이는 방식은 사용하지 않는다.
현재 장치의 통합 읽기 가능 여부/펌웨어 프로필은 현장 확인 대상이며 이번 로컬 작업에서
확인된 것으로 표시하지 않는다. 필요한 전환이 있으면 현재 지지·전원 상태부터 확인한다.
수락 파일의 `live_checks`에는 같은 세션에서 연속으로 받은 실제 동기화 스냅샷 3개를
넣는다. 서로 다른 capture ID, 증가하는 획득시각, 실제 수신시각(`received_s`), 장치와
원점 식별이 모두 맞아야 한다. 이 증거가 없으면 실측 완료로 판정하지 않는다.

## 수락 기준과 좌표 흐름

```text
D415 RGB 정렬 깊이 → optical 표면점 → 고정 카메라 보정 → base_link 표면점
양팔 연속 엔코더값 → 현재 Home/방향 대응 → 공식 SO101 FK → 고정 TCP
리프트 연속 누적값 → 이번 세션의 최저 원점 + 공식 환산 → 양팔 장착 높이
                                        ↓
                          같은 촬영시각의 위치·방향 비교
```

리프트 높이가 바뀌어도 고정 D415 변환은 바뀌지 않는다. 양팔 장착 높이만 변한다.
기존 26cm는 과거 측정 기록이다. 현재 CAD+실측 바닥 기준의 장착판 최저 높이는 약
25.6cm이며, 새 수락 기록의 정확한 기준 높이는 자동으로 채우지 않는다. 바닥 기준
높이를 `base_link`에서 팔 원점까지의 거리로 더하지 않는다. 그 변환은 TCP 대응점으로 별도 추정한다.

| 검사 | 초기 S2 허용값 |
|---|---|
| 카메라 보정점·독립점, 깊이 기준 | 최대 10mm |
| 양팔 FK/TCP 보정점·독립점 | 최대 10mm |
| 독립 TCP 축 방향 | 최대 3° |
| 카메라 관측 ↔ 양팔 TCP 전체 연결 | 최대 15mm |
| 리프트 높이·복귀·재시작 원점 | 최대 5mm |
| 관절 기준각 두 점의 환산 일치 | 최대 2° |
| 카메라/관절/리프트 시각 차이 | 최대 50ms |
| live 좌표 입력의 나이 | 최대 200ms, 미래 시각 거부 |
| 지연된 DINO/SAM 분석 결과 | 촬영 후 최대 5초; 촬영시각 좌표로만 반환 |

이 값은 **프로젝트의 초기 좌표 수락 기준**이며 공식 제품 정확도나 작은 펜을 잡을
수 있다는 보증이 아니다. S3에서는 물체 크기·그리퍼 여유에 맞춰 더 엄격한 작업 오차를
검증한다. 보정에 쓰지 않은 점을 별도로 유지하며 실패점 자동 삭제, 허용 오차 자동 완화,
재조립 후 옛 프로필 재사용은 하지 않는다. 결과에는 검사한 자세의 공간 범위도 남긴다.
그 범위 밖의 자세/하중까지 검증한 것으로 확대 해석하지 않는다.

소프트웨어는 누락값·Mini 2 혼입·원본 변조·중복점·퇴화 배치·잘못된 회전·좌표계·
단위·시각·카메라 식별·세션 불일치를 거부한다. 엔코더를 0..4095로 나머지 처리하거나
자동 최단 회전으로 바꾸지 않는다. 모터 읽기 계층에서 확정한 **연속값**을 입력한다.

## 실행 도구

핵심은 L3A `home_robot_tasks.s2_commissioning`, 파일 입출력은
`tools/diagnostics/s2_coordinates.py`다. 새 모터 제어 경로를 만들지 않는다.
아래 모든 명령은 파일만 처리하며 장치를 열거나 움직이지 않는다.

```bash
python3 tools/diagnostics/s2_coordinates.py audit
python3 tools/diagnostics/s2_coordinates.py prepare \
  --output output/home-assistant/s2/measurements.json
# 실물 확인 후 measurements.json의 null 항목을 실제 자료로 채운다.
python3 tools/diagnostics/s2_coordinates.py commission \
  --record output/home-assistant/s2/measurements.json \
  --output output/home-assistant/s2/acceptance.json
python3 tools/diagnostics/s2_coordinates.py export-urdf \
  --profile output/home-assistant/s2/acceptance.json \
  --output output/home-assistant/s2/coordinates.urdf
```

미완료/오차 초과는 종료 코드 2다. 결과 파일을 남길 수 있는 실패는 이유도 기록한다.
기존 출력은 덮어쓰지 않는다. 입력 계약 위반은 승인 프로필을 만들지 않는다.
`provenance=simulation`은 모의 검사이며 절대 `s2_complete=true`가 되지 않는다.
실측 자료를 제출해 전체 검사를 통과한 경우만 `accepted_coordinates`와
`s2_complete=true`를 반환한다. 실측 출처는 수집자가 사실대로 기록해야 하며 파일 해시는
물리적 측정을 자동 증명하는 수단이 아니다.

생성 URDF는 **좌표/TF 전용**이다. 충돌 형상·제어기·이동 권한을 포함하지 않는다.
`robot_state_publisher`에 사용할 경우 기존 모의 모델과 동시에 같은 TF를 발행하지 않는다.
입력 JointState는 `observe` 결과의 `model_joint_positions_si`를 사용한다.
`s2_lift_joint`는 m, `left_model_*`/`right_model_*`는 공식 모델 기준 rad이며, 기존
Home 상대 관절 토픽을 변환 없이 연결하지 않는다. 실제 충돌 모델/MoveIt 운용은 S3 작업이다.

### 고정 D415 장치 기록 연결과 현재 결과

양팔 Home 대응은 사용자 요청대로 보류한다. 먼저 D415의 실제 SDK 내부 보정값과
최종 고정 위치에서의 화면을 확인한다. 모터 전원이나 로봇 이동은 필요 없다.
`realsense_viewer.py`의 새 촬영 기록에는 실제 활성 스트림 해상도·FPS·형식이 들어간다.

```bash
# 현재 코드가 설치된 PC/Jetson에서: 카메라만 90프레임 촬영, 설정 변경 옵션 없음
python3 tools/diagnostics/realsense_viewer.py --headless --frames 90 \
  --depth-filter off --save-on-exit --output output/home-assistant/s2/camera
# 위 명령이 출력한 SAVED 디렉터리를 사용한다.
python3 tools/diagnostics/s2_coordinates.py camera-evidence \
  --snapshot output/home-assistant/s2/camera/<SAVED-directory> \
  --output output/home-assistant/s2/camera-evidence.json
```

첫 명령은 카메라를 열며, 이미 스트리밍 중이면 동시에 실행하지 않는다. 둘째 명령은
저장 파일만 읽는다. device serial은 출력에서 해시로 바꾸고, intrinsics·depth scale·
Depth→Color 변환과 스트림 설정을 각각 지문으로 만든다. 해시는 프레임 시각과 무관하게
유지되며 장치/보정/설정 변화는 식별된다. SDK 회전 배열은 column-major로 해석한다.
`camera_device` 3개 식별값은 S2 입력 계약과 같다. `factory_calibration_sha256`은
SDK가 보고한 보정값 묶음의 해시이며 EEPROM 전체를 읽었다는 뜻은 아니다.

RGB·원본 깊이·정렬 깊이·metadata 파일 해시를 남기되 이미지 품질이나 실측 정확도를
자동 승인하지 않는다. 예전 기록에 활성 스트림 형식/FPS가 없으면 새 촬영이 필요하다.
이 결과는 외부 보정이나 로봇 시계 동기화도 아니므로 `s2_complete`와
`coordinate_use_allowed`는 false다. 다음 외부 보정에서는 독립된 베이스 기준점을 쓴다.
`audit`는 이 순서와 양팔 Home 보류 상태를 함께 출력한다. 기록된 촬영 결과를 표시하며
현재 장치 연결 상태를 새로 검사하지 않는다.

2026-11-05 Jetson에서 D415 USB 3.2 / 펌웨어 5.17.0.10을 확인했다.
카메라 전용 두 파일을 관리 배포 `s2-camera-cd98b17216f6`에 설치하고, RGB 640×480 /
원본 깊이 1280×720, 각 30fps 설정으로 90프레임을 읽었다. 관측 속도는 약 29.09fps,
최종 정렬 깊이 유효 비율은 90.35%였다. 프레임 번호 누락은 스트림별 2회, 반복은 0회로
기록됐다. 짧은 캡처이므로 장시간 안정성이나 거리 정확도 검증 결과로 해석하지 않는다.

`config/home_assistant/camera_device.observed.json`에 장치 식별 해시·SDK 보정값·
원본 파일 해시·화면 검토 결과를 보존했다. 실제 Depth→Color X 이동은 약 14.78mm로
SDK에서 읽었으며, 이것은 카메라→베이스 장착 변환이 아니다. 원본 영상과 장치 일련번호가
있는 metadata는 Git에서 제외된 `output/home-assistant/s2/camera/`에 두었다.
Jetson에는 `robot/shared/diagnostics/s2/camera/20261105T044231_337093Z`에 보관했다.

화면에서 계산기·컵·마커와 작업대가 보이며 컵 윗부분은 잘려 있다. 왼쪽 작업대 모서리와
일부 물체 경계에 깊이 누락이 있다. 현재 화면에는 독립적으로 위치를 아는 베이스 기준점이
없어 외부 보정을 수락할 수 없다. **다음 단계는 독립 베이스 기준점 확보와 외부 보정**이며,
양팔 Home 보류, 로봇 시각 동기화·리프트 원점 검증 미완료 상태는 유지한다.
이번 촬영에서는 모터 명령·STM32 변경을 하지 않았다.

후속 간이 비교(2026-11-05): 사용자가 체커보드 한 칸 25×25mm, 상판 높이 80.1cm를
제공했다. 최신 RGB에서 내부 모서리 8×5개를 검출했다. 사용자는 정밀 보정보다
대략적인 차이 확인을 요청했고, A/B의 앞쪽 거리 약 47cm, 좌우 위치는 로봇 기준
A 왼쪽 12.5cm / B 오른쪽 5cm로 보고했다. 거리 시작점은 처음 안내한 밑판 정면
끝이 아니라 **메인 기둥 또는 베이스 중심 부근**으로 정정됐다. 정확한 기준점 오프셋은 모른다.
명목 `base_link` 기준 계산은 앞 약 43cm, A 왼쪽 약 11.0cm / B 오른쪽 약 6.5cm다.
차이는 앞 약 4cm(47cm 대비 약 8%), 좌우 약 1.5cm이며 기준점·수작업 측정·장착
모델 오차를 포함한다. 이를 센서 자체 오차나 집기 정확도로 해석하지 않는다.
간이 확인 결과만 설치 기록에 연결했고 카메라 변환값은 변경하지 않았다. 정밀
외부 보정·독립 확인점 수락 및 S2 완료 상태는 여전히 미완료다.

사용자는 이 간이 비교 후 **기존 명목 카메라 모델을 유지하고 다음 단계로 진행**하기로

### 상승·하강 및 자동 높이 검사로 전환 (2026-11-05)

사용자가 수동으로 들어 올리거나 키보드로 점검하는 대신, 에이전트가 상승시키고

### live 입력 계약

`observe --profile acceptance.json --snapshot snapshot.json --now-s <공통시계현재값>
--output coordinates.json`은 동기화된 상태 한 묶음의 좌표를 검사·계산한다.
`snapshot.json`에는 다음 필드가 필요하다.

- 승인 프로필과 동일한 `calibration_id`, `assembly_revision`, `camera_device`, `source_frame`
- 현재 `session_id`, `origin_id`, 공통 `clock_id`
- `camera_time_s`, `joints_time_s`, `lift_time_s`: 처리 완료시각이 아닌 **샘플 획득시각**
- `camera_xyz_m`: RGB 정렬 깊이에서 얻은 optical 표면점
- `lift_raw_unwrapped`, `raw.left` 및 `raw.right`: 연속값과 이름 기반 6축
  (`base`, `shoulder`, `elbow`, `wrist_flex`, `wrist_roll`, `gripper`)

반환값은 베이스 표면점, 양팔 TCP 변환, 모델 기준 관절값이다. 런타임 API
`observe_report(..., report, stamp=..., context=..., now_s=...)`는 기존 DINO/SAM
`report_entities` 경계와 연결하며 `capture_id`도 일치해야 한다. 이 경로는 스냅샷의
실제 수신시각 `received_s`에 관절/깊이가 신선했는지 검사한다. DINO/SAM 추론 지연은
별도로 최대 5초 허용하되, 결과의 `coordinate_mode=capture_time`과 원래 촬영시각을
유지한다. 반환하는 TCP도 그때의 자세이며 지금의 팔 위치로 간주하지 않는다.
깊이 없는 검출은 좌표를 만들어내지 않는다. 5초를 넘긴 결과나 녹화 분석은 현재 관측
경계에서 거부하고, 시각을 갱신해 새 프레임인 것처럼 사용하지 않는다.

### 재시작 후 원점 연결

리프트 위치를 잃었다면 수동으로 최저 기준점에 맞춰 확인한다. 자동 원점 복귀 구동은
이 도구의 역할이 아니다. 새 기준 증거로 다음 필드를 기록한다.

```json
{
  "previous_calibration_id": "이전 승인 ID",
  "assembly_revision": "같은 조립 버전",
  "provenance": "measured",
  "operator": "확인자",
  "platform_height_m": null,
  "origin_raw_unwrapped": null,
  "session_id": "새 세션 ID",
  "origin_id": "새 원점 ID"
}
```

```bash
python3 tools/diagnostics/s2_coordinates.py rebind-origin \
  --profile output/home-assistant/s2/acceptance.json \
  --evidence output/home-assistant/s2/new-origin.json \
  --output output/home-assistant/s2/rebound-profile.json
```

같은 조립 상태와 최저 높이가 확인되면 팔/카메라 변환은 보존하고 원점과 보정 ID를
갱신한다. 이전 ID의 관측은 거부한다. 부품·Home·장착 변경은 이 절차로 덮지 않고 재보정한다.

## 완료 판정과 남겨둔 범위

**실측 입력, 독립 오차 검사, 라이브 시간/장치/원점 연결 확인이 모두 맞아야 S2를 닫는다.**
현재 확인되지 않은 값을 공식 규격이라고 채우거나 소프트웨어 테스트 통과를 실물 통과로
표시하지 않는다. 현장에서는 위 순서의 자료와 통합 조회를 확인하고 수락 보고서를 보관한다.
새 좌표계나 수락 기준을 그때 즉석에서 설계할 필요가 없도록 입력·판정·출력을 준비했다.

테스트는 공식 소스 일치, 독립 URDF 순기구학 비교, 양팔 부호/영점 오류, 위치/방향 확인점
실패, 카메라+팔 교차 오차, 리프트 고정 카메라 분리, 재시작 무효화, DINO/SAM 관측 경계와
CLI 출력 보존을 포함한다. 전부 합성/오프라인 검사이며 실제 장치 명령은 보내지 않는다.

2026-11-05 검증: S2/카메라 관련 **68개 통과**. 전체 Python 검사는 1,673개 통과,
2개 건너뜀, 로컬 HTTP 소켓을 샌드박스가 차단한 3개 실패였다. 해당 3개를 소켓 사용이
가능한 환경에서 다시 실행하여 모두 통과했다(합계 **1,676개 통과 / 2개 건너뜀**).
이후 DINO/SAM 촬영시각 보존 보완도 관련 68개로 재검사했다.

LDS-01 설치/지도 좌표 연결은 S4 주행에서 진행한다. 손에 든 D415 방 스캔은 지도 인지
자료 수집이며, 최종 고정한 카메라 외부 보정을 대신하거나 S2의 필수 선행이 되지 않는다.
S1 공통 구동·반복 동작의 미완료 항목은 별도로 유지한다.

**S1-LIFT-NOISE**는 사용자 결정대로 최종 실물 이슈에 남긴다. 하강 소음의 원인이나
무해함은 아직 확정하지 않았다. 이번 작업에서 이를 해결됨으로 표시하거나 구동 범위를
늘리지 않았다.

## 좌표 시각화로 검토하기

`tools/diagnostics/s2_visualize.py`는 같은 공식 기구 모델을 사용한 읽기 전용 좌표
그림을 생성한다. 공식 STL 부품 형상, 입체 회전·팔 확대·정면/측면/평면 보기, 리프트·관절 각도 조절, 카메라 표면점과
베이스 좌표 비교, 선택한 기준축의 성분 확인을 지원한다. 모터 명령이나 네트워크 통신은 없다.

```bash
# 실측 전: 장착·카메라는 명확히 표시된 예시 배치. 공식 팔 내부 형상만 확정값.
python3 tools/diagnostics/s2_visualize.py \
  --output output/home-assistant/s2/coordinate-illustration.html

# 실측 수락 후: 검증된 장착/카메라/현재 Home 대응을 그대로 표시.
python3 tools/diagnostics/s2_visualize.py \
  --profile output/home-assistant/s2/acceptance.json \
  --output output/home-assistant/s2/coordinate-measured.html
```

HTML은 대화 내 시각화용 조각이다. 공식 SO101 STL의 모터·링크·집게 형상과 Mini 1
베이스/기둥/상판 CAD를 경량화해 표시한다. 카메라 케이스는 공식 D415 STL이며 센서 좌표는 공식 명목 Xacro를 따른다. 베이스 외형의
미보정 보기의 상판은 공식 vertical_move 원점·축·계산 접촉점을 따르며 팔 중심으로 옮기지 않는다. 실물 설치 보정값은 아니다. 팔은 공식
visual origin과 FK를 그대로 따른다. 원본 내부 기구 정보는 Python과 브라우저에서
교차 검사한다. 프로필을 바꾸면 재생성하며, 해시가 틀리거나 수락되지 않은 프로필은 거부한다.
합성 프로필은 실물 검증으로 표시하지 않는다.

`--snapshot <파일>`을 함께 주면 당시 모터값·리프트·카메라 점을 표시한다. 스냅샷에는
`received_s`도 있어야 하며 기존 시각/장치/원점 검사를 적용한다. 과거 촬영시각의 상태로
표시하고 실시간 현재 자세로 가장하지 않는다. 프로필만 있으면 2048에 해당하는 모델 자세,
프로필도 없으면 공식 모델의 0° 자세로 시작한다. 슬라이더를 조절한 뒤에는 수동 미리보기다.

검토 순서: 베이스 X 앞/Y 왼쪽/Z 위 → 카메라 optical 축 → 양팔 장착 좌우 → TCP 축.
리프트를 바꿔 카메라의 베이스 좌표가 유지되는지 보고, 관절을 하나씩 바꿔 해당 팔의
변화를 확인한다. 그림의 각도 슬라이더는 공식 모델 참조 범위이며 실물 운용 허용 범위가
아니다. 집게 개구가 변해도 고정 `gripper_frame_link` TCP가 움직이지 않는 것은 의도된 동작이다.

시각화 추가 검증: JS/Python 양팔 FK·리프트 높이·카메라 점 변환 일치, 고정 TCP와
움직이는 턱 분리, 실측/합성/예시 표시, 기록된 촬영시각과 변경 프로필 거부를 검사했다.
