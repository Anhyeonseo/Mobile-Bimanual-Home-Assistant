# 카메라 + 팔 동시 보정 촬영 가이드 (현장용)

대상: 로봇 앞에서 촬영하는 사람 · 작성: 여은 · 브랜치 `yeoeun/extrinsic-calibration`

이번 촬영은 두 번에 나눠서 한다. **1차는 팔을 손으로 움직여 "다녀도 되는 길"을 기록**하고(로봇은 안 움직인다),
**2차는 로봇이 그 길로만 움직이며 스스로 사진을 찍는다.** 1차와 2차 사이에 여은이 PC에서 투어 계획을 만든다.

| | 로봇이 움직이나 | 시간 | 결과 |
|---|---|---|---|
| 1차: 손으로 훑기 | 아니오 (토크 꺼짐) | 약 1시간 | `sweep.jsonl` 6개 + 사진 |
| (여은) 계획 | – | 수십 분 | `tour.json` |
| 2차: 자동 촬영 | **예** | 약 1시간 | 사진 약 40~90장 |

---

## 1. 왜 이렇게 찍나 (3줄 요약)

1. 11/13 데이터로는 "카메라 위치가 틀렸다"와 "팔 관절 0점이 틀렸다"가 사진상 똑같이 보여서 구분이 안 됐다.
   둘은 **팔 자세가 다양해야** 구분된다. 어떤 자세가 좋은지는 PC에서 계산해서 고른다.
2. 고른 자세는 손으로 정확히 맞출 수 없으니 **로봇이 직접 간다.**
3. 저장소에 로봇 몸체 충돌 모델이 없으니, **사람이 먼저 손으로 다녀 본 공간 안에서만** 로봇이 움직이게 한다.
   1차에서 손으로 훑은 범위가 곧 2차에서 로봇이 갈 수 있는 범위다.

배경은 [인계 문서](EXTRINSIC_CALIBRATION_HANDOFF.md) 7장, 도구 설명은
[`tools/diagnostics/extrinsic_capture/README.md`](../tools/diagnostics/extrinsic_capture/README.md)의 "자동 촬영 투어".

## 2. 가기 전 준비

### 챙길 것

- [ ] ArUco 마커 2장: [`extrinsic_calibration_markers_A4.pdf`](extrinsic_calibration_markers_A4.pdf)의 `id 4 / 70 mm`. 배율 100%로 인쇄한다
- [ ] 검은 네모 네 변을 자로 잰 값. 70.0mm에서 0.5mm 넘게 다르면 다시 인쇄한다
- [ ] **단단한 판 2장** (폼보드나 아크릴, 약 10×10cm). 마커를 판에 붙여서 쓴다. 11/13에는 마커가 휘거나 떨어졌다
- [ ] 양면테이프, **박스테이프**
- [ ] 아래 7장의 기록표

### 마커 붙이기 (팔마다 한 번)

1. 마커를 판에 양면테이프로 평평하게 붙인다.
2. 판을 집게의 **움직이지 않는 쪽 손가락**에 붙이고 박스테이프로 두 번 이상 감는다. 검은 네모와 흰 테두리는 가리지 않는다.
3. 판을 손가락으로 툭 쳐도 흔들리지 않아야 한다.
4. 부착 이름을 정한다. 왼팔 `TL1`, 오른팔 `TR1`이다. **다시 붙이면 번호를 올린다**(`TL2` …). 기록표에 적는다.
5. 붙인 모습을 휴대폰으로 2장씩 찍는다.

**1차와 2차 사이에 마커를 떼지 않는 것이 가장 좋다.** 떼야 하면 2차에서 새 이름(`TL2`)을 쓴다.

## 3. Jetson 준비 (1차·2차 공통)

1. **노트북의 저장소에서** 최신 브랜치를 받는다.

   ```bash
   git fetch && git checkout yeoeun/extrinsic-calibration && git pull
   ```

2. 오늘 날짜로 새 폴더를 만들고 도구를 복사한다(노트북에서).

   ```bash
   CAL=cal_YYYYMMDD          # 예: cal_20261121
   ssh hyper@<jetson> "mkdir -p ~/$CAL"
   scp tools/diagnostics/extrinsic_capture/{*.py,helpers.sh} hyper@<jetson>:~/$CAL/
   ```

3. Jetson에서 `~/$CAL/helpers.sh`의 **두 줄을 고친다.**
   - `CAL=~/cal_20261113` → `CAL=~/cal_YYYYMMDD`
   - `cd /home/hyper/robot/releases/s3-stationary-9d2fd662e718` → 지금 쓰는 release 폴더.
     도구가 이 폴더의 `tools/run/stationary_pick.py`를 불러 쓰고, 펌웨어 식별(0x24911)도 거기서 확인한다.

4. 불러온다.

   ```bash
   source ~/cal_YYYYMMDD/helpers.sh      # ready: ... 가 나오면 된다
   pose                                  # 관절이 모두 범위 안인지 확인 (읽기만 함)
   ```

### 휴식 자세 정하기 (중요)

양팔을 접어 둔 **휴식 자세**가 1차의 시작·끝이자 2차의 출발점이다.

- `pose`를 쳤을 때 **모든 관절이 `OK`이고 margin이 2° 이상**이어야 한다.
- 11/13의 왼팔 휴식 자세는 어깨(831 < 833)와 팔꿈치(3076 > 3035)가 **범위 밖**이었다. 그 자세로는 2차가 시작되지 않는다.
  조금 덜 접어서 `OK`가 나오는 자세를 찾는다.
- 휴식 자세 사진을 휴대폰으로 찍어 둔다. 2차에서 같은 자세(5° 이내)로 놓아야 한다.

### 카메라를 건드렸으면

카메라나 더듬이 받침이 11/13 이후 **조금이라도 움직였으면** 바닥·탁자 사진을 다시 찍는다
([기존 가이드](EXTRINSIC_CALIBRATION_GUIDE.md) 5장 2단계, `camshot F-1` … `camshot TF-3`). 안 건드렸으면 필요 없다.

## 4. 1차: 손으로 훑기 (로봇은 안 움직인다)

리프트 높이 3개 × 팔 2개 = **6번** 기록한다. 한 번에 3~5분.

| 순서 | 리프트 | 훑는 팔 | 명령 |
|---|---|---|---|
| 1 | 0.20 | 왼팔 | `sweep SW20-L left 0.20 --camera --attachment TL1` |
| 2 | 0.20 | 오른팔 | `sweep SW20-R right 0.20 --camera --attachment TR1` |
| 3 | 0.35 | 왼팔 | `sweep SW35-L left 0.35 --camera --attachment TL1` |
| 4 | 0.35 | 오른팔 | `sweep SW35-R right 0.35 --camera --attachment TR1` |
| 5 | 0.50 | 왼팔 | `sweep SW50-L left 0.50 --camera --attachment TL1` |
| 6 | 0.50 | 오른팔 | `sweep SW50-R right 0.50 --camera --attachment TR1` |

- 리프트 값은 **정확히 0.20 / 0.35 / 0.50**이어야 한다. 계획 도구가 이 세 값만 받는다.
  리프트는 평소처럼 옮기고 실제 엔코더 값을 기록표에 적는다.
- 양팔 토크는 꺼져 있어야 한다. 켜져 있으면 도구가 거부한다.

### 한 번 훑는 방법

1. 양팔을 **휴식 자세**에 둔다. 명령을 친다. `logging ...`이 나오면 시작이다.
2. 훑는 팔을 휴식 자세에서 천천히 꺼낸다. **손 한 뼘을 2초쯤에 움직이는 속도**로 움직인다.
3. 아래를 모두 지나간다. 순서는 상관없다.
   - **아래 관절**: 카메라 앞에서 쓸 수 있는 범위의 왼쪽 끝 ↔ 오른쪽 끝
   - **멀리 ↔ 가까이**: 팔을 쭉 뻗은 곳과 몸 가까이 접은 곳
   - **높이 ↔ 낮게**: 카메라 화면 위쪽과 아래쪽
   - **손목 굽힘**: 위로 ↔ 아래로 끝까지(무리 없는 데까지)
   - **손목 회전**: 마커가 카메라를 보는 방향 기준 좌우로 크게
4. **가끔 1초씩 멈춘다.** 멈추면 사진이 저장된다(`photos` 숫자가 오른다). 마커가 카메라를 향할 때 멈추면 좋다.
5. 다 훑었으면 **휴식 자세로 돌아온 뒤** Ctrl+C로 끝낸다.

### 꼭 지킬 것

- **훑은 곳은 전부 "로봇이 가도 되는 곳"이 된다.** 몸체·카메라 받침·다른 팔에 거의 닿을 듯한 곳은 지나가지 않는다.
  손으로는 괜찮아도 로봇이 같은 곳을 같은 속도로 지나간다.
- **다른 팔은 휴식 자세에서 움직이지 않는다.**
- 화면의 `range margin`이 **`WARN`(5° 이하)이면 그 방향으로 더 가지 않는다.**
  범위 밖으로 나가면 제어기가 잠긴다(토크는 이미 꺼져 있어 위험하지는 않지만 STM32 리셋이 필요하다).
- 탁자·의자·상자 등 **주변 물건 배치를 기록표에 적고 사진을 찍는다.** 2차 때 똑같아야 한다. 가능하면 치운다.

### 끝나면

```bash
# 노트북에서 받아서 여은에게 전달 (사람이 찍힌 사진은 저장소에 올리지 않는다)
scp -r hyper@<jetson>:~/cal_YYYYMMDD ~/
```

## 5. (여은) 투어 계획

여은이 PC에서 계획을 만든다. 끝나면 `tour.json`과 함께 아래 숫자를 알려 준다.
리프트 높이별 촬영 장수와 이동 시간, 그리고 계획 파일의 sha256 앞 12자리다.

```bash
A=tools/diagnostics/extrinsic_capture/analysis
python3 $A/joint_calib.py . ~/cal_20261113 calib.json
python3 $A/plan_tour.py . ~/cal_20261113 calib.json tour.json \
    --sweeps ~/cal_YYYYMMDD/SW20-L ~/cal_YYYYMMDD/SW20-R ~/cal_YYYYMMDD/SW35-L \
             ~/cal_YYYYMMDD/SW35-R ~/cal_YYYYMMDD/SW50-L ~/cal_YYYYMMDD/SW50-R
scp tour.json hyper@<jetson>:~/cal_YYYYMMDD/
```

## 6. 2차: 자동 촬영 (로봇이 움직인다)

### 6-0. 실행 전 코드 검토 (처음 한 번)

`calib_tour.py`는 `stationary_pick.py run`과 같은 `StationaryPickAdapter` / `ResidentStop` 경로를 쓴다.
**처음 실제로 돌리기 전에 이동 코드 담당자가 아래를 확인한다.**

- [ ] `OperationalLimits(..., hardware_authorized=True)`와 `motion_authorized=True` 생성이 `stationary_pick.run`과 같은 조건인가
- [ ] `activate_stationary_hold()` → `start(finite=True)` → `poll()` 반복 순서와 owner 사용이 맞는가
- [ ] 프롬프트 대기 중 `keepalive()`가 0.1초 간격으로 계속 불리는가 (`wait_key`, `hold`)
- [ ] Ctrl+C / 예외 → `ResidentStop.request` → `STOPPED` 확인 흐름이 `run()`의 `finally`와 같은가
- [ ] 투어 궤적: 최대 관절 속도 20°/s, 40ms 간격, 다른 팔과 양쪽 집게는 휴식 값 고정. 계획 단계에서 어댑터의 `_validate_finite_plan_points`(범위, 틱당 이동량, 엔코더 경계)를 이미 통과했다

### 6-1. 리허설 (로봇 안 움직임)

같은 `tour.json`으로 가짜 제어기 실행을 먼저 한다. `source helpers.sh` 뒤라면 이미 release 폴더 안이다.
가짜 제어기는 실제 시간대로 움직이므로 `--max-steps 6`으로 앞부분만 돌린다.

```bash
tour ~/cal_YYYYMMDD/tour.json rehearsal20 0.20 TL1 TR1 --simulate --max-steps 6
```

`COMPLETED`와 `토크 꺼짐 확인`이 나오면 된다.

### 6-2. 실제 실행 (리프트 높이마다)

**시작 전 확인**

- [ ] 리프트가 1차와 **같은 높이**(0.20 / 0.35 / 0.50)인가
- [ ] 주변 물건 배치가 1차와 같은가
- [ ] 양팔이 휴식 자세인가(1차 사진과 비교, 5° 이내). 아니면 도구가 시작을 거부한다
- [ ] 마커가 1차와 같은 부착인가(떼었으면 새 이름)
- [ ] **한 사람은 팔 옆에서 손을 뻗을 수 있게 대기**하고, 한 사람은 키보드를 잡는다

**실행**

```bash
tour ~/cal_YYYYMMDD/tour.json T20 0.20 TL1 TR1       # 높이 0.20
```

| 화면 | 할 일 |
|---|---|
| `준비됐으면 yes 입력` | 위 확인이 끝났으면 `yes` |
| `Enter = 양팔 토크 켜고 휴식 자세 유지 시작` | Enter. 양팔에 토크가 들어가고 휴식 자세로 살짝 맞춘다 |
| `다음: left → T20-L-03 (6.2s)` | 경로에 사람·물건이 없는지 보고 Enter |
| `saved T20-L-03 ...` | 사진 저장. 다음 이동으로 넘어간다 |
| 몇 번 지켜보고 괜찮으면 | `a` 입력: 이후 이동은 자동 |
| 끝내고 싶을 때 | `q`: 미리 확인된 길로 휴식 자세까지 돌아간다 |
| `휴식 자세 도착. 양팔을 손으로 받친 뒤 Enter = 토크 끄기` | **양팔을 손으로 받친 다음** Enter |

- **위험하면 바로 Ctrl+C.** 즉시 토크가 꺼지고 **팔이 떨어진다.** 그래서 한 사람은 항상 받칠 수 있는 위치에 있는다.
- 리프트 높이 3개를 각각 같은 방식으로 실행한다(`T20` / `T35` / `T50`).
- 자세 몇 개는 일부러 2~3번 다시 간다(`-r1`, `-r2`). 같은 자세를 다른 방향에서 다가갔을 때 얼마나 차이 나는지(반복성, 유격) 재는 것이다.

### 끝나면

`~/cal_YYYYMMDD/T20`, `T35`, `T50` 폴더(각각 `tour_run.json` 포함)를 1차와 같은 방법으로 여은에게 보낸다.

## 8. 문제가 생기면

| 나오는 말 | 뜻 | 할 일 |
|---|---|---|
| `torque is on` / `torque-off mismatch` | 토크가 켜진 팔이 있다 | 1차는 토크를 끄고 다시 실행 |
| `current arm pose outside recorded range` | 관절이 범위 밖이다 | `pose`로 확인하고 범위 안으로 옮긴다 |
| `stationary controller identity/state mismatch` | 펌웨어 또는 release 폴더가 다르다 | `helpers.sh`의 release 폴더와 펌웨어를 확인 |
| 1차 중 기록이 갑자기 멈춤 | 범위 밖으로 나가 제어기가 잠겼다 | STM32 리셋 후 그 기록만 새 이름으로 다시 |
| `arm_ranges.development.json differs` | 계획 때와 범위 파일이 다르다 | 여은에게 알려 다시 계획 |
| `arms are N deg away from the tour rest pose` | 휴식 자세가 다르다 | 1차 사진처럼 손으로 놓고 다시 |
| `팔이 멈추지 않아 건너뜀` | 촬영 순간 팔이 떨렸다 | 그냥 진행. 많으면 여은에게 알림 |
| `move did not finish in time` / `terminal settle error` | 목표에 도달하지 못했다(걸림, 과부하) | 자동 정지됨. 팔을 받치고 원인 확인 후 여은에게 알림 |
| `정지 미확인` | 정지가 확인되지 않았다 | **양팔·리프트를 받치고 모터 전원을 끈다** |

## 9. 하면 안 되는 것

- 1차에서 몸체·카메라 받침에 닿을 듯한 곳을 훑지 않는다.
- 2차에서 리프트 높이나 주변 배치를 1차와 다르게 하지 않는다.
- 2차 중 팔 옆을 비우지 않는다. `--auto`를 처음부터 쓰지 않는다.
- 사람이 찍힌 사진을 저장소에 올리지 않는다.
