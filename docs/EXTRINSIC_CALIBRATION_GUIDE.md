## 1. 무엇을 하는가

**로봇 손에 마커를 붙이고, 손을 여기저기 옮기면서 사진을 찍는다.**
그 사진으로 "카메라가 로봇에 실제로 어떻게 붙어 있는지"를 컴퓨터가 계산한다.

지금은 이 값을 측정하지 않고 설계도 값(45°로 붙였다고 가정)을 쓴다. 탁자 높이 한 번만 자로 재서 9.1mm를 고쳤다.
그래서 카메라가 실제로 얼마나 틀어져 있는지 아무도 모른다.

## 2. 원리

**① 두 가지 답을 비교한다.**
로봇은 손 위치를 두 방법으로 안다.

- 카메라로 보고: "마커가 저기 있다"
- 모터 각도로 계산해서: "팔을 이만큼 폈으니 손은 여기 있다"

카메라가 정확히 붙어 있으면 두 답이 같다. 삐뚤면 다르다.
사진이 여러 장 있으면 컴퓨터가 "카메라가 이만큼 삐뚤어져 있어야 두 답이 모두 맞는다"를 찾아 준다.

**② 마커는 크기를 아는 네모다.**
크게 찍히면 가깝고 작게 찍히면 멀다. 찌그러진 모양으로 기울기도 안다. 그래서 사진 한 장으로 마커 위치를 계산한다.
크기를 틀리게 알면 거리도 틀린다. 그래서 출력한 마커를 자로 잰다.

**③ 다양하게 찍어야 한다.** 비슷한 사진만 있으면 컴퓨터가 원인을 가려낼 수 없다.

| 이렇게 찍는다 | 이유 |
|---|---|
| 많이 | 한 장마다 조금씩 흔들린다. 평균을 내면 정확해진다 |
| 손 위치를 넓게 | 가까운 두 점으로 선을 그으면 방향이 부정확하다. 멀리 떨어진 두 점이면 정확하다 |
| 손 높이도 바꿔서 | 같은 높이만 있으면 위아래 정보가 없다 |
| 손목을 돌려서 | 안 돌리면 "마커가 손 옆에 붙은 것"과 "카메라가 옆으로 치우친 것"을 구분할 수 없다 |
| 리프트 높이를 바꿔서 | 안 바꾸면 "리프트 계산이 틀린 것"과 "카메라 높이가 틀린 것"을 구분할 수 없다 |

**④ 시험용 사진은 따로 찍는다.**
계산에 쓴 사진으로 채점하면 연습 문제로 시험 보는 것과 같다. 안 쓴 사진으로 재야 진짜 점수다.

**⑤ 팔 없이 바닥과 탁자도 찍는다.**
팔 자체가 틀렸을 수도 있다. 바닥은 평평하고 높이가 0이라, 팔 없이 카메라의 각도와 높이만 따로 확인할 수 있다.

**⑥ 체커보드도 찍는다.**
칸 크기를 아니까, 카메라의 거리 측정 자체가 정확한지 볼 수 있다.

## 3-2. 로봇에 연결하기 (SSH)

### 구조

로봇 안에 **Jetson**이라는 작은 컴퓨터가 있다. 카메라와 모터 제어기가 모두 Jetson에 꽂혀 있다.
그래서 촬영 명령은 **Jetson에서** 실행한다. 내 노트북은 SSH로 Jetson에 들어가 명령을 치는 창 역할만 한다.

```
내 노트북 ──(와이파이, SSH)──> Jetson ──USB──> 카메라
                                      └──USB──> 모터 제어기(STM32) ──> 팔, 리프트
```

### 팀원에게 받아야 하는 것

| 필요한 것 | 저장소 기록 (오늘은 다를 수 있음) | 오늘 값 |
|---|---|---|
| Jetson 사용자 이름 | `hyper` | |
| Jetson IP 주소 | `192.168.35.2` | |
| 비밀번호 또는 SSH 키 | 기록 없음 | |
| 와이파이 이름과 비밀번호 | 기록 없음 | |
| **실행 폴더** | `/home/hyper/robot/releases/s3-stationary-…` (아래 "실행 폴더 찾기") | |
| **파이썬 실행 파일** | `/home/hyper/robot/shared/venvs/room-scan-bag/bin/python` | |

IP는 Jetson에서 `hostname -I`를 치면 나온다.

### 연결 순서

1. 노트북을 **Jetson과 같은 와이파이**에 연결한다.
2. 노트북 터미널에서 Jetson이 보이는지 확인한다. 응답이 오면 Ctrl+C로 멈춘다.

   ```bash
   ping 192.168.35.2
   ```

3. 접속한다.

   ```bash
   ssh hyper@192.168.35.2
   ```

4. 처음이면 `Are you sure you want to continue connecting?`이 나온다. `yes`를 치고 Enter.
5. 비밀번호를 친다. 화면에 글자가 안 보이는 것이 정상이다.
6. 프롬프트가 `hyper@...`로 바뀌면 Jetson 안에 들어온 것이다.

### 연결한 뒤 준비 (Jetson 터미널에서)

1. 실행 폴더를 찾아 들어간다. 이름이 `s3-stationary-`로 시작하는 폴더 중 **가장 최근 것**이 후보다.

   ```bash
   ls -dt /home/hyper/robot/releases/s3-stationary-*
   readlink -f /home/hyper/robot/stationary-pick
   ```

   첫 줄은 최근 순 목록이고, 둘째 줄은 팀이 "현재 버전"으로 걸어 둔 폴더다.
   둘이 같으면 그 폴더로 간다. 다르면 팀원에게 묻는다.

   ```bash
   cd /home/hyper/robot/releases/s3-stationary-<목록에 나온 이름>
   ```

   이 폴더가 맞는지는 3번 연결 검사가 알려 준다.

2. 저장 폴더를 만든다.

   ```bash
   mkdir -p ~/cal_20261113
   ```

3. **연결 검사**를 한다. 읽기만 하고 모터를 움직이지 않는 명령이다.

   ```bash
   <파이썬> tools/run/stationary_pick.py check --output ~/cal_20261113/check.json
   ```

   `READ_ONLY_CONNECTION_CHECK_PASSED`가 나오면 카메라와 제어기가 연결된 것이다.
   `REJECTED`가 나오면 `reason`을 팀원에게 보여 준다.

4. 매번 긴 명령을 치지 않도록 짧은 명령 `shot`을 만든다. `<파이썬>` 자리에 위 표의 파이썬 실행 파일 경로를 넣는다.

   ```bash
   shot() { <파이썬> tools/run/stationary_pick.py capture --fixed-lift-m "$2" --output ~/cal_20261113/"$1".json; }
   ```

5. 이제 한 장은 이렇게 찍는다. 앞은 기록표의 이름, 뒤는 리프트 값이다.

   ```bash
   shot L1-01 0.20
   ```

   `stationary_capture_verified`가 나오면 성공이다.

`shot`은 그 터미널 창에서만 기억된다. SSH가 끊겨 다시 접속했으면 1번과 4번을 다시 한다.

### 꼭 확인할 것: 실행 폴더와 제어기가 맞는가

저장소의 마지막 기록(11월 9일)에는 이렇게 적혀 있다.

- 제어기에 **시연 전용 프로그램**이 설치되어 있다.
- `/home/hyper/robot/stationary-pick` 폴더는 설치된 제어기와 맞지 않으니 그대로 실행하지 말라고 되어 있다.
- 모터가 켜진 채 자세를 유지하고 있을 수 있다. 임의로 끄거나 리셋하지 않는다.

그 뒤로 바뀌었을 수 있다. **어느 폴더에서 실행해야 하는지 팀원에게 꼭 묻는다.**
폴더가 제어기와 맞지 않으면 3번 연결 검사에서 `REJECTED`가 나온다.

### 실시간 화면 보기 (선택)

노트북에서 새 터미널을 열고, 저장소 폴더에서 실행한다.


- 카메라는 한 번에 한 프로그램만 쓸 수 있다. **촬영하기 전에 이 화면을 끈다**(그 터미널에서 Ctrl+C).
- 화면을 못 쓰면, 찍은 뒤 `color.png`를 노트북으로 가져와 확인한다.

### 사진을 노트북으로 가져오기 (노트북 터미널에서)

```bash
scp -r hyper@192.168.35.2:~/cal_20261113 ~/
```

가져온 뒤 저장소 폴더에서 확인한다.


### 하면 안 되는 것

- `stationary_pick.py run`이나 `--execute`가 붙은 명령을 치지 않는다. 팔과 리프트가 움직인다.
- `flash`가 들어간 스크립트를 실행하지 않는다. 제어기 프로그램이 바뀐다.
- Jetson을 `reboot`하거나 전원을 뽑지 않는다.

`check`와 `capture`는 읽기만 한다.

## 4. 도착해서 먼저 할 것

### 팀원에게 확인

1. **촬영 명령이 아래와 같은지.** 저장소 코드에서 찾은 명령이다. 실행 폴더와 파이썬 환경은 팀원이 안다.

   ```bash
   python3 tools/run/stationary_pick.py capture \
     --fixed-lift-m 0.20 \
     --output ~/cal_20261113/L1-01.json
   ```

   3-2장에서 만든 `shot`을 쓰면 `shot L1-01 0.20`과 같다.

   - `--fixed-lift-m`: 지금 리프트 높이. 최저점이 0이고 **미터 단위**다(20cm → `0.20`)
   - `--output`: 저장할 이름. 매번 다른 이름을 쓴다. 같은 이름이 있으면 실행되지 않는다
   - 결과: `L1-01.json`(모터 값, 리프트 값)과 `L1-01/` 폴더(`color.png`, `depth_aligned.png`, `metadata.json`)

2. **리프트를 원하는 높이로 옮기는 방법.** 리프트는 팀원이 조작한다.
3. **팔을 자세로 고정할 수 있는지.** 안 되면 한 사람이 손으로 받친다.
4. **실시간 카메라 화면을 볼 수 있는지.** 못 보면 찍은 `color.png`를 열어 확인한다.
5. 빨강/파랑 막대 테스트 자료와 집기 9회 기록이 남아 있는지.

### 촬영이 실패했을 때

| 나오는 말 | 뜻 | 할 일 |
|---|---|---|
| `arm moved during stationary capture` | 찍는 동안 팔이 움직였다 | 팔을 상자에 올리거나 더 단단히 받치고 다시 찍는다 |
| `no fresh synchronized stationary capture` | 사진과 모터 값의 시간이 안 맞았다 | 그대로 다시 찍는다 |
| `output already exists` | 같은 이름이 이미 있다 | 이름 끝에 `b`를 붙여 다시 찍는다 |
| `lift outside model` | 리프트 값이 범위를 벗어났다 | 미터 단위로 넣었는지 본다 |

## 5. 촬영

기록표(7장)의 번호 순서대로 찍는다. **이름 칸에 적힌 이름을 `--output`에 그대로 쓴다.**

### 0단계. 시험 촬영 (3장)

1. 4단계의 "마커 붙이기"대로 왼팔 집게에 70mm 마커를 붙인다.
2. 리프트를 +35cm로 맞춘다.
3. 손을 화면 아래쪽(가까이), 가운데, 위쪽(멀리)에 한 번씩 놓고 찍는다. 이름은 `T-1`, `T-2`, `T-3`.
4. 폴더를 노트북으로 옮겨 확인한다.

   ```bash
   python3 tools/diagnostics/check_aruco_capture.py ~/cal_20261113
   ```

| 결과 | 할 일 |
|---|---|
| 세 장 모두 `OK` | 다음 단계로 간다 |
| `TOO SMALL` | 마커가 작게 찍혔다. 손을 더 가까이에서만 찍도록 범위를 줄인다 |
| `NOT FOUND` | 마커가 카메라를 향하는지, 가려졌는지, 빛이 반사되는지 본다. 가까이에서 마커가 화면을 벗어나면 50mm로 바꾼다 |

**이 확인을 건너뛰면 나머지 사진을 전부 못 쓸 수 있다.**

### 1단계. 카메라 상태 (휴대폰 5장)

1. 카메라를 정면에서 1장.
2. 왼쪽 옆, 오른쪽 옆에서 1장씩. 카메라와 뒤의 경사면이 같이 보이게 찍는다.
3. 위에서 1장.
4. 휴대폰 경사계 앱을 켜고 휴대폰 옆면을 **카메라 윗면**에 댄다. 화면을 캡처한다.
5. 줄자로 **바닥에서 카메라 가운데 렌즈까지** 높이를 잰다.

| 항목 | 값 |
|---|---|
| 카메라 숙인 각도 (설계 45°) | ° |
| 바닥 → 렌즈 높이 (설계 약 107cm) | cm |

### 2단계. 바닥과 탁자 (9장)

리프트는 최저점(`--fixed-lift-m 0`). 양팔은 기본 자세로 두어 화면에 안 보이게 한다.

**바닥 3장 (`F-1` ~ `F-3`)**

1. 로봇을 평평한 맨바닥에 둔다. 매트나 러그 위는 안 된다.
2. 로봇 앞 50cm ~ 2m 사이의 물건을 모두 치운다.
3. 아무것도 바꾸지 않고 3번 찍는다.

**탁자 3장 (`TB-1` ~ `TB-3`)**

1. 탁자 위 물건을 모두 치운다. 유리나 반짝이는 표면이면 무광 종이나 천을 깐다.
2. 탁자를 **평소 물건을 집을 때 두는 자리**에 놓는다.
3. 줄자로 탁자 높이를 두 곳에서 잰다.
4. 3번 찍는다.

**탁자 멀리 3장 (`TF-1` ~ `TF-3`)**

1. 탁자를 로봇에서 15cm 더 멀리 민다.
2. 3번 찍는다.

| 항목 | 값 |
|---|---|
| 탁자 높이, 로봇 쪽 끝 | cm |
| 탁자 높이, 반대쪽 끝 | cm |
| 로봇 앞면 → 탁자 끝 거리 (평소 자리) | cm |

### 3단계. 체커보드 (9장)

체커보드는 **로봇에 붙이지 않는다.** 평평한 곳에 눕혀 놓는다. 팔은 계속 화면 밖에 둔다.

놓는 높이를 바꿔 거리 3가지를 만든다. 높은 곳일수록 카메라와 가깝다.

| 놓는 곳 | 카메라와의 거리(어림) | 이름 |
|---|---|---|
| 탁자 위 (약 80cm) | 약 40cm | `CB-1`(왼쪽) `CB-2`(가운데) `CB-3`(오른쪽) |
| 의자 위 (약 45cm) | 약 90cm | `CB-4` `CB-5` `CB-6` |
| 바닥, 로봇 앞 약 1m | 약 150cm | `CB-7` `CB-8` `CB-9` |

놓는 법:

1. 긴 변이 좌우로 가게 놓는다.
2. 빨간 스티커 코너가 **카메라에서 가까운 왼쪽**에 오게 한다.
3. "가운데"는 보드가 화면 한가운데 오는 자리다.
4. "왼쪽"은 보드를 화면 왼쪽 끝으로 밀되 **잘리지 않는** 자리다. "오른쪽"도 같다.
5. 보드 전체와 흰 테두리가 화면에 다 보여야 한다. 조금이라도 잘리면 못 쓴다.
6. 보드가 휘거나 들뜨지 않게 한다. 위에 아무것도 올리지 않는다.
7. 탁자 위에서는 화면이 좁다. 왼쪽·가운데·오른쪽이 서로 겹쳐도 된다.
8. 바닥에서는 큰 보드(35mm 칸)가 있으면 큰 보드를 쓴다.

| 항목 | 값 |
|---|---|
| 체커보드 칸 9개 길이 ÷ 9 | mm |
| 의자 높이 | cm |

체커보드가 없으면 이 단계는 건너뛴다.

### 4단계. 왼팔 (36장) — 가장 중요

**마커 붙이기**

1. 집게의 **움직이지 않는 쪽 손가락**의 넓은 면에 양면테이프를 붙이고 마커 판을 붙인다.
2. 마스킹테이프로 판과 손가락을 함께 두 번 감는다. 검은 네모와 흰 테두리는 가리지 않는다.
3. 움직이는 손가락에 닿지 않는지 본다.
4. 손가락으로 톡 쳐서 판이 흔들리지 않는지 확인한다.
5. 붙인 모습을 휴대폰으로 2장 찍는다.

카메라는 위에서 비스듬히 내려다본다. 손목을 돌려 **마커가 위쪽을 보게** 해야 찍힌다.
마커를 붙인 정확한 위치는 재지 않아도 된다. 계산에서 같이 구한다.

**리프트 높이 3개**

| | 최저점 기준 | `--fixed-lift-m` |
|---|---|---|
| 높이 1 | +20cm | `0.20` |
| 높이 2 | +35cm | `0.35` |
| 높이 3 | +50cm | `0.50` |

그 높이에서 손이 화면에 안 들어오면 세 높이를 모두 올리거나 내린다. 서로 15cm 이상 차이 나면 된다.
바꿨으면 실제로 쓴 값을 기록표에 적는다. 탁자는 치운다. 팔 받침이 필요하면 상자를 쓴다.

**손 위치 12곳**

```
카메라 화면 기준

  위쪽 1/3 (멀리)     ①왼쪽   ②가운데   ③오른쪽
  가운데 1/3          ④왼쪽   ⑤가운데   ⑥오른쪽
  아래쪽 1/3 (가까이)  ⑦왼쪽   ⑧가운데   ⑨오른쪽

  ⑩ ⑪ ⑫  : ④ ⑤ ⑥ 자리에서 손을 10~15cm 더 든 것
```

- 왼쪽/가운데/오른쪽은 **그 팔이 닿는 범위에서** 가장 왼쪽, 중간, 가장 오른쪽이다.
- 닿지 않는 칸은 건너뛰고 기록표에 ✕를 적는다. 골고루 섞이는 것이 중요하다.

**한 장 찍는 순서**

1. 손을 기록표의 다음 칸으로 옮긴다.
2. 손목을 기록표의 "손목" 칸대로 돌린다(아래 표).
3. 마커가 카메라 쪽을 보는지, 손이나 케이블에 가려지지 않는지 본다.
4. 팔을 받치는 손은 마커 뒤나 아래에 둔다.
5. 1~2초 멈춘다.
6. 찍는다.
7. 기록표에 ✓ 한다.

| 손목 | 어떻게 |
|---|---|
| 정면 | 마커가 카메라를 똑바로 본다 |
| 왼 | 마커의 왼쪽 변이 카메라에서 멀어지게 20~30° 돌린다 |
| 오 | 마커의 오른쪽 변이 멀어지게 20~30° |
| 위 | 마커의 위쪽 변이 멀어지게 20° |
| 아래 | 마커의 아래쪽 변이 멀어지게 20° |

각도는 눈대중이면 된다. 실제 각도는 모터 값에 기록된다.

### 5단계. 왼팔 시험용 (6장)

마커를 **떼지 않고** 바로 이어서 찍는다. 뗐다 붙이면 위치가 달라져 같이 쓸 수 없다.

1. 리프트를 +27cm(`0.27`)로 옮긴다. 4단계에서 쓰지 않은 높이다.
2. 칸과 칸 **사이**에서 3장: ①과 ⑤ 사이, ⑤와 ⑨ 사이, ③과 ⑤ 사이.
3. 리프트를 +43cm(`0.43`)로 옮겨 같은 식으로 3장.
4. 이름은 `LH-1` ~ `LH-6`.

### 6단계. 반복 (8장)

같은 자세인데 값이 얼마나 다르게 나오는지 본다. 이 흔들림보다 더 정확해질 수는 없다.

1. 리프트를 +35cm로 맞춘다.
2. 상자 위에 펜으로 점을 하나 찍는다.
3. 집게 끝을 그 점에 대고 찍는다(`RP-1`).
4. 팔을 치웠다가 다시 그 점에 대고 찍는다. `RP-5`까지 반복한다.
5. 팔은 그대로 두고, 리프트를 10cm 올렸다가 다시 +35cm로 내리고 찍는다(`RP-6`). `RP-8`까지 반복한다.

### 7단계. 오른팔 (24장)

1. 왼팔에서 마커를 떼어 오른팔 집게에 같은 방법으로 붙인다. 휴대폰으로 2장 찍는다.
2. 높이 1, 2, 3에서 각각 8장: ① ③ ⑤ ⑦ ⑨ ② ⑧ ⑪.
3. 찍는 순서는 4단계와 같다.

### 8단계. 오른팔 시험용 (4장)

마커를 떼기 전에 찍는다. +27cm에서 2장, +43cm에서 2장. 칸 사이 위치. 이름은 `RH-1` ~ `RH-4`.
