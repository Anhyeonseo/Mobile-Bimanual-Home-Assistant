## 준비 경로

`S4_UNIFIED_CANDIDATE`는 보정된 S3 범위와 모바일 profile을 함께 쓰는 명시적 빌드다.
부팅 시 모터 설정, 토크, 원점, 영구 boot journal을 자동으로 쓰지 않는다.
AC 조회는 준비 티켓만 발급한다. 별도 준비 요청은 최신 티켓·지지 확인·유휴 상태를
요구하며 16개 모터를 읽어 정지와 토크 OFF를 확인한다. 필요한 모바일 모드만 쓰고
다시 읽어 보정 보존을 확인한 후 영구 boot ID와 endpoint를 등록한다.
불확실한 쓰기 결과는 같은 부팅에서 자동 재시도하지 않는다.

AL 7은 사용자가 실제 최하단임을 확인한 경우에만 현재 위치를 원점으로 등록하는
기능이다. 신선한 정지 관측과 팔/베이스 interlock을 요구하며, 이동 명령을 생성하지
않는다. 실제 zero 전송과 별도 유지 증거 전에는 `holding`으로 판정하지 않는다.
통합 빌드에서는 접촉 전류 기반 자동 homing(AL 1)을 거부한다.

profile은 `commissioning`이다. 실제 inventory와 기존 보정 파일의 해시를 묶었지만,
공유 버스 시간 예산·리프트 유지·최대 속도를 실물 검증한 `measured` profile은 아니다.
따라서 `hardware_authorized`와 `physical_test_ready`를 false로 유지한다.

### 지지 상태 속도 0 힘 켜기·해제 실물 시험

사용자가 받침 유지·현장 관찰을 확인하여 `--check-zero-power`를 한 번 실행했다.
`zero-power-01.json`에 AC 3 성공(flags 113), 15회 전체 inventory, AC 4 성공(flags 17)과
16축 토크 OFF·정지·보정 보존을 기록했다. 활성화 응답부터 해제 응답까지 3,276ms다.
비영점 속도·팔 활성화·리프트 원점/이동·제어기 재시작 명령은 보내지 않았다.

- 바퀴 7/8은 위치 3450/2100으로 일정했고, 리프트 10도 3832로 일정했다.
- 바퀴 9는 위치 2271–2272(1 count)였으며, 15번째 표본에서 speed_raw 32818
  (부호 해석 -50), moving 1이 관측돼 원본 자동 시험 결과는 FAILED로 보존했다.
- 사용자는 눈에 띄는 움직임·떨림·이상음이 없었다고 확인했다.

전체 재조회로 설정 보존·토크 OFF·정지를 확인한다. 보정·모드·위치 목표를 쓰지 않는다.
거부된 티켓은 소모하며 불명확한 쓰기를 같은 부팅에서 자동 반복하지 않는다.

호스트 `--release-boot-supported --supported-empty --baseline ...`가 기존 baseline과
모델 해시를 먼저 비교한다. 기본 조회/prepare에는 새 해제가 자동으로 붙지 않는다.
설치·재시작·해제·준비·힘 켜기·실물 시험은 각각 별도의 결과로 기록한다.
