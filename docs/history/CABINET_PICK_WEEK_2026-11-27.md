# 수납장 앞까지 주행해서 흰 지우개 집기

**이번 주(2026년 11월 23~27일)에는 SLAM 지도에서 로봇 위치를 추정하고, Nav2로 수납장에 접근한 뒤 지우개 위치에 맞춰 정렬하고 집는 흐름을 픽스테이션 시험기에 연결했다.** 수납장 앞 고정 위치에서는 지우개가 상판에서 들려 집게에 유지되는 것을 현장에서 확인했다. 주행부터 파지까지 연속으로 성공하는 것은 남은 실물 검증 항목이다.

## 구현한 흐름

1. **수납장을 찾는다.** LDS-01의 현재 스캔을 저장된 점유 지도에 정합해 차체 위치와 방향을 추정한다. Nav2로 수납장 관측점에 접근하고, 그 근처에서 연속된 라이다 반사점으로 실제 수납장 앞면을 구한다. 시험 입력은 11월 13~14일에 수집한 지도·깊이 자료다. 이번 주에 이 자료와 최신 센서를 결합해 수납장 접근 주행을 구현하고 실물에서 시험했다.
2. **베이스 앞끝 기준 6cm에 정차한다.** 리프트는 최상단에 고정한다. 정차 거리는 수납장 앞면에 수직인 방향으로 AlohaMini1 차체 외곽에서 잰다. 베이스 앞끝에는 CAD 형상을 쓰고, 이동 중 충돌 검사에는 현재 엔코더 자세의 양팔과 리프트 형상까지 포함한다. 정차 허용 범위는 4~8cm다.
3. **흰 지우개에 맞춰 정렬하고 집는다.** 바퀴가 정지하고 주차가 확인되면 RGB-D로 수납장 상판의 흰 지우개를 찾는다. 물체 위치와 실측 파지 기준점으로 베이스 후보를 만들고 팔 도달성, 그리퍼 접촉 방향과 전체 경로를 검사한다. 재정렬이 필요하면 이동 후 다시 촬영한다. 기존 캘리브레이션, GraspNet 기반 후보와 MoveIt 2 팔 경로를 사용한다. 성공 기준은 지우개가 실제로 들려 유지되는 것이다.

## 현장에서 드러난 문제와 대응

| 관찰한 문제 | 구현한 대응과 검증 상태 |
|---|---|
| 수납장을 보고도 팔이 닿기에는 먼 곳에 멈췄다. 같은 위치에서 팔 앞끝과 베이스 앞끝이 서로 다른 간격을 나타냈다. | 관측점 도착과 파지용 정차를 분리했다. 라이다로 앞면을 다시 구해 베이스 기준 거리를 확인하고, 지우개를 찾은 뒤에는 물체 좌표로 파지 위치를 고른다. |
| 저장 지도에서 베이스 기준 6cm 후보가 모두 탈락했다. 직전 기록에서는 목표 간격에 걸치는 21개 칸이 모두 막혀 있었다. | 정지한 채 접근 경로에서 차체·팔이 지나갈 높이와 겹치는 부분을 다시 본다. 라이다 높이에서는 레이 통과 여부를, 높이별 공간에서는 깊이 픽셀이 그 뒤까지 관측했는지를 본다. 서로 다른 두 센서 관측에서 확인된 경로에만 이번 요청용 지도를 적용하고, 실행할 바퀴 명령도 확인된 경로 안에 있는지 검사한다. |
| 라이다·깊이가 늦거나 속도 명령과 공간 검사 결과의 시점이 달라 바퀴 명령이 끊겼다. 바퀴 온도가 한 표본에서 급등한 경우도 있었다. | 센서 시각·검사한 속도·유효기간을 함께 전달한다. 갱신을 기다릴 때는 바퀴를 정지시킨다. 명령 유지 시간과 엔코더 변위를 함께 기록한다. 펌웨어에서는 온도 급등 시 속도를 0으로 유지하며 다시 읽고, 과열이 지속되면 정지한다. |
| 마지막 실물 시험은 정차 후보를 계산하는 동안 제어기 상태 갱신이 141ms 비어 중단됐다. | 후보 열거를 별도 프로세스로 옮겼다. 젯슨에서 같은 기록을 재생했을 때 검색에 601ms가 걸리는 동안 모사한 제어 루프의 최대 간격은 10.1ms였다. 이 수정 후 실제 제어기와 주행하는 검증이 남았다. |

## 마지막 실물 시험에서 확인한 경계

11월 27일 시험에서 라이다 95점으로 수납장 앞면을 잡았다. 베이스 앞끝 간격은 30.0cm였고, 상태 갱신 지연으로 바퀴 명령을 보내기 전에 정지했다. 이 요청에서는 지우개 탐지·좌우 정렬·파지 단계에 진입하지 않았다.

정지 후 같은 자리에서 라이다와 깊이를 두 번 짝지어 측정했다. 가장 가까운 6cm 후보에서 팔이 지날 **바닥 위 100~105cm 구간**은 두 번 모두 깊이 카메라 시야 밖이었다. 이 구간에 실제 장애물이 있다는 증거는 없고, 현재 관측만으로 비었다고 확인할 수도 없었다. 다음 실물 시험에서 확인할 항목은 이 높이의 시야 확보, 주행 중 제어기 갱신, 정차 후 실제 파지다. 통합 성공 전까지 수정본은 별도 시험기에 둔다.

브랜치 게시 전 관련 Python 회귀 테스트 395개와 STM32 호스트 테스트 17개가 통과했다. 정차 판정은 [수납장 주행](../../tools/run/cabinet_navigation.py), 센서 재검사는 [접근 경로 검사](../../tools/run/cabinet_path_review.py), 지도·차체·팔이 겹친 위치의 재생은 [정차 검토 도구](../../tools/diagnostics/review_cabinet_parking.py)에서 확인할 수 있다.
