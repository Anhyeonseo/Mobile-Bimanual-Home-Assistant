# 현재 진행 상황

기준일: **2026-11-16**. 미세 정렬과 리프트 상승·광각 정지 촬영을 실행했다. 방향 잔차는 줄었지만 라이다 XY 잔차는 수렴하지 않아 미세 정렬 성공으로 집계하지 않는다. 리프트는 현재 최하단보다 **8.059mm** 높고, 집기는 아직 실행하지 않았다. 리모컨을 옮기지 않았다는 사용자 확인 후 이전/현재 RGB-D의 탁자 무늬와 평면을 직접 연결했다. 새 좌표에서는 베이스를 앞 1.0cm·오른쪽 2.5cm 수정하는 후보의 전체 팔 경로가 계산됐으며 **새 후보는 사용자 승인을 받았지만 리프트 원점 복구 전에는 이동하지 않는다**.

## 지금 어디까지 됐나

**정지 상태 집기는 S3 수락을 받았다. 지도 생성·목적지 이동·장애물 대응·기존 가구 위치 갱신은 실제 장치에서 확인했고, 현재는 집기 좋은 베이스 자리 선정과 마지막 정렬을 보완하는 S4b 단계다. S5는 로컬 언어 모델과 작업 연결을 준비했지만 실물 전체 배달은 아직 완료하지 않았다.**

## 이번까지 바뀐 주요 동작

- **주행 연결:** 검증된 3륜 텔레옵 변환을 재사용하고 Nav2 출력과 설치 상한을 일치시켰다. 미전송 패킷 처리 때문에 STOP 전달이 막히던 경로와 시작 조회 소유권 회수를 보완했다.
- **사용성:** 주행 전 팔·리프트 유지 상태를 확인한 뒤 이동 중에는 바퀴 중심으로 조회한다. 바퀴 온도 단발 급등은 새 응답으로 확인하고, 지속 고온·응답 실패는 정지한다.
- **지도:** 오류 종료 구간의 유효 원본도 연결한다. 라이다 뒤쪽 자기 가림을 반영하고 RGB-D 상부 형상을 합친다. 주행 폭은 하단 베이스가 아니라 고정 리프트/장착대까지 포함한다.
- **가구 이동:** 같은 가구의 새 위치가 확인되면 옛 점유 기여를 교체한다. 원본 지도와 이력은 보존하며, 새 미등록 물체는 임시 장애물로 취급한다.
- **집기 자리:** 장축이 분명한 물체에는 도구 접근 방향의 수평 투영을 맞추고, 고정 손가락·관절 여유·과도한 신전을 고려한다. 최종 시야를 요구하지 않는 저장 관측 방식도 분리했다.
- **높이:** 여은 보정 결과의 높이 성분만 적용했다. 고정 16ms 노출·정지 다중 촬영에서 탁자 높이 반복성을 확인했으며 기존 -9.1mm를 중복 적용하지 않는다.
- **언어·앱:** PC 로컬 Qwen3-4B와 텍스트 작업 흐름을 연결했다. 한 물체·구체적 목적지·작업당 한 번의 실행 확인이 첫 범위다.

## 최신 결과와 재개 조건

- 미세 정렬 7회 보정 뒤 마지막 유효 관측의 방향 잔차 약 0.045°. XY는 1.18~3.27cm로 변해 `ALIGNMENT_REVIEW`로 종료했다. 이후 정지 관측 323개/64.6초의 XY P90 변동은 1.44cm다. 절대 정확도나 도착 성공의 증거로 쓰지 않는다.
- 승인된 리프트 10mm 목표를 실행해 8.059mm 도달, 종료 시 전체 정지 확인·유지 토크 보존. 광각 RGB/depth 1280×720 정지 촬영 12장 확보. 탁자 높이 ROI 중앙값 31.616cm, 프레임 범위 31.555~31.707cm이며 사용자 실측은 31.8cm다.
- 리모컨 위치·방향이 그대로라는 사용자 확인. 이전/현재 영상의 독립적인 무늬 대응점과 측정 탁자 평면을 연결하면 12장 집기점 P90 반복 변동 약 2.50mm, 최대 5.26mm다. 보이는 리모컨의 최근접 깊이 오차 중앙값은 프레임별 1.76~2.85mm. 이는 저장 형상 재연결의 기록 분석이며 실제 팔 정확도 검증이 아니다.
- 현재 자리에서는 접촉 자세는 가능하지만 수직 들기 경로가 실패했다. **앞 1.024cm·오른쪽 2.489cm, 회전 없음, 리프트 8.059mm** 후보는 공식 전체 STL·측정 탁자 평면·주변 관측 장애물로 접근/닫힘/들기/운반 자세 경로를 찾았다(1,478 상태 검사). 집게 벌림은 관측 폭 46.49mm + 여유 8mm, 닫힘 여유는 기존 5mm다. 새로운 실물 집기 성공이 아니다.
- 제어기 boot 73은 정지 잠금 상태다. 마지막 읽기에서 리프트 명령 0·fault 0·8.059mm를 확인했지만 팔 snapshot은 오래됐고 유지보수 inventory는 사용할 수 없었다. 상승 종료 당시의 전체 정지 증명을 최신으로 재사용하지 않는다. **재시작 후 올라간 리프트를 최하단으로 등록하면 안 된다.** 실제 높이를 보존/복원할 재개 경로와 새 관절값이 먼저 필요하다.

다음 순서: 변경된 후보 확인 완료 → 실제 리프트 높이를 보존/복원하는 제어 연결 복구 → 새 관절·라이다/RGB-D 확인과 베이스 정렬 → 저장 대상 재연결 → 새 상태 기준 경로 재계산·시간 보간 검사 → 집기. 현재 계산은 과거 유지 관절값을 사용한 오프라인 검토이며 실행 파일로 승격하지 않았다. 팔 영점·카메라 XY 변환은 바꾸지 않았다.

증거: `output/s4b-fine-step-deploy-20261116-r3/review/resume-state.json`, `tracked-pick-adjusted-base-plane-open8-c3/report.json`, `rgbd-planar-window.json`. 반복 실행용 진단 스크립트는 같은 폴더의 `reproduction/`에 보관한다. 커밋·PR 갱신은 하지 않았다.
