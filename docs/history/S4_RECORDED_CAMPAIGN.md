현재 요구는 최종 `lidar-final-v1/occupancy.json`에 RGB-D 상부 장애물을 보완하고
베이스 차폭까지 반영한 이동 영역이다. `navigation-2d-v1`은 라이다만 사용한
중간 비교본이며 최종 이동 영역이 아니다. 최신 검토는 `movement-fused-v1`이다.
원본 라이다 지도·시멘틱 이름·RGB-D 원본은 유지한다.

사용자는 이 본을 다음 검증의 기준으로 선택했다. 운용 중 가구 이동은 사용자의
재SLAM 요청 없이 자동 부분 갱신하는 요구로 확정했다. 후속 결정으로 새 물체는
모두 임시 장애물이며, 새 가구 등록은 사용자 요청의 추가 매핑으로 한정한다.
기존 가구의 검증된 동일성 근거가 있을 때만 위치를 자동 갱신한다. `living-map-v2`는 이 지도
격자에서 합성 변경·저장·재시작을 검사한 별도 결과이며, 원본 지도나 실제 가구 위치를
변경한 결과가 아니다. 구현 범위와 남은 순서는 [생활 공간 지도 설계](../S4_LIVING_MAP_DESIGN.md)의
2026-11-13 절에 기록한다. 실물 자동 주행·갱신 인수는 아직 남아 있다.

`--ray-depth-review`는 기존 native depth 투영과 `DepthVolume._ray`를 재사용한다.
9개 원본 묶음에서 이동 10cm 또는 회전 10° 이상 달라진 시점과 각 묶음의 끝을
선택해 365개 깊이 영상을 재생했다. 단순히 모든 과거 끝점을 합치는 대신 같은
관측에서는 hit를 우선하고, 뒤의 측정 광선으로 비어 있음이 관측되면 과거 점유
근거를 낮춘다. hit/clear 점수와 불확실 상태는 따로 저장하며 확률이라고 부르지 않는다.
8픽셀 간격의 오프라인 검토이므로 전 높이의 빈 공간을 보증하지 않는다.

상부 voxel을 지도 칸에 먼저 넓혀 그린 뒤 다시 로봇 외형으로 확장하면 두 격자의
원점이 다를 때 중복 팽창이 생긴다. `voxel_body_centres`는 원래 voxel의 정사각형과
지도 중심점의 격자 위상 차이를 직접 사용한다. `--movement-area`는 5° 간격의
72개 방향에서 높이별 고정 외형을 검사한다. 팔은 제외하고 베이스·고정 장착대·
리프트·센서와 3cm 여유를 유지한다. 초록은 가능한 방향이 있는 중심 위치 후보,
노랑은 깊이 근거가 불확실한 곳이다. 연속 회전이나 연결 경로 검증을 뜻하지 않는다.

실제 기록 위치는 장애물을 지우는 데 사용하지 않고 마지막에 대조한다. 1,096개
기록 위치 중 207개에는 여전히 외형/깊이 충돌 판정이 남아 그림에 재확인 점으로
표시했다. 이 결과를 완료된 실물 통과 검증이나 운용 costmap으로 승격하지 않는다.

이동 범위 검토에는 사용자가 팔을 접고 주행한다는 전제로 `--traversability
--exclude-arms`를 요청했다. 이 옵션은 팔 관절·집게 STL만 제외하며 하단 베이스,
바퀴, 고정 장착대, 리프트, D415, 라이다를 유지한다. 실제 접힌 팔의 외형 확인이나
실시간 제어 기준 변경을 뜻하지 않는다. 이번 표시는 `traversability-body-only-v1`과
`movement-body-only-v1`이며 리프트 최하단·여유 3cm·한 방향 기준이다.

## 사진 맥락으로 붙이는 가구 이름

`tools/diagnostics/review_context_labels.py`는 기존 시멘틱 관측에 별도의 이름 층을
만든다. 이번 `s4-room-mapping-20261113-context-review-v1`은 대화에서 대표 사진
60장을 직접 비교한 결과다. 상시 자동 추론 서비스나 외부 모델 API 실행 결과로
기록하지 않는다. 검토 결정은 `decisions.json`, 원본 사진 연결과 해시는
`household-labels.json` 및 `evidence-hashes.json`에 보존한다.

기존 48개 관측 조각을 12개 가구·기구 후보에 연결하거나 오분류로 표시했다.
주요 지도에는 11개 가구를 표시하고, 운동기구 후보는 상세 기록에 남겼다.
소파 옆 수납장과 실제 주방 냉장고, 침대 프레임과 소파, 침대 옆 탁자와 옷장처럼
부분 영상에서 혼동된 이름을 여러 방향 사진으로 재검토했다. 화장대는 화장품과
드라이어·스툴 배치에 따른 용도 추정이다. 원본 모델 결과와 장애물 형상은 유지한다.

부엌·현관·소파/작업 공간·침실은 기능별 영역 제안이다. 네 개의 독립된 방이라는
판정이나 방 경계 다각형을 생성하지 않으며, 안방 여부와 개인 호칭은 미확정이다.
이미지 기반 가구 연결은 추정이며 이름 위치는 주행 목표나 물체를 놓을 표면이 아니다.

```bash
python3 tools/diagnostics/review_context_labels.py \
  --output output/NEW-context-review build \
  --semantic output/s4-room-mapping-20261113-semantic-on-lidar-v2/report.json \
  --review output/s4-room-mapping-20261113-context-review-v1/decisions.json \
  --map output/s4-room-mapping-20261113-lidar-final-v1/occupancy.json

python3 tools/diagnostics/review_context_labels.py \
  --output output/NEW-context-review query '침실 화장대'
```

개인 호칭 확인 후 `rename ID 이름 --alias 별칭 --expected-revision N`으로 저장한다.
예를 들어 사용자가 침실을 안방으로 확인한 경우에만 `zone-sleeping 안방 --alias 침실`을
적용한다. 이름 수정은 관측 시각·좌표·물리적 확인 상태를 갱신하지 않는다.
동일한 별칭이 여럿이면 `AMBIGUOUS`와 모든 후보를 반환한다.
기존 `WorldStore`의 별도 기록으로 저장·재읽기하며 실시간 제어용 엔티티는 생성하지 않는다.
빌드 명령은 기존 이름 결과를 덮어쓰지 않는다. 새 지도에는 원본 보고서 해시와
해당 지도에서의 가구 관측을 다시 대조해야 한다.

전원 이동과 조종 복구로 나뉜 기록은 각각 원본으로 보존한다. 조종의 종료 오류는
센서 촬영 전체를 버리는 기준이 아니다. 로봇의 현재 상태를 확인하는 제어기 검사와
이미 저장된 환경 관측을 처리하는 오프라인 지도 검사는 분리한다.

## 원본과 파생 자료

- 원본: 각 구간의 `teleop/*.jsonl`, `capture/scans.json`, RGB-D 원본과 보정·시간 정보.
- PC 백업: 젯슨 파일 전체의 SHA-256 및 RGB-D 촬영 당시 해시를 모두 대조한다.
- 파생 자료: 구간별 시각을 하나의 재생 시간축에 옮기되 원래 시각·파일·구간을 함께 기록한다.
- 실패 이벤트를 정상 종료로 바꾸거나 가짜 명령 응답을 추가하지 않는다.
- 젯슨 삭제·완성 지도 배포는 이 처리의 일부가 아니다.

## 전체 센서 관측 사용

`prepare_recorded_campaign.py --all-sensor-observations`는 이동 중, 정지 중,
오류 종료 직전, 복구 대기 중의 저장된 라이다 관측을 모두 연결한다. 정상적으로
짝이 맞는 바퀴 명령·응답은 광선 시간 보정과 정합의 초기 추정에만 사용한다.
바퀴 응답이 없는 구간은 인접 라이다 관측으로 추정한다. 없는 센서 관측을 생성하지 않는다.

구간 경계와 긴 수신 간격은 양방향 라이다 잔차와 여러 초기 위치의 정합 결과를
비교한다. 서로 다른 위치가 비슷하게 맞으면 자동으로 붙이지 않고 해당 경계를
보고한다. 정상적인 수신 간격에서는 라이다 정합을 이어 간다. 이 경로는 모터나
실시간 주행 허용 기준을 변경하지 않는다.

모든 RGB-D 원본은 파생 묶음에도 보존한다. 영상이 해당 원본 구간의 라이다 위치
범위를 벗어나면 `pose_covered=false`로 표시한다. 다른 구간의 비슷한 재생 시각에
잘못 투영하지 않으며, 원본을 삭제하지 않는다.

```bash
python3 tools/diagnostics/prepare_recorded_campaign.py \
  --campaign output/s4-room-mapping-20261113-campaign.json \
  --all-sensor-observations \
  --output output/s4-room-mapping-20261113-combined-all-v2

source output/s4-local-mapping-runtime/env.sh
export ROS_DOMAIN_ID=176
python3 tools/run/check_slam_replay.py \
  --recorded-capture output/s4-room-mapping-20261113-combined-all-v2 \
  --prepared-campaign --replay-rate 4 \
  --output output/s4-room-mapping-20261113-map-all-v2
```

각 출력 경로는 새 디렉터리여야 한다. 기존 결과를 덮어쓰지 않는다. 재생은 실제
`slam_toolbox`를 사용하며 지도·그래프 저장 후 별도 프로세스에서 다시 읽어 셀 일치를
검사한다. 가속 재생은 TF·라이다·광선 시간에 동일 비율을 적용하고, 저장된 위치에는
원래 재생 ROS 시각과 영상에 연결할 원본 시간축을 함께 남긴다.

## 2026-11-13 촬영

1~3구간 및 중간 복구 묶음 9개를 PC로 복사했다. 원본 4,929파일,
13,522,827,742바이트, RGB-D 4,835장의 해시가 일치했다.
`output/s4-room-mapping-20261113-backup-integrity.json`에 검증 결과가 있다.

전체 센서 처리에는 라이다 12,039회 스캔 전부와 RGB-D 4,835장을 보존했다.
RGB-D 4,796장은 해당 구간의 라이다 위치 시간 범위 안에 있고, 39장은 주로
라이다보다 먼저 촬영된 시작 영상이다. 복구 대기 묶음 `03b`도 포함한다.
바퀴 응답 구간만 사용한 첫 비교본 `combined-v1`은 최종 처리 대상이 아니다.

구간 정합은 실내 관측의 연결 확인이며 측량에 의한 절대 좌표 정확도나 전원 재연결
직후의 실시간 위치 복구 검증을 대신하지 않는다. RGB-D 투영과 가구 이름 검토는
저장 지도의 위치 결과를 사용하므로, 지도 정합 품질과 의미 분류 품질을 따로 확인한다.

## 라이다 단독 비교와 본체 가림

사용자가 원한 라이다 단독 비교는 `--lidar-only`로 별도 생성한다. 이 경로는
카메라·시멘틱·바퀴 로그를 읽지 않는다. 종료 오류와 관계없이 저장된 라이다
스캔을 전부 보존하고, 최근 공간 키프레임의 주변 관측에 맞춰 이동을 추정한 다음
기존 `slam_toolbox`로 전역 정합과 지도 저장·재읽기 검증을 한다.
`--surface-matching`은 벽 표면의 법선을 이용하는 비교 옵션이다.

앞바퀴 케이스 위의 라이다에서는 본체가 뒤를 가린다.
`lidar_visibility.review.json`은 기존 공식 STL 광선 교차 검토와 사용자의 장착
확인을 기반으로 센서 각도 0~42°, 316~359°를 가림으로 표시한다. 경계에 2°를
더해 0~44°, 314~359°를 제외하며 나머지 269개 방향을 유지한다. 이 마스크는
현재 장착·최하단 리프트 기록의 검토값이며 정밀 외부 보정값은 아니다.

배열을 압축하거나 각도·광선 시각을 바꾸지 않는다. 가려진 광선은 파생 JSON에서
`null`, ROS 재생에서 `NaN`으로 전달한다. 보이지 않는 구역을 빈 공간으로
칠하거나 그곳의 근거리 반사를 벽으로 정합하지 않는다. 실제 기록의 원래
가림 87방향 중 유효 반환 765개와 경계 여유의 10,595개 반환을 제외했다.
이것은 스캔 회차나 오류 구간을 버리는 처리와 다르다.

```bash
python3 tools/diagnostics/prepare_recorded_campaign.py \
  --campaign output/s4-room-mapping-20261113-campaign.json \
  --lidar-only --output output/NEW-lidar-input
# 위의 기존 SLAM 재생과 최종 그래프 내보내기를 같은 방식으로 실행한다.
python3 tools/diagnostics/review_s4_sensor_capture.py \
  --capture output/NEW-lidar-input --slam-review output/NEW-final-graph \
  --lidar-only --output output/NEW-lidar-review
```

단독 검토는 모든 원본 해시와 스캔 수, 가림 밖 거리의 동일성을 대조한다.
순수 2D 지도와 구간별 관측 겹침을 따로 그린다. 관측과 지도 사이의 잔차는
동일 자료의 내부 일치도이며 측량 정확도가 아니다. 입력 스캔 수와 SLAM이
선택한 공간 키프레임 수도 구분해서 남긴다. 원본·이전 지도는 덮어쓰지 않는다.

이번 라이다 단독 대표 결과는 `lidar-final-v1`, 그림과 원본 대조는
`lidar-review-v1`이다(공통 접두사 `s4-room-mapping-20261113-`). 9개 묶음의 12,039회 스캔 모두가 입력됐고 저장 그래프의 키프레임은 1,096개다. 5 cm 지도 셀은 저장 후 재시작·재읽기에서도 동일했다. 관측점의 지도 장애물
10 cm 이내 일치율은 97.77%, 중간값 2.20 cm, 90백분위 4.10 cm였다.

벽 표면을 이용한 비교본은 각각 97.68%, 2.19 cm, 4.03 cm로 큰 구조와 잔차가
비슷했다. 대표본은 하단 오른쪽 경계의 두꺼워짐·겹침이 조금 덜한 쪽으로 골랐다. 일부 가장자리 겹침과 고립된 반사는 남아 있으며 측량 정확도나 실제 주행 통과를
판정한 것은 아니다. 두 결과와 중단된 비교 실행 기록도 보존했다. 젯슨 배포나 원본 삭제는 수행하지 않았다.

선택과 비교 수치는
`output/s4-room-mapping-20261113-lidar-only-summary.json`에 기록했다.

## 라이다 대표 지도에 RGB-D·시멘틱 재결합

`prepare_recorded_campaign.py --attach-rgbd-to <lidar-only>`는 라이다 지도 입력을
수정하지 않고 원본 구간의 RGB·깊이 노출 시각을 해당 라이다 구간의 시간축으로
옮긴다. 이전 합성본의 시각을 재사용하지 않는다. 스캔과 궤적은 동일 파일로
연결하고, RGB-D 원본 해시·보정값·센서 변환의 일치를 검사한다. 지도 검토에서는
첨부본의 원본 라이다 입력을 따라가 저장 지도와 동일한 입력인지 확인한다.

```bash
python3 tools/diagnostics/prepare_recorded_campaign.py \
  --campaign output/s4-room-mapping-20261113-campaign.json \
  --attach-rgbd-to output/s4-room-mapping-20261113-lidar-only-v1 \
  --output output/NEW-rgbd-attachment
```

최종 결과 요약은 `output/s4-room-mapping-20261113-fusion-summary.json`이다.
원본 4,835장은 모두 보존했고 위치가 연결되는 4,773장을 깊이 합성했다.
나머지 62장은 원본 구간 라이다 범위 밖 39장, 최종 지도 위치 범위 밖 23장으로
임의 위치에 투영하지 않았다. 시멘틱은 9개 촬영 묶음을 모두 포함하는 60개 시점을
선정해 기존 DINO/SAM 및 주거 가구 분류 검토 모델을 로컬에서 실행했다.

희소한 최종 그래프 사이의 보정 검사는 임의의 궤적 원점 대신 실제 로봇 위치에서
보정 변화량을 계산하도록 수정했다. 원점에서 먼 위치의 작은 회전이 큰 병진으로
계산돼 정지 복구 묶음 `03b`를 배제하던 오류다. 기존 이동·회전 허용치는 유지했다.
원점에서 10 m 떨어진 회전 사례와 실제 0.7 m 병진 거부 사례를 검사했다.

`fused-review-v2`에는 같은 격자의 라이다·상부 RGB-D·높이별 본체 여유 후보·주요
가구 관측 레이어를 저장했다. 주요 가구의 부분 관측 48개를 실제 물체 48개로
표현하지 않는다. 그림에서는 관측된 셀을 유지하면서 연결된 큰 범주로 이름만
묶는다. 이름 표시를 위한 연결 처리는 장애물 영역이나 통과 가능 영역을 바꾸지
않으며, 작은 물체는 별도 가구 이름으로 추가하지 않는다.

깊이 상부 형상은 라이다가 빈 공간으로 본 셀 4,474개에 추가 관측을 제공했다.
상부 형상의 부재를 전 높이의 빈 공간으로 인증하지 않는다. 냉장고·수납장 구분과
일부 중복 분류는 확인이 필요하다. 원본 지도, 원본 영상과 이전 비교 결과를
보존했으며 젯슨 배포·삭제·로봇 동작은 수행하지 않았다. 관련 검사 76개가 통과했다.

## 최종 그래프와 영상 좌표

온라인 SLAM 위치를 그대로 사용하면 나중에 수행된 루프 보정이 과거 영상 위치에
반영되지 않는다. `tools/diagnostics/export_slam_graph_poses.cpp`를 설치된 동일 버전의
Karto 헤더·라이브러리로 컴파일해 저장 그래프의 `GetCorrectedPose()`를 읽는다.
이는 저장 파일만 읽으며 그래프나 로봇을 수정하지 않는다.

```bash
source output/s4-local-mapping-runtime/env.sh
python3 tools/run/check_slam_replay.py \
  --finalize-graph-from output/s4-room-mapping-20261113-map-all-v2 \
  --graph-pose-exporter output/s4-local-mapping-runtime/export-graph-poses \
  --output output/s4-room-mapping-20261113-map-final-v3
```

이번 저장 그래프에서 보정된 위치 919개를 얻었다. 기존 온라인 위치도 별도로
보존했다. 관측점과 최종 지도 장애물의 10 cm 이내 일치율은 온라인 위치 사용 시
69.1%, 최종 그래프 사용 시 81.9%였다. 중간값은 2.6 cm, 90백분위는 18.1 cm다.
같은 촬영 자료의 내부 일치도이므로 실측 위치 정확도로 해석하지 않는다.

최종 그래프는 정지 구간의 키프레임이 드물어도 정상이다. 의미 지도 검토에서는
최종 그래프와 연속 라이다 궤적이 모두 있는 경우에만 이 구간을 보간한다. 입력 위치
간격 2초 초과 또는 보정 변화 0.5 m/20도 초과는 계속 표시한다. 실시간 위치의 기존
신선도 검사는 변경하지 않았다. 시멘틱 비교 영상은 각 촬영 묶음에서 먼저 한 장씩
고른 뒤 다른 시점을 추가하고, 촬영 ID에는 원본 구간 이름을 포함한다.

최종 산출물은 캠페인 JSON과 별도 처리 요약을 통해 찾는다. 이름 인식과 깊이 기반
주행 제한 후보는 검토 자료다. 로봇 자체의 반사, 회전 중 전체 외형, 실측 지도 오차가
남아 있으므로 이 레이어를 그대로 실물 주행 허용값으로 배포하지 않는다.
