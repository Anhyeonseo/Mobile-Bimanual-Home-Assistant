# 인식·지도 기술 선택 기준

2026-10-29 · 상태: 후보 평가 기준, 실측 우승 모델 미선정

목표는 새 집에서 가구를 지도에 연결하고 ALOHA Mini 1이 실제로 지나갈 수 있는 길을 만드는 것이다. 기존 Grounding DINO·SAM과 자체 Python 깊이 구현은 비교 기준으로 보존한다. 이미 사용했다는 이유로 고정하지 않고, 새 기술이라는 이유로 교체하지 않는다. 주요 모듈 선택과 실측 병목·실패가 발생할 때 결과를 다시 비교한다.

## 역할을 먼저 나눈다

| 역할 | 필요한 출력 | 선택 기준 |
|---|---|---|
| 지도 생성의 기하 처리 | 시간·포즈가 맞는 높이별 occupied/free/unknown, 저장 가능한 전역 투영 | 침대 몸체·돌출 상판 누락, 잘못된 free, 루프 보정 후 정합, 저장/복원, 동시 처리 부하 |
| 가구 의미 인식 | 가구 종류·인스턴스 영역·관측 근거 | 다른 집의 누락/오탐, 같은 가구의 중복·잘못된 결합, 범주 커버리지 |
| 요청 물체 찾기 | 자연어 속성과 실제 대상 후보·마스크 | 작은 물체·색·비슷한 두 물체·가림 조건에서의 대상 선택 |
| 불확실한 장면 해석 | 제한된 의미 후보와 재관측 필요 여부 | 설명의 타당성·비용·지연. 충돌 지도를 모델 설명으로 지우지 않음 |

모든 역할을 한 모델로 처리할 필요는 없다. 매 프레임의 기하 입력과 필요한 키프레임의 의미 인식을 분리하고, 지도 생성은 의미 추론의 완료를 기다리지 않는다. 물체를 찾을 때만 무거운 모델을 쓰는 구성도 같은 조건으로 평가한다.

## 인식 후보

| 후보 | 평가하는 이유 | 아직 검증할 부분 |
|---|---|---|
| 현재 Grounding DINO + SAM | 설치·촬영 사례가 있는 기준선, 언어 기반 후보와 분리된 마스크 생성 | Jetson 동시 부하, 작은 물체 오탐, 가구별 깊이와 맞는 마스크. 기존 동작을 최고 성능의 근거로 삼지 않음 |
| [YOLOE 공식 구현](https://github.com/THU-MIG/yoloe) | 텍스트/시각/프롬프트 없는 입력과 탐지·분할을 통합하는 비교 후보 | 사용할 정확한 버전·가중치·범주, 실제 Jetson 지연/RAM/정확도, TensorRT 변환 후 결과와 라이선스 |
| 경량 고정 범주 instance segmentation | 반복 관측할 가구 목록이 제한될 때 비교할 단순 기준선 | 책상/식탁 같은 필요한 세부 범주가 실제 학습 목록에 있는지 확인. 범주가 빠진 상태로 속도만 비교하지 않음 |
| 필요한 키프레임의 VLM 보조 해석 | 공간 관계나 이름이 모호한 장면의 추가 판단 후보 | 잘못된 설명, 공간 정밀도, 비용·지연. 외부 영상 API는 텍스트 API 허용과 별도 설정 |

YOLOE의 공식 지원 기능을 근거로 비교 후보에 넣었으며 우리 Jetson에서 더 빠르거나 정확하다고 측정한 것은 아니다. 탐지와 분할이 한 모델인 점은 통합 부담을 줄일 가능성이 있지만 실제 이득은 기록 영상과 동시 실행 조건에서 확인한다. 단순 가구 스캔과 복잡한 물체 요청에서 각각 유리한 구성이 다를 수 있다.

## 지도 생성 후보

| 후보 | 평가하는 이유 | 우리 요구에서 확인할 조건 |
|---|---|---|
| 기존 `DepthVolume` + 저장 투영 | 센서/지도 계약·unknown 처리·침대 사례를 재현하는 작은 참고 구현 | Python 누적 지도 전체를 제품용 엔진으로 간주하지 않음. 처리량·메모리·집 크기 한계 평가 |
| [OctoMap](https://github.com/OctoMap/octomap) 기반 점유 지도 | 확률적 3D occupancy를 다루는 공개 기반 | 입력 포즈/루프 보정과 연결, 전체 운반 높이 투영, CPU 비용, 센서 오차·free 갱신 정책 |
| [NVIDIA Isaac ROS nvblox](https://github.com/NVIDIA-ISAAC-ROS/isaac_ros_nvblox) | GPU 기반 3D 재구성과 Nav2 국소 costmap 연결 제공 | Jetson·JetPack·ROS 호환, 다른 추론과 GPU 경쟁, 전신 높이 범위, 전역 저장·재로드·루프 보정. 국소 costmap 제공만으로 최초 스캔 요구를 충족했다고 보지 않음 |
| [RTAB-Map ROS](https://github.com/introlab/rtabmap_ros) 통합 검토 | RGB-D 관측과 지도 처리의 공개 통합 기반 비교 | 기존 2D 위치 추정과의 역할 중복, map→odom 단독 발행, 센서 구성·저장·재위치 추정의 실제 설정 |

현재 권장 아키텍처는 **위치 추정 + 누적 높이 기하 + 가구 의미 기억 + 생성된 전신 주행 지도**의 분리다. 라이브러리를 고르는 일과 이 아키텍처의 요구를 충족하는 일은 구분한다. 특정 라이브러리의 기본값이 ALOHA 전신 높이를 포함한다고 가정하지 않는다.

## 동일한 자료로 비교하고 결정한다

1. 조정에 사용하지 않은 집/구역과 카메라 시점을 포함한 RGB-D·LiDAR·실측 포즈 기록을 고정한다. 같은 집의 연속 프레임을 무작위로 섞어 새 집 일반화 성능으로 보고하지 않는다.
2. 침대 다리 사이, 낮은 소파, 돌출 책상 상판, 얇은 의자, 검은/반사 표면, 물체 가림, 같은 가구 두 개를 포함한다. 보이지 않는 부피는 정답 free로 만들지 않는다.
3. 모델/가중치/입력 크기/정밀도/범주를 고정하고 누락·오탐·mask 품질·3D 위치 오차·인스턴스 오류를 기록한다. 각 후보에 같은 조건과 필요한 범주를 제공한다.
4. 실제 Jetson에서 SLAM·추론·영상·제어를 함께 실행할 때 p50/p95 지연, 관측 나이, 메모리, 온도, 프레임 누락을 잰다. 단독 GPU FPS와 전체 작업 성능을 구분한다.
5. 최종 생성 지도에서 잘못된 통과 가능 셀, 저장 후 재로드 차이, 경로 성공/정지, 과도한 차단으로 지나갈 수 없는 통로를 평가한다. 바닥 지도 정확도만 비교하지 않는다.
6. 같은 자료에서 이득과 회귀를 비교해 유지/교체/역할 분리를 결정한다. 측정하지 않은 칸은 미측정으로 남긴다. 현재는 모델 다운로드·교체·Jetson 벤치마크를 수행하지 않았다.

지도 산출물에는 LiDAR 원본, RGB-D 높이를 반영한 주행 지도, 가구 의미 정보, 각 원본/생성 revision, 센서 보정, 운반 외형, 관측 범위를 함께 연결한다. 최초 지도 생성·저장 단계부터 침대 몸체가 차단되어야 하고, 주행 중 최신 관측은 이동한 가구와 사람 등을 갱신한다.
