## 0. 한눈에 보기

- 토크를 켠 자동 촬영으로 **리프트 두 높이(약 5cm, 30cm)에서 120장**을 모았다. 사진 맞춤 오차가 11/13의 4–5px에서 **1.1–1.6px**로 줄었다.
- 카메라 **pitch·roll·높이에 더해 x·y·yaw도 정해졌다.** 모델을 바꿔도 x·y는 약 5mm, yaw는 0.5° 안에서 일치한다(11/14에는 x가 10–29mm 흔들렸다). 기준은 왼팔 장착 위치다.
- **팔 끝 좌우·상하 오차는 0.7–3mm.** 남은 오차는 카메라 깊이 방향으로 한쪽으로 치우쳐 있었고, 원인은 **리프트 모델**이었다.
- **리프트가 런타임 공식(1회전 = 84mm, 최하단 = 0)보다 약 4–5% 더 움직이고 영점도 몇 mm–1.6cm 낮다.** 그래서 팔이 프로필보다 낮은 곳에 있다. S3에서 "목표보다 약 8mm 아래를 잡았다"는 관찰과 방향이 같다.
- 가장 좋은 모델(영점 + 중력 처짐 + 리프트)은 교차 검증 중앙값 **5.1mm**다. 다만 **런타임은 처짐 보정을 받지 못한다.** 런타임이 받을 수 있는 모델(영점 + 리프트)은 **10.5mm**이고, 리프트 보정이 없는 모델은 15.8mm다.
- 펌웨어는 측정 중 S3(0x24911)로 바꿨다가 **S4(0x2492D)로 복구했다**(`install.sh` 종료 코드 0). 최종 식별 확인과 S4 준비 절차는 현서가 평소 방식으로 한다.

## 4. 결과

### 4.1 모델 비교 (리프트 높이 = 엔코더, 5겹 교차 검증, 팔 마커 오차 중앙값 mm)

| 모델 | 전체 | 95% | 왼 5cm | 왼 30cm | 오른 5cm | 오른 30cm | 런타임 적용 |
|---|---|---|---|---|---|---|---|
| A 영점 | 15.8 | 47.5 | 12.2 | 2.0 | 34.5 | 12.5 | 가능 |
| **AL 영점 + 리프트** | **10.5** | 30.9 | 9.8 | 2.0 | 19.5 | 7.9 | **가능** |
| **CL 영점 + 처짐 + 리프트** | **5.1** | 18.1 | 5.7 | 2.2 | 9.3 | 4.4 | 처짐 항 필요 |
| CLT + 리프트 기울기 | 6.1 | 29.9 | 7.2 | 2.3 | 18.4 | 4.0 | – |

방향별(CL): 좌우·상하 0.7–3.0mm, 깊이 방향 −8.5 ~ +3.3mm.

### 4.2 추정값

| 값 | AL (런타임 가능) | CL (최선) |
|---|---|---|
| 리프트 배율 | +3.9% | +5.0% |
| 리프트 영점 | −5.7mm | −15.9mm |
| 카메라 pitch / roll / yaw | 45.78° / −1.31° / +0.30° | 45.77° / −1.29° / +0.17° |
| 카메라 x, y, z (base_link) | 121.9, 34.8, 1008.0mm | 121.5, 35.9, 1007.9mm |
| 왼팔 영점 어깨 / 팔꿈치 / 손목 굽힘 | +5.4 / +0.9 / −0.0° | +2.5 / +7.6 / +1.0° |
| 오른팔 영점 | +7.7 / +3.2 / −4.6° | +1.4 / +8.1 / +4.7° |
| 오른팔 장착 보정 t | (10.2, 1.2, −1.2)mm | (7.6, 0.6, −7.5)mm |

- 리프트 배율은 분석마다 **3.4–5.1%**, 영점은 **−6 ~ −16mm**로 모델에 따라 달라진다. 처짐과 리프트가 일부 섞인다. 방향(더 많이 움직이고, 팔이 낮음)은 모든 분석에서 같다.
- 팔 영점도 모델에 따라 수 도씩 다르다. 그러니 **값을 섞어 쓰면 안 되고, 한 모델의 묶음 전체를 같이 적용해야 한다.**
- 카메라 6자유도는 모델과 상관없이 안정적이다(x·y 5mm, 각도 0.5° 이내). 바닥·탁자 높이 오차는 4mm 이내다.

### 4.3 서보 추종 오차 (명령 대비 실제, 투어 매 촬영 기록)

어깨 10–14 raw(0.9–1.2°), 팔꿈치 3–10, 손목 굽힘 최대 15 raw. 어깨 1°는 팔 끝 약 5mm다.
**보정은 실제 엔코더 기준이라, 런타임이 목표각을 그대로 보내면 이 차이(주로 아래 방향)는 남는다.**
원본은 각 투어 사진의 `joints.json`에 있다(`commanded_raw`, `settle_error_raw`). 관절별 중력 토크에 대해 맞춰 명령 보정식을 만드는 작업은 아직 하지 않았다.

### 4.4 반복성

왼팔은 반복 방문 3자세에서 카메라 마커 위치 흩어짐 4.0mm(관절 0.9°)다. 오른팔은 8자세에서 7.0mm(최대 19mm, 관절 0.26°)다.
오른팔 마커가 작게(약 46px), 비스듬하게 찍혀 PnP 깊이 잡음이 큰 영향으로 본다.

## 5. 적용 방법 (제안, 팀 합의 후)

**한 모델의 묶음 전체**를 같이 넣는다. 일부만 넣으면 나빠질 수 있다. 11/14 결과에서 카메라만 바꾸자 왼팔이 11.1mm로 나빠진 적이 있다.

1단계(설정만, 코드 수정 없음): **AL 모델 묶음**

| 프로필 항목 | 바꿀 내용 |
|---|---|
| `base_from_optical` | AL 카메라 행렬(`calib_enc_20261117.json`의 `AL ...`→`p`의 `cam`) |
| `arms.*.alignment.*.home_model_rad` | AL 영점(어깨, 팔꿈치, 손목 굽힘). 회전축(base) 영점은 기준이라 그대로 |
| `arms.right.base_from_arm_at_lift_zero` | 기존 행렬 뒤에 오른팔 장착 보정 `rm`을 곱함 |
| `lift.meters_per_count` | × 1.039 (배율) |
| 리프트 영점 | 양팔 `base_from_arm_at_lift_zero` z에 −5.7mm(또는 `platform_at_lift_zero`에 같은 의미로 반영) |
| `camera_height.calibrated.json` | 위 카메라 행렬의 z 행으로 교체. 높이 전용 모델도 같은 묶음에서 나와야 함 |

2단계(코드): 런타임 FK·IK에 중력 처짐 항을 추가하면 CL 묶음(5.1mm)을 쓸 수 있다. 서보 추종 오차는 명령 보정으로 따로 넣는다.

**적용 전후로 반드시**
- 기존 프로필 백업, 프로필에 `calibration_id`와 출처(이 문서, 결과 JSON SHA) 기록
- 같은 조건(수납장, 흰 리모컨)에서 **집기 전후 비교**. 집게 끝 검증이 실패했으므로 손가락 끝 정확도는 아직 실물로 확인되지 않았다
- 리프트를 높게 쓰는 집기는 배율 불확실성(3.4–5.1%)을 감안해 별도 확인

## 6. 집게 끝 대기 (검증 실패, 재계산 대기)

- 기록된 리프트 높이는 `0.29`다. 그런데 사진상 표적지가 80cm 책상 위이고 팔이 거의 수평이다. 29cm(3회전)로 계산하면 카메라 십자와 팔 끝이 28cm 어긋나고, **약 55cm(6회전)**로 계산하면 1–2cm다.
- 55cm로 가정해도 같은 점을 여러 각도로 찍은 사진끼리 약 12mm 어긋난다(정상 1–2mm). 손 미끄러짐, 토크 끈 집게의 휨, 투어가 다루지 않은 높이와 자세(외삽)가 후보다.
- **실제 리프트 높이를 확인하면** `calib_encoder_lift.py`의 엔코더 계산(바퀴 수)을 맞춰 다시 계산할 수 있다. 실측 검증은 실제 집기 시험이 더 확실하다.

## 7. 현장에서 확인된 하드웨어·소프트웨어 문제 (집기 코드 담당 참고)

| 문제 | 근거 | 제안 |
|---|---|---|
| **자동 이동 중 안전 정지 2회** | 오류 메시지는 `SAMPLE_DISCONTINUITY`(27)지만, 이는 펌웨어 `binary_control.c`의 대체 코드다. 실제로는 dispatch `failure_count=1`(모터 명령 전송 중 UART 오류) → `BinaryControl_LatchStop`. 읽기 실패 0. 두 번 다 오른팔 이동 중. 계획은 연속(한 틱 최대 1,745µrad, 한도 9,000) | 오른팔 케이블·커넥터·전원 점검. 진단 출력에 버스 구분이 있으면 좋음 |
| 오른팔 6개 모터 동시 무응답(여러 번) | 재연결로 복구(기존 C01) | 위와 같음 |
| 리프트가 토크 없이 천천히 하강 | 투어 후 약 1cm(raw 1689 → 2058), 집게 끝 대기 중 여러 번 | 리프트 유지 상태를 운용 중 확인 |
| 하드웨어 수리 후 바퀴 3개 무응답 | 배선 분리 | S3 시작 검사와 정지 확인에 바퀴가 필요 |
| 정지 잠금 | 범위 초과(쉬는 팔이 받침에서 미끄러짐 포함), 투어 종료 시 | 읽기 전용 도구는 잠금 상태에서도 읽도록 수정 |
| 노트북 ↔ Jetson 접속 불가 | 공유기 2.4/5GHz 대역 간 격리(Jetson 2.4GHz) | 노트북 2.4GHz 고정 |

## 8. 재현

```bash
PY=~/.venvs/calib/bin/python; A=tools/diagnostics/extrinsic_capture/analysis; C=~/cal_20261116
# 최종 분석 (리프트 = 엔코더, 모델 4개 교차 검증 + 집게 끝)
$PY $A/calib_encoder_lift.py . $C $C/T05b,$C/T05d,$C/T05f,$C/T30 ~/cal_work/calib_enc_20261117.json --cv 5

$PY $A/intrinsics_check.py $C --square-mm 25.0 --out ~/cal_work/lens_near_20261117.json
# 투어 계획 (5cm 훑기 재사용, 휴식 자세 = 마지막 연결 훑기 시작점)
$PY $A/plan_tour.py . ~/cal_20261113 ~/cal_work/calib_1113.json $C/tour30.json --sweeps $C/SW05-L* $C/SW05-R $C/SW05-R2 $C/SW05-R3 $C/SW05-R5 \
    --rest-sweeps $C/SW05-R5 $C/SW05-L7 --rest-own --plan-lift 0.30 --repeats 3
```

분석 venv: `python3 -m venv ~/.venvs/calib && ~/.venvs/calib/bin/pip install numpy scipy opencv-contrib-python pillow`

## 9. 남은 일

1. 팀 합의 → AL 묶음을 설정 파일 형식으로 만들어 적용 → 집기 전후 비교
2. 런타임 FK·IK 처짐 항, 서보 추종 오차 명령 보정
3. 리프트 배율 확정(높은 리프트 한 높이 추가. 55cm는 카메라와 6cm까지 가까워져 새 훑기 필요)
4. 오른팔 두 높이 불일치 원인(장착 강성, 케이블, 마커)
5. 광각 평면(`W2-*`) 분석 반영, 렌즈 왜곡(모서리 사진 보강)
6. 집게 끝 대기 리프트 높이 확인 후 재계산
