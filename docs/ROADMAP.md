# 개발 로드맵

기준일: 2026-10-04. **VLM 기반 모바일 매니퓰레이션 플랫폼을 전체 작업 과정으로 완성하고, 단계 사이의 판단을 실험으로 검증한다.** 기존의 VLA 학습·Classical 비교 목표는 현재 범위에서 제외한다. 기존 실행 코어를 재사용하고 실제 인식·지도·접근 판단·실물 연결을 보완한다.

## 현재 시작점 — 2026-10-04

- ALOHA Mini 1 조립 및 Pi 5/Ubuntu 24.04.3 → STM32 → 왼쪽 Waveshare 공유 버스 연결 완료. 사용자 확인 배치는 **왼쪽 7 / 오른쪽 8 / 정면 9 / 리프트 10**이며 세 바퀴 +raw는 바깥쪽 기준 시계 방향이다.
- 공통 버스 응답, 바퀴 mode 1, 개별 방향과 이동 조합, **v4 브라우저 베이스 텔레옵 동작**을 사용자 확인했다. 초기 목표 0 쓰기 후 torque=1 문제는 명시적 OFF/readback을 추가해 해결 경로를 검증했다. 상세는 [하드웨어 기록](../hardware/README.md#텔레옵-v4--목표-0-쓰기-후-토크-off-명시)에 둔다.
- 다음 실물 작업은 **H2 리프트**이며 H1의 odometry·제동·통신 단절 실측은 남아 있다. H0 환경 확인은 확보되지 않은 항목만 보완한다. 텔레옵 성공을 전체 로봇 실기 완료로 세지 않는다.
- VLM 모델·실행 위치, 학습 없는 실영상 인식, 관측 기반 시맨틱 지도, 동적 정차 후보 선택은 아직 미구현/미평가다. H3의 영상 수집과 U1 평가를 일찍 시작하되 수동 리프트 시험을 막는 선행 조건으로 만들지 않는다.

## 1. 최종 목표와 완료 판정

| 목표 | 완료로 판단할 결과 | 필요한 단계 |
|---|---|---|
| G1. VLM 기반 전체 배달 | 언어 요청 → 장소/대상 후보 탐색 → 관측·집기에 적합한 정차 → RGB-D 좌표 검증 → 집기·운반·놓기·독립 결과 확인. 실패/취소/재관측 포함 | H0–H6 + U1/M1/Q1의 최소 기능 → E1 |
| G2. 판단 근거와 적용 범위 검증 | 새 외형, 복수 후보/대상 없음, 가림, 가구 이동에서 판단·보류·재탐색의 근거와 실패 원인을 재현하고 구성별 효과를 측정 | U1/M1/Q1의 비교 시험 + E1 |
| G3. 휴대폰 지도 이동 | 같은 주행·상태·취소 경계를 이용해 휴대폰 지도에서 선택한 바닥 지점으로 실제 이동 | H4 → A1, 운영 승격은 E1 |

**핵심 완료는 G1과 G2다.** 지정 물체·등록 좌표로 수행하는 기존 P&P 배달은 장치와 실행기를 검증하는 중간 기준선이다. VLM을 연결했다는 사실이나 한 번의 성공 시연만으로 최종 완료로 표시하지 않는다. G3는 확장 기능이며 핵심 판단 검증을 지연시키지 않는다.

### 플랫폼의 기여를 어떻게 설명할 것인가

구체적 문제는 **좁은 실내에서, 대상별 추가 학습 없이 리모컨을 찾아 접근·집기·배달할 때 생기는 판단의 불확실성**이다. 재사용 가능한 모듈/입출력 계약, 판단 근거를 남기는 관측·행동 로그, 구성별 비교와 실패 분석을 결과물로 만든다. 새로운 기반 모델이나 SLAM 알고리즘을 만들었다고 주장하지 않으며, 통합 방식의 효과와 일반화 범위는 측정 결과로 제시한다.

### 먼저 답할 개발 질문

| 질문 | 검증할 가설·비교 | 판단 근거/지표 | 단계 |
|---|---|---|---|
| 어디에 멈추는 것이 좋은가? | 고정 waypoint / 가장 가까운 도달 가능 후보 / 시야·팔 도달·리프트·재정렬 비용을 함께 보는 후보 선택 | 집기 가능 정차율, 첫 집기 성공, 재정렬 횟수, 전체 시간 p50/p95 | Q1 + H4/H5 |
| 처음 보는 외형을 언제 대상이라고 판단할까? | 한 번의 영상 판단 / 위치를 찾는 인식기와 VLM 교차 확인 / 다른 시점 재확인 | 오검출·누락·보류·잘못된 물체 선택, 수용한 후보의 정확도와 수용 비율 | U1 |
| 추가 학습 없이 리모컨을 찾을 수 있는가? | 특정 물체를 미세조정하지 않은 사전학습 모델과 고정 프롬프트로 새 인스턴스 평가 | 물체별/조건별 탐색 성공, 잘못된 집기, 대상 없음의 종료, 추론 시간 | U1 + H6 |
| RGB 의미 정보를 지도에 합치면 무엇이 좋아지는가? | 등록 장소만 / 프레임별 의미 검출 / 다중 관측을 연결한 의미 메모리 | 라벨 정확도, 물체 위치 오차, 중복/오병합, 이동 반영 지연, 탐색 이동거리·시간 | M1 |
| 가려졌거나 판단이 애매하면 언제 다시 볼까? | 고정 시점 순서 / 미관측 영역·예상 정보 증가와 이동 비용을 보는 순서 | 제한 시간 내 발견율, 추가 관측 수, 질문/개입 수, 잘못된 부재 선언 | Q1 + U1 |

‘최적’은 시험한 후보와 목적 함수 내에서 가장 좋은 선택을 뜻한다. 임의의 집에서 전역 최적임을 주장하지 않는다. 시맨틱 매핑으로 탐색이 좋아지는 것과 SLAM 위치 추정이 좋아지는 것은 별도 가설이다.

### 적용 범위와 물리적 전제

- 시작 범위는 알려진 평탄한 실내, 접근 가능한 소파/침대, 그리퍼가 다룰 수 있는 가벼운 강체다. 지정 리모컨으로 실행을 검증한 뒤 **개발에 쓰지 않은 리모컨 인스턴스**, 배치·조명·가림·가구 이동으로 확장한다. 새로운 물체 종류와 미지의 집은 별도 난이도로 보고한다.
- ‘추가 학습 없음’은 대상별 detector 재학습이나 VLM 미세조정 없이 평가한다는 뜻이다. 사전학습 데이터에 해당 종류/제품이 없었다고 보장하지 않는다. 프롬프트 예시·참조 사진을 쓰면 그 조건을 별도 기록한다.
- 실제 소파/침대 높이, 접근 공간, lift 범위, 팔 도달·충돌, 그리퍼 두께/무게 적합성을 먼저 확인한다. 낮은 곳 집기는 관절 범위와 충돌 검증으로 판단한다.
- 안 보인 것은 없는 것과 다르다. 다른 안전한 시점/리프트 높이로 재관측하고, 완전 가림·접근 불가·예산 소진은 미확인 사유를 남긴다. 쿠션을 치우거나 가구 내부를 뒤지는 능력은 현재 포함하지 않는다.
- 집기·운반 유지·해제·목적지 놓기는 별도의 실측 증거가 필요하다. 명령 성공, VLM의 문장, 깊이 평면 통과만으로 물리적 성공을 확정하지 않는다.
- 빨래/변형체, 계단, 모든 가사 작업은 완료 조건이 아니다. 양팔 전달은 대표 작업에 필요한 경우에만 사용한다.

이 보고서는 검증 당시 소스 묶음의 기록이다. 이후 문서 변경을 기존 해시에 소급 반영하지 않는다. 해당 PC 시험에서는 실물 명령·플래시·물리적 배달을 수행하지 않았다. 이후 2026-10-04에는 수동 베이스 텔레옵까지 실물 확인했다. 현재 전체 회귀 기록은 Python 1,002개/CTest 17개/STM32 6종 빌드다. 이는 VLM·시맨틱 매핑 성능 측정 결과가 아니다. 새 방향에 필요한 U1/M1/Q1은 실제 추가 개발 범위다.

## 3. 가장 빠르게 목표에 도달하는 순서

```text
현재: H1 수동 베이스 텔레옵 성공
  ├─ H0 미확인 환경 보완 + H1 odom/정지 → H4 실제 주행 ─────────┐
  └─ H2 리프트 → H3 팔·TF·카메라 → H5 정지 상태 집기 ──────────┤
                    └─ 실제 영상 → U1 VLM 인식·보류 판단 ────┤
H3 + H4 위치 추정 → M1 의미 지도/장소·물체 메모리 ────────────┤
H3 + H4 + H5 + U1 최소 기능 → Q1 관측·집기 정차/재탐색 ──────┤
                    H6 단계적 전체 연결 → E1 반복/구성별 평가 → G1/G2
                    H4 → A1 휴대폰 지도 이동 (확장)
```

1. 다음 실물 작업은 H2다. 기구·원점·하중 유지부터 확인하고 H0/H1의 남은 측정을 함께 진행한다.
2. H3부터 영상과 노출 시각·TF·수동 정답을 모은다. U1은 이 기록으로 평가를 시작해 로봇 제어/모델 선택을 서로 기다리지 않게 한다. 인식 모델·프롬프트를 바꿀 때마다 모터를 돌리지 않는다.
3. H4 주행과 H5 정지 플랫폼 집기는 독립 검증한다. 한 장비의 모터 시험은 시간을 나눠 수행한다. 첫 배달은 등록 장소와 고정 접근점을 써서 실행 경로를 먼저 확인한다.
4. M1은 등록된 2D 지도에 최소한의 가구/물체 관측 메모리를 붙이는 것부터, Q1은 검증된 소수 접근 후보를 고르는 것부터 시작한다. 정교한 전역 3D mesh나 새 SLAM 알고리즘을 선행 조건으로 만들지 않는다.
5. U1/M1/Q1을 한 번에 켜지 않는다. 기록 재생 → 단일 단계 → 짧은 배달 → 소파에서 침대로 배달 순서로 연결하고, 매번 기존 기준선과 비교한다. G1 최종 평가는 세 기능을 포함한다.
6. E1의 배치·정답·오류 분류와 로그 형식은 U1/H3 시작 시 정한다. 성능 측정은 마지막에 몰아 하지 않고 단계마다 축적한다. 가장 큰 실패 원인과 시간 소모부터 개선한다.
7. Pi는 현재 제어 시험 환경으로 유지한다. 추론 장치를 바꿀 필요가 확인되면 그때 ROS·센서·통신 회귀를 거친다. 모델 선정 전 Jetson 이전이나 외부 추론을 확정하지 않는다.

완료한 PC 코어를 다시 만드는 일정은 넣지 않는다. 일정은 각 단계의 실측 문제와 통과 기준으로 관리하며, 근거 없는 완료 날짜나 모든 상황을 해결한다는 약속은 두지 않는다.

## 작업별 구현 범위와 검증

아래는 **남은 작업**이다. 기존 F1–F3의 프로토콜·소유권·정지 구현을 다시 만드는 계획이 아니다. 각 단계에서 실제 driver binding, launch/config, 관측 제공자, 배포 승격 코드는 필요에 따라 추가해야 한다. ‘실측 숫자만 넣으면 끝’이라는 상태는 아니다.

### H0. 장비 확인·실행 환경·물리적 가능성

**선행:** PC 후보 검증 완료. **후속:** H1–H3과 실영상 수집의 공통 기반.

- ALOHA Mini 1 실부품·전원 분배·전압/전류·배선을 확인한다. 왼쪽 공유 버스는 팔 1–6 + wheel 7/8/9 + lift 10, 오른쪽은 별도 UART의 팔 1–6이다. 실제 모터 모델·ID·baud·mode를 readback한다. Waveshare의 두 커넥터를 독립 통신 채널로 취급하지 않는다.
- 보유 Jetson/Pi 중 한 대의 실제 OS/ROS/SDK·GPU/USB·메모리·저장/전원/냉각을 확인하고 실행 환경을 고정한다. 현재 베이스 시험은 Pi 5/Ubuntu 24.04.3이다. Jetson 전환이나 외부 VLM 추론은 실제 센서/제어/추론 동시 지연·메모리 측정 후 결정한다. PC Jazzy 환경과 동일하다고 가정하지 않는다. 배포판/컨테이너 변경이 필요하면 먼저 프로토콜·ROS·MoveIt 회귀를 확인한다.
- D415 변경 상태를 확인하고 실제 카메라 기준으로 설정한다. LDS-01은 2D 위치 추정/주행, 리프트 D415는 정지 집기 + 주행 상부 장애물 관측, 전/후 RGB는 의미 탐색을 맡는다. 보유하지 않은 IMU·리더암·손목 카메라를 필수 장비처럼 설정하지 않는다.
- D415가 주행 공간을 보는 자세에서 그리퍼/물체를 계속 볼 수 있는 카메라와 관측 지연을 먼저 확인한다. 불가능하면 운반 자세·카메라 배치/센서를 보완한다. 영상이 가려졌다는 이유로 load_retained를 유지하지 않는다.
- 실제 소파·침대·통로·리모컨 치수/무게와 카메라 장착 후보를 측정해 접근/높이/시야/그리퍼 공간을 확인한다. 간섭이나 도달 불가면 마운트·접근 방향·작업 위치를 먼저 수정한다. 원래 목표를 줄여서 통과 처리하지 않는다.
- 모델/원본 의존성 리비전, 코드·펌웨어·설정 hash와 원복 가능한 배포본을 보관한다. 물리 실행용 검증 절차와 축별 시험 진입점을 마련하되 자동 ARM/homing/이전 작업 재개는 금지한다.

**통과:** 장치 목록·실행 환경 고정, 중복 ID/전원 문제 없음, 기구 검토상 대표 물체의 집기/놓기 후보가 존재함. H2/H3/H5에서 실제로 성립하는지 확정한다. 환경 미확정 상태로 모든 노드를 한꺼번에 이식하지 않는다.

### H1. 베이스·공유 버스·기본 정지

**진행:** 2026-10-04 바퀴 배치·회전 방향·3륜 이동 조합과 v4 브라우저 텔레옵 동작을 사용자 확인했다. 아래 실측/고장 시험까지 포함한 H1 전체 통과는 아직 아니다.

- 바퀴를 지지한 상태에서 개별 방향/속도 단위/피드백을 확인하고 순수 전후·횡이동·회전을 시험한다. 명령 echo 대신 실제 wheel feedback으로 odometry를 만든다.
- 팔 tick·wheel/lift writer·READ가 함께 있을 때 wire time·turnaround·timeout·최대 관측 나이를 실측해 버스 예산을 설정한다. STM32만 UART를 소유하며 별도 LeRobot Host를 동시에 붙이지 않는다.
- 통신 단절·누락/늦은 응답·host 종료·재부팅·오래된 명령에서 zero 전송과 실제 바퀴 정지를 구분한다. 재연결/재시작 시 자동 이동하지 않아야 한다.
- 추후 H2/H3의 하중 유지 확인을 합쳐 전체 정지를 검증한다. 바퀴 정지만 확인하고 전체 로봇 정지가 완료됐다고 하지 않는다.

**통과:** 방향/단위/odometry 기본 검증, 시간 예산 내 피드백, 장애 시 정지·재명령 차단. 지상 주행용 속도/제동 거리 후보를 기록한다.

### H2. 리프트·원점·독립 지지 증거

- 기구를 지지한 상태에서 명시적 torque-off 유지보수·mode provisioning/readback → disabled 새 boot → 신선한 관측 → 별도 homing 순서로 시험한다. 일반 부팅에 EEPROM 변경·자동 하강을 넣지 않는다.
- 높이/회전 변환, encoder wrap/점프, 상하 끝점·기구 여유, homing 반복성/timeout/오탐, 속도별 제동 거리와 정지 후 처짐을 측정한다. 현재 접근 감속 코드를 실측 제동 모델로 보완한다.
- 무부하 다음 실제 팔·물체 하중에서 유지/정지를 확인한다. 속도 0·TX 완료·torque off를 하중 지지로 간주하지 않는다. 통신/전원 상실 대응이 부족하면 지지 기구/전원 구성을 보완한다.
- 실제 interlock/hold 증거를 기존 lift·stop 입력에 연결한다. 시험용 지지 상태와 자율 운용에서 가능한 지지를 구분한다.

**통과:** 원점/높이/경계·제동 허용치, 지정 하중 유지, 오류 시 원점 폐기·재구동 차단. 실측 기록으로 lift profile 생성.

### H3. 팔·카메라·실측 관측과 충돌 장면

- 좌우 관절 영점/방향/기계 끝점·배선 여유를 저속으로 측정한다. 예전 작업의 **관절 범위**를 새 기구에서 확인된 범위로 갱신하고 raw/model/ROS/펌웨어 설정을 함께 생성·검사한다. 고정 Z 제한을 푸는 작업으로 대체하지 않는다. 팔 베이스 아래 집기도 실제 자기/환경 충돌을 통과해야 한다.
- 리프트 높이별 base/lift/팔/카메라/그리퍼 TF와 collision geometry, 실제 joint_states를 연결한다. jaw 각도→간격·open/close 방향을 보정한다. 기존 고정 작업대 변환을 복사하지 않는다.
- arm/base/localization/lift/scene driver 출력을 EvidenceProducer에 연결하고 원 취득 시각·boot/profile·sequence를 보존한다. ROS 생산/소비와 AE/AF 입력을 실측 상태로 검증한다. 장치 누락을 임의 true로 채우지 않는다.
- 실제 scene의 단일 writer·revision, 물체별 attached/detached, fresh stage pose, 독립 reach/collision 검사 제공자를 구현·연결한다. ResidentRouteBuilder의 validator는 **전체 경로**를 현재 장면에서 검사해야 한다. 이 연결은 아직 끝난 소프트웨어로 간주하지 않는다.
- 카메라 정렬·깊이 단위·노출 TF·팔 가림을 확인하고 실제 소파/침대 RGB-D를 저장한다. 기존 ONNX 인식 계약을 실행 기준선으로 활용하고, U1의 VLM/영상 내 대상 위치 추정과 결합할 입력·출처를 기록한다. 개발 영상과 최종 평가 영상을 물체 인스턴스·수집 세션 단위로 분리한다.
- 전체 zero→양팔/lift hold의 후속 관측을 실제로 확인한다. 취소·tracking fault·관측 상실·재부팅 후 제어권을 성급하게 해제하지 않는다.

**통과:** 실측 설정·TF·관측 공급, 저속 범위/자기 충돌·그리퍼 검증, 전체 정지/하중 증거 연결. 카메라에서 본 대표 목표를 실제 팔 좌표와 대조할 수 있음.

### U1. VLM 요청 해석·추가 학습 없는 물체 판단

**선행:** 평가 설계는 지금 시작하고 실영상 평가는 H3 카메라·TF 기록을 사용한다. H6 완료를 기다리지 않는다. **현재 상태:** 미구현/모델 미선정.

- 자연어의 대상 종류·속성·출발/도착 장소를 정형 요청으로 바꾼다. 기존 `object_id`/MissionCatalog 계약은 종류 표현과 장면의 개별 물체를 동일시하지 않도록 adapter를 설계한다. 현재 고정 class ID ONNX 계약이 열린 어휘 인식까지 지원한다고 간주하지 않는다.
- 사전학습 VLM에 더해 필요하면 열린 어휘 탐지/분할 모델로 영상 내 대상 위치를 찾는다. 전체 장면 설명, 후보 ROI/마스크, 물체 식별, RGB-D의 3D 위치를 분리한다. ‘소파에 리모컨이 있다’는 문장만으로 집기 좌표를 만들지 않는다.
- 개발에 쓰지 않은 리모컨 외형, 휴대폰/계산기 같은 유사 물체, 복수 리모컨, 대상 없음, 부분/완전 가림을 평가한다. 새 인스턴스와 새 종류를 구분하고, 프롬프트/예시/참조 사진 제공 여부를 기록한다. 평가 물체를 보고 프롬프트를 고친 결과는 개발 결과로 돌린다.
- 후보 수용/재관측/사용자 질문/보류 조건을 정의한다. 모델의 자기 확신 문장이나 원시 점수를 정답 확률로 취급하지 않는다. 임계값은 개발 세트에서 오수용·누락·보류의 관계를 보고 고정하고 최종 평가에 적용한다.
- 정지 후 가까운 D415 관측으로 후보를 재확인한다. 시야 밖·가림·invalid depth·오래된 TF에서는 좌표 실행을 보류한다. 문장 의미와 물체 접근 가능성은 서로 다른 검사다.
- 모델/가중치/프롬프트/입력 크기/양자화·실행 위치와 지연·메모리·실패를 기록한다. 추론은 제어 주기를 막지 않으며 지연된 결과는 촬영 시각·장면 revision으로 폐기한다. 외부 추론을 쓰면 왕복 지연·연결 상실·영상 전송 범위도 조건에 포함한다.

**통과:** 고정 평가에서 종류/인스턴스 선택·영상 위치·3D 위치 오류를 구분해 보고하고, 잘못된 후보의 수용률과 보류율이 사전 기준을 충족한다. 실제 추가 학습 없이 대표 물체 후보를 찾고, 모호하거나 없는 경우 유한하게 처리한다. 인식 성공을 집기 성공으로 세지 않는다.

### M1. 2D SLAM과 RGB/RGB-D 의미 메모리

**선행:** H3의 카메라/TF/시각, H4의 위치 추정 기준선. 초기에 저장 영상·기록 pose로 시험 가능하다. **현재 상태:** 지도 revision/등록 장소 계약은 있으나 자동 시맨틱 매핑은 미구현.

- 기본 구성은 2D LiDAR 위치 지도 + depth 기반 주행 장애물 + 가구/물체 의미 메모리의 세 층이다. 먼저 등록된 방의 소파/침대와 물체 후보를 같은 map frame에 연결한다. 의미 메모리는 관측 출처·시각·위치 오차·상태를 가진 항목이며 정교한 전역 3D mesh를 요구하지 않는다.
- 전·후 RGB는 장소/물체 종류와 관측 방향의 가설을 만든다. 깊이 없는 단일 영상은 정확한 3D 점으로 저장하지 않는다. D415의 유효 depth 또는 보정된 다중 시점 기하를 확보했을 때 좌표화하고, 측정이 없는 동안에는 방/가구 관계·시선 가설로 남긴다.
- 노출 시각 TF, lift 높이, 카메라 외부 보정, 위치 추정 오차를 함께 기록한다. 같은 프레임을 반복 본 결과를 독립 증거로 세지 않으며 동일 물체 연결·복수 물체 오병합/중복을 검사한다.
- 가구/물체 이동 시 새 관측과 기존 항목의 관계를 재평가한다. 안 보였다고 즉시 삭제하거나 오래된 위치로 집으러 가지 않는다. map revision 전환·재위치 추정 시 의미 항목을 재변환/재검증하고 해결되지 않은 항목은 보류한다.
- **인식/의미 정확도:** 수동 검수한 종류/인스턴스/가구 관계와 대조한다. **지도 좌표 정확도:** 측정한 참조 위치와 비교한다. 참조 측정이 없다면 반복 관측 일치도만 보고하며 절대 위치 정확도로 부르지 않는다.
- **SLAM 정확도:** 같은 센서 기록·경로의 위치 기준선과 별도로 비교한다. 의미 정보를 실제 위치 추정에 사용하지 않았다면 SLAM 향상을 주장하지 않는다. 초기 목적은 검색할 장소와 후보의 재발견 효율 개선이다.

**통과:** 서로 다른 시점의 소파/침대·리모컨 관측을 출처와 함께 조회할 수 있고, 중복·오병합·이동·오래된 항목을 평가할 수 있음. 등록 장소만 사용한 기준선 대비 의미 메모리의 탐색 효과와 비용을 보고한다. 기대한 개선이 없으면 그 결과도 남긴다.

### Q1. 관측·집기를 위한 정차와 유한 재탐색

**선행:** H3 관측/도달 모델, H4 주행, H5 실제 집기 가능 범위, U1 후보 판정. M1이 아직 연결되지 않은 개발 단계는 등록 장소로 시험한다. **현재 상태:** 등록된 유한 시점 재탐색 코어는 있으나 통합 정차 최적화는 미구현.

- 탐색용 관측 위치와 집기용 정차 위치를 구분한다. 처음부터 물체의 정확한 위치를 안다고 가정하지 않는다. 넓게 볼 위치에서 후보를 찾은 뒤 가까운 관측과 집기 접근으로 전환한다.
- 후보는 베이스 x/y/yaw, 관측 또는 작업 lift 높이, 사용할 팔을 함께 나타낸다. 초기에는 실측 검증한 소수 후보를 쓰고 범위가 확보된 뒤 생성 후보로 확장한다.
- 집기 후보는 **주행 경로·전신 여유·제동/시야 → lift 범위·지지 → 팔 도달/IK·전체 충돌 → 대상 가시성·유효 depth**의 필수 조건 검사 후 점수를 비교한다. 대상 발견 전 관측 후보에는 주행·관측 자세의 실행 가능성과 예상 시야를 적용하고, 아직 없는 대상 좌표·IK·depth를 요구하지 않는다. 충돌하는 가까운 후보가 좋은 점수로 선택되지 않게 한다.
- 가능한 후보끼리 이동·리프트·추가 관측·재정렬의 예상 시간, 목표 가시성, 도달 여유, 실측 실패율을 비교한다. 가중치/성공 확률이 측정되지 않았으면 고정 규칙의 기준선부터 쓴다. 도달 가능성만으로 집기 성공 확률을 확정하지 않는다.
- 선택 근거와 탈락 사유를 기록한다. 정차 후 위치 오차·새 RGB-D·scene·대상 동일성을 다시 검사한다. 기구학상 가능했던 후보가 실물에서 실패하면 소수 대체 후보로만 재시도하고 예산을 넘기지 않는다.
- 미발견이면 이미 관측한 영역/시점, 가림, 예상 추가 정보, 이동 비용으로 다음 후보를 고른다. 무작위 이동을 기본으로 하지 않으며 모든 허용 시점에서 못 찾으면 미관측 영역과 종료 사유를 보고한다.

**통과:** 고정 waypoint/가장 가까운 가능 후보와 같은 배치에서 비교해 정차 후 집기 성공, 재정렬, 탐색/전체 시간의 변화를 측정한다. 선택된 pose의 실행 가능성과 정지 후 재검증을 실물로 확인한다. 보지 못한 목표나 도달 불가 목표를 성공으로 반환하지 않는다.

### H4. Nav2 주행·재탐색 위치·정차

**선행:** H1, 운반 중 팔/lift가 유지되는 H2/H3의 확인. H5 집기와 구동 시간을 나눠 진행한다. 초기에는 등록 waypoint로 주행만 검증하고, 작업용 정차 선택은 Q1에서 확장한다.

- 먼저 주행 자세의 D415 커버리지·진동·낮은/높은 장애물·near blind spot·후진/횡이동 사각을 검증한다. base/lift 정지→운반 높이/팔→새 depth epoch/관측→이동 순서를 확인한다. 시야 부족이면 마운트/보완 센서를 먼저 수정하고 속도 최적화를 진행한다.
- 베이스 단독 방향·거리/회전 odometry → LiDAR 지도/위치 추정 → Nav2 왕복 → 반복 정차 순서로 검증한다. 실제 footprint·팽창 여유·운반 자세·제동 거리를 반영한다.
- 소파/침대 접근점과 유한한 재관측 위치·리프트 높이를 등록한다. Nav2와 미세 정렬기는 베이스 명령 소유권을 공유하며 동시에 쓰지 않는다. 도착 결과 다음 실측 정지를 확인한다.
- 책상을 A→B로 옮겨 B 회피, A의 상판 기억 유지/깊이 재관측 삭제, 재위치 추정을 시험한다. 2D LiDAR가 상판을 삭제하지 못해야 한다. 기준 map은 지속 변경 확인 뒤 정지→revision 교체→catalog 재검증→재위치 추정 순서로 갱신하며 매 프레임 저장하지 않는다.
- 좁은 통로·경로 차단·위치 추정 상실·scan/TF 지연·취소를 시험한다. 두 번째 LiDAR는 시각/TF를 맞추고 효과를 비교한 뒤 적용한다.
- 실측 정차 오차를 팔 도달/카메라 시야와 비교하고 미세 정렬을 보정한다. 방향/속도뿐 아니라 횡미끄러짐·실제 바닥 영향을 기록한다.

**통과:** 대표 장소 왕복·정차 허용치와 유한 실패/취소. A1의 실물 이동 검증을 시작할 수 있다.

### H5. 정지 플랫폼에서 실제 집기·놓기

**선행:** H2/H3. 초기 시험에서 베이스를 고정하며 H4 완료를 기다릴 필요는 없다.

- 쉬운 지정 면에서 `PickPlacePort`의 집기 6단계·놓기 5단계를 실제 공유 팔/그리퍼, fresh stage observation, MoveIt 장면에 연결한다. factory 미주입 상태의 접근 계획 전용 경로를 전체 집기로 취급하지 않는다.
- 그리퍼 열기 → 접근 → 닫기/집힘 → scene attach/readback → 하중 유지/후퇴와, 목적지 접근 → 해제 → detach/readback → 후퇴/배달 확인을 각각 검증한다. 물체 크기·link/world pose·touch links를 실측한다.
- 그리퍼 미집기/빈 집기·운반 중 미끄러짐·낙하·미해제·scene 응답 유실·단계별 취소에서 실제 결과를 구분한다. 부족한 관측은 새 센서 또는 재관측 절차로 해결한다.
- 다음으로 실제 소파와 침대에서 깊이/가림·리모컨 두께/방향·쿠션/매트리스 변형·진입/후퇴 여유를 확인한다. SurfaceObserver의 평면 통과만으로 놓기 성공을 보고하지 않는다.
- 운반 자세·하중·베이스/lift 상태에 맞는 허용 동작과 전체 충돌 검증을 확정한다. 팔 품질은 아래 기준으로 함께 조정한다.

**통과:** 실제 대표 물체를 사람의 위치 보정 없이 집고 유지하고 지정 영역에 놓는 동작, 관련 실패/취소 검증. 주행 없이 먼저 성공 경로를 확보한다.

#### 팔 떨림과 시연 시간

PC 구현은 기존 어깨 P64/I0/D64·팔꿈치 P56/I0/D64 유지, 좌우 runtime 필드 일치, task waypoint 5차 시간 곡선, MoveIt Ruckig까지 완료했다. P16 후보는 철회했다. **실물 튜닝은 미완료**다.

- 사용자 증상인 접힌 팔이 일어나는 구간과 다시 접히기 직전을 같은 목표/하중/시작 자세로 재현한다. 실제 register, 목표/실측 궤적, 전류/전압·유격을 기록해 목표 자체의 떨림과 servo/기구 반응을 구분한다.
- 낮은 P의 하중 오차 이력을 고려해 기존 P를 기준으로 원인에 따라 D, 경로·가속/jerk를 한 변수씩 비교한다. 무조건 D를 높이거나 전체 팔을 감속하지 않는다.
- 총 이동+정착 시간, 추종 RMS/최대 오차, 정지 hold 진폭, 하중 유지를 함께 비교한다. `tools/run/analyze_arm_motion.py`를 사용하고, 위치 표본으로 못 보는 진동은 별도 관측한다.
- 허용 오차·하중·시간을 함께 통과한 값만 승격한다. 범위/추종 정지 기준을 느슨하게 만들어 통과시키지 않는다. 프로파일 변경 시 firmware/ROS hash와 회귀를 함께 갱신한다.

### H6. 전체 배달·실물 실행 구성

**선행:** H4 + H5 및 전체 정지 검증. 먼저 등록 목표로 통합 기준선을 만들고, 최종 단계에서는 U1/M1/Q1의 최소 검증 기능을 순서대로 연결한다.

- 실제 Nav2·MoveIt·센서·MCU·관측/scene 제공자를 동일 runtime에 조립한다. 단일 UART/scene 소유권, 실제 launch/config·시작/종료 순서, 모델/보정 누락 차단을 구현한다.
- 현재 `RobotApplication`의 physical 차단은 그대로 우회하지 않는다. H1–H5의 축별/정지 플랫폼 시험 경로와 구분된 **검증용 전체 실물 실행 경로**를 만들고, 측정 profile·장치 식별·원점·신선한 상태·정지 준비를 확인한 뒤 명시적으로 시작하게 한다. 검증 없이 simulation 플래그만 바꿔 실물을 허용하지 않는다. 일반 사용자 실행 승격은 E1 뒤다.
- 짧은 이동을 포함한 지정 면 배달 → 실제 소파→침대의 15단계로 확장한다. 이동/리프트 변경 후 재관측, 주행 중 운반 자세·하중, 조작 중 base/lift 정지를 계속 감시한다.
- 정면 미발견→다른 시점 발견, 완전 가림, 대상 없음, 접근 불가를 구분한다. 현재 기본 탐색 후보 32개·시점당 촬영 2회(상한 3회)·탐색 120초·전체 300초는 **PC 후보값**이다. 실제 측정으로 재시도/시간 예산을 정하고, 시연 목표 시간과 timeout을 구분한다.
- 모든 단계의 취소·통신/센서/위치 추정 상실·재부팅·물체 상실을 시험한다. stop 확인 전 소유권 해제/다음 작업 금지, 새 disabled boot·재원점·상태 확인 후 명시적 복구, 이전 작업 자동 재개 금지를 유지한다.

**통과:** VLM 요청·대상 판단, 관측 기반 의미 메모리와 정차 선택을 포함한 실제 배달의 독립 증거·구간별 시간·판단 기록. 실패/취소/보류/복구를 포함해 E1을 평가할 수 있음. 등록 좌표만 쓴 중간 성공은 별도 집계한다.

### E1. 반복 평가·시간 최적화·운용 승격

**평가 계획은 U1/H3 시작 시 작성하고, 최종 평가는 H6 뒤 수행한다.** 다음 공통 규칙을 적용한다.

- 개발/조정 세트와 최종 평가 세트를 물체 인스턴스·공간 배치·수집 세션 단위로 나눈다. 같은 영상의 연속 프레임을 양쪽에 나눠 일반화로 보고하지 않는다. 추가 학습은 우선 하지 않되 프롬프트·임계값 조정도 개발에 해당한다.
- 정답은 수동 물체/종류/위치 주석과 측정 가능한 실제 배달 결과로 만들고 불명확한 표본은 별도 표기한다. 판단에 쓰는 같은 VLM을 유일한 채점자로 쓰지 않는다.
- 단일 영상 판단 / 영상 내 대상 위치 추정과 VLM 교차 확인 / 다중 시점 확인, 등록 장소 / 단일 관측 / 의미 메모리, 고정 정차 / 가까운 후보 / Q1을 각각 같은 배치·시간/재시도 예산에서 비교한다. 한 번에 한 요소를 바꾸고 모델·프롬프트·추론 위치를 고정한다. 모델을 바꾼 비교는 별도로 표시한다.
- 시도 수·성공 수·보류·질문·개입·timeout·잘못된 집기와 각 실패 원인을 함께 집계한다. 보류/사람 도움을 분모에서 빼지 않는다. 인식 후보를 수용한 비율과 그중 정확한 비율을 함께 보고해 전부 보류하는 방식의 과대평가를 막는다.
- 조건별 성공률과 불확실성 구간, 전체/구간 시간 p50·p95를 보고한다. 물체가 실제 없는 평가에서는 ‘예산 내 미발견’과 ‘부재 확인’을 구분한다. 작은 표본의 결과를 모든 환경으로 확대하지 않는다.
- 작업 ID로 요청/프롬프트/모델, 영상·노출 시각·TF, 지도 revision, 후보와 수용/거절 이유, 선택한 base/lift/팔, 단계 결과·수동 정답·개입을 연결한다. 원본 기록과 재생 가능한 최소 사례를 보존한다.

평가 전에 아래 표의 후보를 측정 가능한 수치로 고정한다. 시험 결과를 본 뒤 실패 사례를 빼거나 기준을 완화해 통과시키지 않는다. 기본 제안은 **지원 조건의 배달 20회 중 18회 이상 무개입 성공**이며, 아직 합의된 실기 성능이나 달성 결과는 아니다.

| 장애/취소 | 각 단계 취소, 관측/통신 손실, reboot·낙하·scene 불일치·회복 | 정의한 정지 시간/거리·하중 유지, 의도치 않은 재구동/성공 오보고 0건 |
| 운영/재현 | 목표 보드 동시 부하·열/전원·USB, 여러 작업/재시작, 고정 버전 설치·원복 | 제어/관측 시간 예산 유지, 재시작 뒤 자동 ARM/homing/작업 재개 없음 |

먼저 불필요한 대기·중복 촬영/계획·과도한 정착을 줄이고, 그다음 측정된 추종/정지 여유 안에서 속도·가속/jerk를 조정한다. 총 시간 목표를 못 맞추면 G1의 시연 품질은 미완료로 남긴다. 성공률/안전을 희생해 시간만 맞추지 않는다.

E1을 통과한 코드·펌웨어·모델/프롬프트·보정·지도 revision·평가 조건과 결과를 묶어 G1/G2의 적용 범위를 고정한다. 새 정차/인식/매핑 방식이 항상 우수할 필요는 없지만, 최종 채택 근거와 유효한 조건·실패 범위는 남겨야 한다. 일반 실물 요청 경로의 승격, 설치/재시작/원복 절차, 원격 CI 확인까지 마친다. 임시 의존성 경로나 현재 MoveIt 종료 우회가 필요한 경우 목표 환경에서 재현하고 배포에 명시한다.

## 4. 확장 사용자 기능

### A1. 휴대폰 입체 지도에서 지정 지점 이동

- 기존 브라우저 UI·HTTP gateway를 재사용한다. H4 이후 실측 주행 지도와 표시 지도의 frame/floor/revision을 연결하고, 실제 Nav2/정지 관측 adapter로 검증한다. 현재 simulation 전용 제한을 검증 없이 제거하지 않는다.
- 입체 점유 지도에서도 주행 목표는 바닥의 x/y/yaw다. 클릭 위치·방향을 미리 보여주고, 가구 위 클릭/지도 교체/오래된 permit/경로 불가를 거절한다. 실측 mesh/점군은 표시 품질 확장이며 첫 기능 완료를 막는 조건으로 삼지 않는다.
- 실제 휴대폰에서 LAN/TLS·인증/페어링·토큰 폐기·상태/취소·재연결을 확인한다. 기본 loopback에서 외부 연결로 바꾸는 것은 별도 검증이다. 배달 중 지도 요청·중복 요청·서버 재시작에 기존 소유권/복구 규칙을 적용한다.
- 네이티브 앱 패키징은 별도 선택 사항이다. 첫 완료는 **휴대폰 브라우저에서 실제 지도 선택→이동→취소**이며, 같은 API를 나중에 네이티브 앱에서 사용할 수 있게 유지한다.

**G3 완료:** 지정점 실제 정차 허용치, 경로 차단/위치 추정 상실/재연결/제어권 충돌 검사 통과. H4 뒤 제한된 검증을 시작하고 E1 운영 기준으로 일반 사용을 승격한다. VLM은 필요하지 않다.

## 5. 문서 운영과 다음 작업

- 이 문서는 우선순위·의존성·통과 기준의 단일 목록이다. [CURRENT_STATUS](CURRENT_STATUS.md)는 실제 구현/시험 결과, [ARCHITECTURE](ARCHITECTURE.md)는 통신/상태/단위/제한 계약, [hardware/README](../hardware/README.md)는 장비/실측 근거를 유지한다. 날짜별 개발 메인 문서는 추가하지 않는다.
- 상세 bag/영상/시험표/측정 기록은 코드·보정·모델/지도 ID를 붙인 산출물로 남긴다. H0에서 허용치·횟수·하중·시간의 초안을 잡고 해당 단계 평가 전에 고정한다.
- 바로 다음은 H2 리프트 시험, H1 남은 측정, H3 영상/TF 수집 준비다. U1/M1/Q1은 새 방향에 필요한 개발로 관리한다. 문서 수정만으로 구현 완료를 표시하지 않는다. 커밋·푸시·PR 생성은 사용자가 직접 실행한다.

### 일반화 목표의 경계

대표 배달에서 새 인스턴스·새 배치·가림·가구 이동에 대한 결과를 먼저 제시한다. 등록된 방의 의미 메모리와 유한 시점 탐색이 미지의 집 전체 탐색을 완료했다는 뜻은 아니다. ‘집 안 모든 빨래를 찾아 미지의 빨래통에 넣기’는 변형체 집기, 탐색 범위·수거 종료, 중복/가득 참 판정이 추가로 필요한 별도 확장이다. 현재의 VLM·의미 지도 평가를 그 능력의 증거로 확대하지 않는다.
