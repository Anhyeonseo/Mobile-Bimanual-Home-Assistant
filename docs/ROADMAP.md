# 개발 로드맵 — 온디바이스 전체 작업 최적화

기준일: 2026-11-16 · 사용자와 합의한 개발 방향. 구현·실물 완료 보고는 [현재 상태](CURRENT_STATUS.md)에 둔다.

## 최종 목표

**로봇 안에서 사용자의 요청을 실제로 끝내고, 전체 대기 시간과 중간 개입을 줄인다.**
TF·캘리브레이션, 인식 모델, 집기 후보, 경로 계획, 주행은 이 목표를 위한 수단이다.
기술 도입이나 개별 모듈의 정밀도 자체를 성과로 삼지 않는다. 변경마다 실제 성공률,
전체 시간, 사용자 개입 중 무엇을 개선하는지 설명하고, 근거가 없으면 우선순위를 주지 않는다.

최종 사용 시 언어 처리·관측·계획·실행에 필요한 계산은 로봇의 온보드 장치에서 끝낸다.
개발·학습·분석에 PC를 사용할 수 있지만, 외부 PC나 클라우드가 작업 수행에 필수이면
온디바이스 완료로 표시하지 않는다. 사용자 입력 화면이 다른 기기에 있는 것과 계산 의존은 구분한다.
현재 PC 언어 모델과 대화 중 수동 후보 선택은 이 목표까지 해소할 의존이다.

## 전체 시간과 평가

```text
요청 이해·필요한 확인 → 대상 위치로 이동 → 관측 → 정차·집기 결정
→ 집기·집힘 확인 → 운반·놓기 → 실제 결과 확인·응답
```

전체 시간은 요청 접수부터 완료 또는 실패 안내까지의 경과 시간이다. 계산·동작뿐 아니라
정지 후 관측 대기, 반복 보정, 재계획, 복구, 사람의 응답 대기도 포함한다. 사용자 확인에
걸린 시간은 따로 표시해 로봇 처리 시간과 구분하되 전체 시간에서 숨기지 않는다.
동시에 실행한 구간의 시간을 중복 합산하지 않는다.

| 평가 항목 | 기록과 판단 |
|---|---|
| 실제 성공률 | 시도 수와 성공 수, 물체가 실제로 집혀 지정한 곳에 놓였는지. 실패·보류·도움 요청을 분모에서 빼지 않음 |
| 전체 완료 시간 | 성공 작업의 중앙값과 느린 사례, 실패 종료 시간. 표본 수가 충분할 때 P90도 기록 |
| 중간 개입 | 최초 요청·실행 확인 이후의 후보 선택, 수동 정렬, 물체 이동, 복구 도움 횟수와 이유 |
| 실패 사용성 | 원인에 맞는 유한 재시도, 필요한 도움의 구체성, 실제 상태와 안내의 일치 |

첫 자동 수행에서 기준값을 얻은 뒤 지원 조건별 시간 목표·성공률·시도 수를 정한다.
현재 합의된 초 단위 목표나 성공률 수치는 없다. 설정된 timeout은 사용자가 만족할 목표 시간이 아니다.
성공률을 낮추거나 필요한 상태 확인을 없애 시간을 줄인 결과는 개선으로 채택하지 않는다.

기존 실행 로그와 시간 필드를 우선 재사용하고, 구분할 수 없는 병목에만 최소 계측을 보탠다.
변경 전후는 같은 물체·배치·시작 조건에서 비교하고, 조정에 쓰지 않은 반복에서도 확인한다.
이미 필요한 검사가 통과했다면 새 변경·실패·의문 없이 같은 시험을 반복하지 않는다.

## 해결할 문제와 선택 기준

| 문제 | 현재 근거 | 반영 방향 | 확인할 결과 |
|---|---|---|---|
| TF·캘리브레이션 | 모델상 접촉점과 사용자가 본 실제 손가락 위치가 다름. 모터 값은 고정 영점·비율로 모델 각도에 연결됨 | 실제 위치 반복성과 모델 오차를 구분. 기존 보정·접촉 측정 도구로 일정 오차와 자세·접근 방향 의존 오차를 분리 | 수납장 작업 범위에서 필요한 접촉 위치에 반복 도달 |
| 집기 후보·자세 | 6DOF 후보를 5DOF 팔에 맞추고 여러 전체 경로를 비교. 고정면 보완은 구현됐으나 실물 정합 미검증 | 고정 손가락 접촉면·접근 방향·닫힘 공간을 앞단에서 제한. 소수 후보부터 평가. GraspNet·MoveIt 유지/교체는 전체 시간과 성공률로 판단 | 자동 선택한 후보로 실제 집기, 후보·계획 시간 감소 |
| 베이스 정차 | 이동은 확인됐으나 작은 XY 보정이 수렴하지 않은 기록 | 가장 정밀한 정차보다 이후 집기가 가능한 정차를 선택. 새 관측과 팔 도달성으로 처리 가능한 잔차는 허용하고 필요한 보정만 수행 | 반복 왕복 감소, 이동 후 집기 성공, 정렬 시간 감소 |
| 오른팔 응답 | 주행 중 간헐 응답 문제와 마지막 접근 중 읽기 오류 정지 | 전원·배선·통신 처리 원인을 구분. 조회와 제어가 충돌하는지 확인하고 원인에 맞게 수정 | 필요한 상태 확인을 유지하며 작업 중단·재준비 감소 |
| 전체 타임라인 | 단계별 도구는 있으나 대화·수동 후보 선택·준비 연결이 개입. 실제 전체 작업 시간 기준값 없음 | 대기·중복 촬영·후보 탐색·재계획·복구 중 가장 큰 비용부터 제거. 유효 조건이 유지되는 결과는 재사용 | 요청부터 결과까지 시간·개입 감소 |

베이스 보정에는 이미 시간·횟수·개선 부족 시 중단 조건이 있다. 한도를 새로 추가하는 것과
실제 구동 특성·관측 편차에 맞게 수렴을 개선하는 것을 구분한다. 현재 후보 생성에도
형상·관절 샘플링과 비용 정렬이 있으므로 LLM이 모든 후보를 생성한다고 설명하지 않는다.

현재 근거가 있어 함께 해결할 항목은 두 가지다.

- **실제 성공 판정:** 관절의 들기 완료와 물체 집힘이 달랐던 기록이 있다. 기존 영상·그리퍼 피드백으로 확인 가능한 범위를 정하고, 미확인 상태를 성공으로 넘기지 않는다.
- **사람·외부 PC 의존 제거:** 실행 중 후보 선택과 준비 파일 연결을 자동화하고, PC 언어 모델 등 필수 계산을 온보드 환경에 연결한다. 개발용 원격 분석과 제품 실행을 구분한다.

그 밖의 가능성만 있는 문제는 필수 작업으로 늘리지 않는다. 실제 실패나 측정된 병목이
나오면 근거·사용자 영향·필요한 변경을 기록하고 추가한다.

## 현실적인 허용 오차

실제 하드웨어에서 달성 가능하고 작업을 성공시키는 오차 범위를 사용한다.
0.02mm 같은 수치를 측정 근거 없이 실물 도달 조건으로 요구하지 않는다. 이 수치는
과도한 기준의 예이며 현재 코드 전체가 그 기준이라는 뜻은 아니다.

- 센서 편차, 실제 구동 반복성, 물체·지지면·손가락의 여유를 근거로 정한다. 상대 오차율만 쓰지 않고 필요에 따라 mm·도·시간 단위로 명시한다.
- 주행 정차, 접촉 위치, 집게 닫힘, 관절 추종, 데이터 시각의 기준을 목적별로 나눈다. 베이스 잔차가 있어도 검증된 관측·도달 범위 안에서 집기가 가능하면 추가 정렬을 끝낸다.
- 계산 수렴 허용치·명령 분해능·화면 표시 자릿수와 실제 정확도를 구분한다. 작은 수치가 있다는 이유만으로 전부 완화하지 않는다.
- 현재 기준이 정상적인 편차를 실패로 처리하는지 확인하고, 변경 전후의 성공·오거절·실패 감지를 비교한다. 모터 각도 반복만으로 실제 손가락 반복성을 대신하지 않는다.
- 근거가 부족하면 미측정으로 남긴다. 여러 기준의 여유를 따로 늘려 최종 접촉 오차가 커지지 않도록 함께 본다.

각 기준은 담당 설정이나 기존 측정 보고에 **목적·값/단위·측정 조건·근거·적용 범위**를 남긴다.
별도 승인 문서나 기준 등록 시스템을 새로 만들지 않는다. 충돌·한계 초과·실제 통신 고장을
품질 편차와 구분하고, 시험 통과를 위해 오류를 숨기지 않는다.

## 개발 순서

| 단계 | 범위 | 완료 판단 |
|---|---|---|
| 1. 수납장 앞 고정 위치 | TF·실제 접촉 오차와 통신 문제 확인, 관측→후보 결정→집기→집힘 확인 자동 연결 | 검증된 작업 범위에서 반복 집기. 사람의 후보 선택 없이 한 사이클 종료. 실제 오차·시간·개입 기록 확보 |
| 2. 수납장 앞 좌우 이동 | 이동 후 관측·정차 판단·집기 연결 | 이동 후에도 집기 성공 유지. 필요한 보정만 수행하고 사람이 베이스를 맞추지 않음 |
| 3. 지정 목적지까지 전체 작업 | 요청 처리·운반·놓기·결과 확인 및 온디바이스 실행 | 지원 범위의 요청을 외부 계산·중간 수동 연결 없이 완료하고 합의한 시간·성공률 충족 |

이번 주 우선 결과는 1단계의 캘리브레이션 근거와 고정 위치 자동 집기다. 좌우 이동은 그다음
연결 지점이다. 실패한 기준을 완료로 바꾸거나, 모든 환경의 보정을 이번 주 선행 조건으로 만들지 않는다.
시간 측정과 중복 제거는 1단계부터 수행하며 마지막 단계로 미루지 않는다.

수납장 기준 시험은 범위를 좁힌 첫 검증이다. 물체 위치·방향의 검증 범위 안에서 관측을
사용하며 특정 리모컨 좌표나 저장 관절 재생만으로 자동 집기·일반화를 주장하지 않는다.
성공한 흐름을 다음 단계에서 재사용하고 새 실행기를 단계마다 만들지 않는다.

## 보류 범위와 문서 운영

집 전체 자동 탐색은 배터리 전에는 미룬다. 음성, 손 전달, 동시 양팔 작업, 다중 작업 큐,
임의 물체 범용 집기는 이번 수납장 목표의 선행 조건이 아니다. 지도·자율주행처럼 이미
확인한 기능은 통합에 필요한 부분을 재사용하고 새 기술 도입을 위해 다시 만들지 않는다.

- 목표·우선순위·평가: 이 문서 한 곳에서 관리한다.
- 사용자 동작·구성·계층 경계: [제품 설계](MOBILE_MANIPULATION_DESIGN.md).
- 구현·실물 결과·마지막 상태: [현재 상태](CURRENT_STATUS.md).
- 상세 계약·실험 근거·운영 도구: [문서 안내](../README.md#문서-구조)에서 찾는다.

문서 정리는 작업 재개 승인이 아니다. 현재 로봇 작업은 중단 상태이며 과거 후보 승인으로
자동 재출발하지 않는다. 이전 로드맵은 [이력](history/DEVELOPMENT_ROADMAP_2026-10.md)에 보존한다.
