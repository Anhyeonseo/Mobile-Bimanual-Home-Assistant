# S2 좌표 연결 결과와 인계

2026-11-05 · 공식 ALOHA Mini 1 / SO-ARM101 양팔 / 고정 D415.

**합의한 개발 범위의 S2 좌표 연결과 정지 상태 실물 통합 검사를 완료했다.**
양팔 Home·리프트 최저점을 사용자 확인한 뒤 D415와 13축을 약 5초간 함께 조회했다.
61개 모터 샘플 중 초기 기준 샘플을 제외한 60개에서 촬영 시각에 맞춘 좌표 계산을 완료했다.
RGB-D·모터 시각 범위 최대 48.42ms, 모터 속도 0·토크 OFF·모터 쓰기 0회였다.
이는 명목 모델의 연결 검증이며, 실제 집기 오차·다양한 자세의 정확도·자율 동작 검증은 아니다.

현재 STM32는 `s2-observer-v1`이다. 플래시 검증과 기존 boot journal 보존을 확인했고
원본 백업은 젯슨에만 보관한다. 세션은 종료되어 실시간 원점은 더 이상 유효하지 않다.
완료 근거는 `config/home_assistant/s2_integration.observed.json`, 원시 보고서는
`output/home-assistant/s2/coordinates/integrated-20261105-04.json`이다.
설치·좌표 프로필의 기존 상태 플래그는 생성 당시 기록으로 보존했다. 최신 완료 상태는
별도 관측 근거와 `s2_coordinates.py audit`에서 판단하며, 검증한 프로필 해시를 변경하지 않는다.

## 데이터 흐름과 책임

1. **장치 조회:** `s2-observer-v1`은 양팔 각 6축과 왼쪽 버스 ID10 리프트만 읽는다.
   각 위치 읽기의 시작/종료 tick을 기록한다. 전송 계층에서 모터 쓰기·브로드캐스트·바퀴 조회를 거부한다.
2. **수집:** `s2_acquisition.Reader`가 응답 순서·모터 목록·호스트 시각 변환 구간을 검증한다.
   프로세스별 nonce는 STM32 재시작 시 사라져 기존 세션이 계속되는 것을 막는다.
3. **연속 엔코더:** `EncoderTracker`는 확인한 양팔 Home과 리프트 최저점을 기준으로
   짧고 연속적인 관측만 unwrap한다. 이는 관측 추적이며 짧은 회전 경로를 만드는 제어기가 아니다.
4. **촬영 시각 연결:** `s2_rgbd_acquisition`은 D415 장치/스트림/SDK 보정 해시를 확인한다.
   SDK `global_time`을 호스트 monotonic 시각으로 옮겨 RGB·depth·13축의 시각 차이를 검사한다.
   USB 수신 시각을 촬영 시각으로 대체하지 않는다. SDK 시각 변환이 물리적 하드웨어 동기화를 입증하는 것은 아니다.
5. **좌표 계산:** `ObservationSession`이 재시작·원점 변경·누락·오래된 관측·각도 점프를 거부하고
   캡처 시점의 양팔 TCP를 계산한다. `transform_report`는 DINO/SAM 결과에 같은 capture ID를 요구한다.
   추론이 늦게 끝나도 최신 팔 위치로 덮어쓰지 않는다.
6. **상위 계층:** 표면점만 전달한다. 파지 후보, 물체 접촉점, 충돌 확인, 궤적 실행은 S3 책임이다.
   기존 엄격한 `s2_commissioning`과 L3 실행용 entity 입력에는 명목 프로필을 통과시키지 않는다.

시각 차이 50ms, 관측 유효 시간 200ms, 추론 보고서 유효 시간 5초를 적용한다.
모터 샘플 간격 200ms 또는 256 counts 점프 한계를 넘으면 연속 기준을 잃은 것으로 처리한다.
전원/통신 단절 후 높이 기준을 추정해서 복구하지 않는다. 새 원점 확인은 초기화 절차이며 추가 정밀 실측 요구가 아니다.

[RealSense 공식 timestamp domain 문서](https://realsenseai.github.io/librealsense/python_docs/_generated/pyrealsense2.timestamp_domain.html)

## 검사 결과

- 관련 좌표·조회·양팔 보정·리프트 회귀 검사 169개 통과 후 RGB-D 시각 검사 2개 추가.
- PR 최종 전체 검사: **1,853개 통과 / 3개 스킵**. Git에 포함되는 파일만 복사한 깨끗한 환경에서도 재검증했다.
- 새 STM32 관측 펌웨어 빌드 성공: text 29,232 / data 104 / bss 11,304 bytes.
- 실제 C 파서의 잘못된 요청·재시작·모터 읽기 실패 검사와 양쪽 버스의 모든 1-byte 쓰기 조합 차단 검사 통과.
- 시각화는 736px 일반 화면과 360px 어두운 화면에서 확인했고 최고점·정면 버튼 동작을 검사했다. WebGL이 없는 환경에서도 CPU로 로봇 형상을 표시한다.
- 별도 URDF 트리 계산과 Python FK, JavaScript 뷰어의 양팔·리프트 계산 일치 검사 통과.
- 젯슨 배포 해시 검증 후 모터 단독 83회, 기준 자세 좌표 71회, RGB-D 통합 61개 모터 샘플/60개 좌표 계산 통과.
- 실물 검사에서 찾은 호스트 시간 변환·SDK 부동소수점·프레임 도착 지연을 수정하고 관련 검사 70개와 엄격한 실측 수락 경로 회귀 검사 55개, **총 125개 통과**.
  이후 PR 준비 과정에서 전체 모음도 재검증했다.
- STM32 시계를 최초 오프셋으로 고정하던 오류를 수정했다. 매 주기 INFO 왕복으로 시각 구간을 갱신하고
  5,000ppm 속도 차이 범위와 50ms 연결 기준을 별도로 검사한다. 리셋·불연속·긴 공백은 계속 거부한다.
- 같은 D415의 SDK translation이 약 9.31e-10m 달라져 해시가 바뀌었다. 장치·스트림·내부 파라미터·회전·depth scale은
  정확히 비교하고, translation만 2e-9m 이내의 표현 차이를 허용한다. 관측/기준 해시와 차이를 모두 저장한다.
- 먼저 도착한 RGB-D 프레임 대신 촬영 시각이 맞는 프레임을 최대 100ms 내에서 찾는다. 수신 시각을 촬영 시각으로 사용하지 않는다.

## 배포와 재검사 방법

최종 조회 프로그램:
`/home/hyper/robot/releases/s2-coordinates-b19a1295753b`

실제 펌웨어 전환은 `s2-coordinates-b1656ccfd291`에서 수행했다. 이후 변경은 호스트 프로그램뿐이며,
최종 릴리스의 펌웨어 해시는 적용된 펌웨어와 같다. 재플래시는 필요 없다.

기존 구동 릴리스나 현재 제어기를 자동으로 바꾸지 않는다.
`flash.sh`는 전원 OFF 확인 인자가 필요하고, 전체 펌웨어 백업·검증과
마지막 8KiB boot journal 보존 검사를 포함한다. 원본 백업은 젯슨에만 둔다.
이번 전환은 사용자가 모터 OFF를 확인한 뒤 완료했다.

이번에는 아래 세 단계를 모두 통과했다. 향후 재검사 때도 동일한 물리 기준이 필요하다.

1. 모터만 약 5초 읽어 13축 응답·조회 시각 폭·정지 상태를 확인한다.
2. D415를 함께 읽어 RGB/depth/모터 시각 연동을 확인한다.
3. 양팔이 저장한 Home이고 리프트가 실제 최저점일 때만 새 연속 기준을 잡고 라이브 좌표를 계산한다.
   조건이 다르면 임의로 원점을 지정하지 않는다. 이번 조회 도구는 자세를 옮기지 않는다.

```bash
cd /home/hyper/robot/releases/s2-coordinates-b19a1295753b
/home/hyper/robot/shared/venvs/room-scan-bag/bin/python tools/diagnostics/capture_s2_observer.py \
  --port /dev/serial/by-id/usb-STMicroelectronics_STLINK-V3_005100393235511438363730-if02 \
  --profile profile.json --seconds 5 --rgbd \
  --output /home/hyper/robot/shared/diagnostics/s2/observer/integrated-NEW.json
```

`--home-and-bottom-confirmed`는 두 물리 기준이 실제로 맞는 경우에만 추가한다.
기존 `room-scan-bag` 가상환경의 RealSense SDK와 NumPy를 재사용하고 `pyserial==3.5`만 추가한다.
종료 뒤 원점은 유효하지 않다. 현재 스크립트는 연속 실행 제어기가 아니라 제한된 관측 검사 도구다.

## 실제 운용으로 연결할 초기화

이번 도구는 짧은 검사마다 물리 Home·최저점 확인이 필요하다. 최종 운용 정책으로 확정한 것은 아니다.
지속 관측 서비스로 원점을 유지하고, 원점 센서/자동 homing 방식과 팔의 시작 각도 분기 식별을 구현해야 한다.
전원 OFF 중 손으로 움직일 수 있으므로 마지막 위치를 파일에서 읽는 것만으로 높이를 복구하지 않는다.
현재 조회 전용 펌웨어는 토크를 켜거나 리프트를 유지해주지 않는다.

## S3로 넘긴 사항

- 실제 집기에서 카메라 외부 보정과 양팔 TCP의 작업 오차를 확인한다.
- 집게 패드·대상 물체·벌림 정도에 따른 접촉점과 파지 깊이/힘을 설계한다.
- 베이스 정지 위치·리프트 작업 높이·충돌 없는 접근 경로를 고른다.
- 리프트 소음은 기존 최종 실물 이슈로 유지한다. 발생하지 않는다고 판정하지 않았다.
- LiDAR 장착과 지도 계층은 주행/매핑 단계에서 다룬다.
