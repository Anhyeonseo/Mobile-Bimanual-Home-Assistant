2026-11-13. 사용자 요청으로 S4의 남은 실물 작업을 보류하고 S5의 로컬 자연어
준비로 전환했다. S4 완료 판정은 변경하지 않는다. 최초 검토는 원격 코드와 격리된 파서 검사였다. 이후 아래 후속 구현에서 언어 파일을
선별 이식하고 로컬 GPU 추론·모의 앱 연결까지 검증했다. 젯슨 배포와 실물 실행은 하지 않았다.

표시한다. 모델이 금지문·복수 요청·손 전달을 누락해도 원문 범위 검사가 이를 보류한다.

모델 실행 위치는 요청 의미 계약과 분리한다. PC와 젯슨은 같은 의미/질문 계약을

응답 지연, 메모리, 인식/제어와의 동시 부하를 같은 평가셋으로 비교한다. 지금 특정

## 그대로 연결하기 전에 고칠 부분

실제 모델 출력 대신 명시한 JSON을 넣어 **후처리 코드만** 검사했다.
재현 입력과 결과는 `review.json`에 저장했다.

1. `컵 가져오지 마` + `{"target":"컵"}`를 `fetch`, 미해결 조건 없음으로 처리한다.
   행동 금지와 `A 말고 B`의 대체 요청을 구분해야 한다.
2. `컵 집고 리모컨 가져와` + `{"target":"리모컨"}`에서 앞 동작이 사라진다.
   지원하지 않는 복수 동작은 일부만 실행하지 말고 질문/미지원 상태로 남겨야 한다.
3. `왼쪽 소파 위 리모컨`의 왼쪽이 소파를 꾸미는지 리모컨을 고르는지 구분하지
   않는다. 물체 상대 위치와 장소 수식을 분리해야 한다.
4. 화면 X 중심이 같은 두 후보에서 `left` 선택 결과가 입력 배열 순서에 따라 바뀐다.
   구분 근거가 없으면 모호함을 유지해야 한다. 화면 아래쪽을 앞쪽으로 보는 fallback도
   현재 시점에서 정당한지 확인해야 하며, 오래되거나 서로 다른 촬영을 혼합하면 안 된다.
5. 원본 파서는 취소 전용 경로, 여러 턴의 지시 대상 기억, 현재 집 가구 별칭 해석,
   실제 작업 진행 상태와의 연결을 완성하지 않았다.

## 현재 S5 코드와 연결하는 순서

현재 `assistant/language.py`는 규칙 파서와 지도 ID 해석을 제공하고,
`assistant/meaning.py`는 외부 의미 결과를 검증한다. `AssistantService`는 질문,
계획 미리보기, 실행 상태를 이미 관리한다. 이를 두 번째 실행기로 대체하지 않는다.

1. **요청 의미 계약 보완:** 원본 target 표현·제외 대상·상대 위치의 수식 대상·미해결
   조건을 잃지 않도록 원본 `TaskRequest`와 기존 의미 계약 사이에 변환 계층을 둔다.
   현재 6개 물체 종류 제한과 원본의 자유로운 명사 입력 차이를 명시적으로 처리한다.
   단독 `pick`을 목적지 없는 `fetch_object`로 조용히 바꾸지 않는다.
2. **언어 경계 보완 및 평가:** 취소는 모델 대기 없이 기존 취소 경로로 전달한다.
   금지문·복수 요청·좌표/모터 출력·깨진 JSON·모델 지연을 검사한다. 원본 133문장과
   새 집의 별칭/문맥/대조 문장을 분리해서 평가한다. 슬롯 일치, 질문 필요성, 잘못된
   실행 가능 판정을 별도로 집계한다.
3. **로컬 모델 작업자:** 원본 Qwen 실행 코드를 재사용해 텍스트 추론만 먼저 연결한다.
   모델 가중치·실행 환경·지연을 확인하고, 취소/정지 루프와 별도 작업자로 둔다.
   프롬프트의 답안이나 대화 속 어시스턴트 판단을 상시 모델 실행으로 표시하지 않는다.
4. **실제 집 기억 연결:** 현재 검토한 가구 이름·별칭을 후보 검색에 사용하되,
   관측 시각·가구 ID·등록 여부를 유지한다. `그거`, `내 리모컨`, `나한테`처럼 근거가
   부족한 표현은 필요한 항목만 질문한다. 이름을 해석했다고 실물 집기 가능으로 판정하지 않는다.
5. **앱의 모의 전체 흐름:** 문장→대상/출발/목적지 확인→필요한 질문→S4 작업 계획→
   상태/취소/결과를 기존 앱으로 연결한다. 새 가구 등록 요청과 기존 가구 위치 변경
   정책도 구분한다. 이후 보류한 S4 실물 기능이 준비되면 실제 전체 수행을 검증한다.

S5 전체 완료는 자연어 파싱 통과가 아니라 요청부터 물체 이동 결과까지 확인한 상태다.
지금은 위 로컬 준비를 진행할 수 있고, 실제 배송의 완료 판정은 S4b 이후다.


## 후속 구현: PC 로컬 모델과 모의 앱 연결

2026-11-13 구현. 원본 `task_parser`, `target_selection`, 테스트 23개, 평가 자료를
선별 이식했다. `contracts.py`와 기존 인식·집기 패키지는 덮어쓰지 않았다.
언어 파서의 출처는 위 여은 커밋이며, 별도 로봇 실행기를 만들지 않고 기존
`AssistantService`의 질문·지도 ID 해석·미리보기·확인·취소를 재사용했다.

### 모델과 PC 상태

- 모델: 공식 [Qwen3-4B GGUF](https://huggingface.co/Qwen/Qwen3-4B-GGUF)의 Q4_K_M.
  텍스트 우선 범위에 맞춘 모델이며, 원본 Qwen3-VL-4B 결과를 재현했다고 주장하지 않는다.
- 실행기: [llama.cpp](https://github.com/ggml-org/llama.cpp), 로컬 CUDA 빌드.
  모델/실행기 고정 커밋과 모델 SHA-256은 `config/home_assistant/s5_local_language.json`에 기록했다.
- RTX 5070 Ti 16GB, 드라이버 580.178.04 정상. 제한된 명령 환경에서는 장치 파일이
  보이지 않았지만 호스트 실행에서 정상 확인했다. GPU 고장이나 드라이버 미설치가
  아니며, 드라이버 변경·재부팅 없이 GPU 실행을 확인했다.
- GPU 추론 확인 시 전체 GPU 메모리 사용량 3,864MiB(데스크톱 포함).
  모델은 약 2.50GB 파일이며 내려받은 뒤 문장·이미지를 외부 추론 API로 보내지 않는다.
- 순수 텍스트 슬롯 추출이며 영상 이해 모델의 성능 검증은 아니다. 이미지·대상 관측은
  기존 인식 계층을 통해 나중에 연결한다. 온디바이스 모델 선정도 아직 확정하지 않았다.

### 처리와 실행 경계

`LocalLanguageModel`은 숫자 loopback 주소만 허용한다. 프록시와 외부 리다이렉트를
사용하지 않고, JSON 형식·출력 길이·종료 여부·시간 제한을 검사한다. 서버가 없거나
답변이 끊기면 실패를 표시하며 규칙 파서의 답을 모델 답으로 대체하지 않는다.

`LanguageJobs`는 모델 요청을 별도 작업자에서 처리한다. 제어 잠금 안에서는
결과 저장과 기존 의미 계약 연결만 한다. 대기 작업은 하나로 제한하고, 동일 요청
재전송은 중복 생성하지 않는다. 취소한 작업의 늦은 답, 지도/보정 문맥이 바뀐 답은
적용하지 않는다. 서버 재시작 시 미완료 해석은 INTERRUPTED로 보존한다.

취소는 모델을 기다리지 않는다. 화면 취소는 현재 작업의 정지 경로로 직접 보내고,
해석 중인 작업도 취소한다. 텍스트 취소는 요청 이력이 가득 차거나 오류가 기록된
상태에서도 처리한다. 어느 해석 결과도 실행 permit을 만들거나 자동으로 실행하지 않는다.
앱은 로컬 모델 연결 여부와 모의 실행임을 표시한다.

후처리는 부정 명령·복수 작업, 중복 JSON 키, 잘못된 제외 목록, 모터/좌표 필드를
검사한다. 원문에 명시된 색·소유·크기 수식어를 모델이 빠뜨리면 보존하고, 원문에서
한 번만 나타난 장소가 명확한 목적지 조사와 함께 쓰인 경우에만 source/destination
혼동을 정규화한다. 장소나 물체를 새로 만들어 넣지 않는다.

모델이 자유로운 명사를 추출하는 것과 실행 가능한 물체 종류는 다르다. 현재 기존
실행 계약은 마커·컵·리모컨·병·가위·드라이버 6개 종류다. 상대 위치, 소유권, 제외

기록하지 않으며, 실제 로봇·젯슨·모터에 접근하지 않는다.

### 실제 집 기록 연결

### 관측과 대화 연결

기존 `grounding_rgbd_snapshot.py`에 저장 RGB-D 재생 입력을 추가했다. 기존 native-depth
정합 → Grounding DINO/SAM → 기존 SigLIP2 크롭 재확인을 재사용한다. 새로운 외부
유료 모델은 쓰지 않는다. 사진 기반 가구 이름과 별도로, 작은 물체의 실제 검출 결과를
요청 ID와 연결한다.

`POST /v1/assistant/object-captures`는 `request_id`, `mode`, `stamp`, `transform`,
`report`, `evidence`, `support_id`, `support_verified`를 받는다. 저장 사진은 원본 시계와
시각을 유지하고 과거 관측으로 남는다. 현재 관측은 현재 시계·지도·보정과 일치해야 하며,
시각 차이 5초 이내, 카메라 변환 시각 차이 50ms 이내를 검사한다. 실제 센서의 이 기준
충족과 동시 부하 검증은 이후 실물 연결에서 확인한다.

위치 변환, 이미지/깊이 해시, 의미 재확인, 유효 깊이를 통과한 물체만 저장한다.
가구 힌트만으로 그 가구 위에 놓였다고 확정하지 않는다. 지지 관계를 확정하려면 현재의
측정된 지지면 관측도 필요하다. 전체 관측과 요청의 장면 갱신을 함께 저장하고, 동일
입력 재전송은 중복 생성하지 않는다. 새 사진에서 물체를 못 찾으면 이전 사진의 양성
결과를 현재 결과로 재사용하지 않는다. 취소한 요청에 늦게 온 관측도 거부한다.

실제 집 저장 자료 2장을 로컬 GPU로 처리하고 실제 HTTP API까지 연결했다.

| 자료 | 원 검출 | 재확인·대화 연결 결과 |
|---|---|---|
| 작업 책상, view 32 | 검은 마커펜 1개, 깊이 약 0.611m | 마커펜 확인, 과거 관측 후보 1개로 연결 |
| 낮은 탁자, view 22 | 빈 탁자 전체를 리모컨으로 오검출 | 탁자 형상으로 재확인되어 물체 후보에서 제외 |

두 사진은 실제 자료로 연결을 확인한 사례다. 일반 물체 검출 정확도나 실물 집기 성공률
측정이 아니다. SigLIP 점수 차이는 재확인 휴리스틱이며 보정된 확률이 아니다.
원본 검출과 재확인 결과 모두 `output/s5-preintegration-20261113/`에 보존했다.

추가 답변은 현재 요청에만 적용한다. `마커펜 가져다줘` → `침실 협탁에`처럼 목적지를
채우거나 모호한 장소를 선택할 수 있다. 물체/소유/상대 위치를 근거 없이 추정하지 않으며,
복잡한 설명은 지원 범위 안의 새 요청을 안내한다. 입력창과 추가 답변의 `취소`는 모델을
기다리지 않고 처리한다. 이미 취소한 요청은 재접속해도 다시 진행하지 않는다.
