# S4b 구현 계획: 관측 기반 정차 → 집기 → 운반 → 놓기

작성일: 2026-11-13. 아래는 설계 원본이다. 이후 호스트 실행 연결을 구현했으며
현재 구현 범위·검증과 인계 경계는 [S4B_HOST_PIPELINE.md](S4B_HOST_PIPELINE.md)를 따른다.
실물 수락·활성 배포 기록은 아니다.

사용자 결정: SLAM 지도 수집보다 이 설계를 먼저 확정한다. 지도는 텔레옵으로 구간별
생성하고 전원 재연결 이어하기를 검증한다. 집 전체 자동 탐색은 배터리 도착 후로
이관한다. S4b의 짧은 자동 정렬·목적지 이동은 케이블 여유가 확인된 작업 구역에서
검증한다. S4b 전체를 사람이 베이스를 맞춰 주는 작업으로 대체하지 않는다.

## 1. 완료할 행동과 이번 설계의 결정

앱에서 출발 가구·대상·목적지를 선택하면 로봇이 가구를 찾아가 대상을 관측하고,
물체 형상과 SO-ARM101 작업 범위를 이용해 베이스와 리프트를 맞춘 뒤 집어서 운반하고
목적지에 놓는다. 자연어 해석은 S5다. 물체 이름별 베이스 좌표, 고정 정차점, 저장된
집기 관절 자세를 사용하지 않는다. 첫 실물 범위는 왼팔과 관측 가능한 단단한 탁상
물체다. 오른팔은 지지/운반 외형 검사에 포함하되 동시 양팔 집기는 이 인수에 넣지 않는다.

확정 실행 순서:

```text
PREPARE_TRAVEL → NAVIGATE_SOURCE → OBSERVE_TARGET
 → PLAN_ALIGNMENT → ALIGN_BASE → SET_LIFT → REOBSERVE_TARGET
 → PLAN_FINE_GRASP → PICK_AND_VERIFY → PREPARE_LOADED_TRAVEL
 → NAVIGATE_DESTINATION → OBSERVE_DESTINATION
 → PLAN_PLACE_ALIGNMENT → ALIGN_LOADED_BASE → SET_PLACE_LIFT
 → REOBSERVE_DESTINATION → PLACE_AND_VERIFY → RETREAT → COMPLETE
```

정밀 GraspNet 후보는 **베이스·높이 정렬 후 새 촬영에서 생성**한다. 그 전에 필요한
것은 물체의 지역별 폭·방향과 팔 작업 영역이며, 미리 선택한 6자유도 파지 자세를
5자유도 팔에 강제로 맞추지 않는다. 도착 후 정밀 파지가 없으면 원인이 있는 대안
정렬을 제한된 횟수로 시도한다. FK로 만든 팔 자세는 정차 계산의 증거일 뿐 팔 명령이 아니다.

## 2. 현재 코드와 반드시 메울 차이

경로는 저장소 루트 기준이다. 아래의 `tasks/`는
`ros2_ws/src/home_robot_tasks/home_robot_tasks/`를 줄인 표기다.

| 현재 재사용할 것 | 확인한 상태 | 이번에 메울 차이 |
|---|---|---|
| `tasks/assistant/object_alignment.py` | 형상 지역·Sobol FK·베이스/리프트 역산, 36개 합성 형상 조건 | FK 기준점과 접촉 중점 분리, 고정 높이 우선, 표본 다양성, 실제 경로/시야/STL 연결 |
| `tasks/assistant/placement.py` / `placement_binding.py` | 후보 검사 계약, 이동 후 새 capture 요구 | 정밀 grasp ID를 정렬 전 요구하는 경로를 새 사전 정렬 정책과 분리 |
| `tasks/stationary_lift.py` | 상판 높이별 1cm lookup, 이력/3mm 히스테리시스 | lookup 우선 정책과 보정 원점 연결. 현재 prototype의 자유로운 높이 역산은 참고값으로 한정 |
| `StationaryArm`, `StockJaw`, `carry_contact_ik.py` | 보정/관절 범위/FK와 공식 손가락 형상 | 베이스가 달라진 장면을 올바르게 변환하고 거친 후보를 정밀 집기로 넘기지 않음 |
| `carry_planning.py`, `carry_moveit.py` | 실제 MoveIt 서비스 기반 단계 연결, 집기/놓기 계획 함수 | 실측 모바일 장면·하중·재관측을 연결하고 놓기 실행 프로그램/검증까지 연결 |
| `carry_program.py`, `carry_execution.py` | S3 집기 단계와 유지 실행 | 현재 집기 단계 전용 계약을 놓기까지 억지 재사용하지 않고 typed place program 추가 |
| `fetch.py`, `fetch_composition.py`, `runtime_factory.py` | 15단계 작업·비동기 port·취소·소유권, 모의 연결 | 물리 어댑터 및 독립 evidence 연결. 단순히 mode 플래그를 바꾸지 않음 |
| `base_driver.py`, `navigation_binding.py` | SI 속도→공통 MobileClient, 정지 확인 계약 | 실제 공통 제어기/프로필 인수. 마지막 확인된 STM32는 수동 wheel-hold 텔레옵 이미지 |
| `config/nav2.simulation.yaml` | Navfn A* + DWB, 합성 closed-loop | 원형 임시 footprint/속도를 실물 설정으로 승격하지 않음. 높이별 몸체 검사·정렬 경로 연결 |
| `CarryVisualMonitor`, `PayloadMonitor` | RGB-D/FK 관계, 측정 집게/영상 증거 계약 | 운반 중 시야와 실제 센서 기준 계측. 명령 성공을 하중 유지 증거로 대체하지 않음 |
| `MissionCatalog` / `SearchSession` | 등록된 장소와 viewpoints 소비 | 의미 가구에서 동적 관측 위치를 생성하고 가구 revision에 묶어 등록 |

기존 36조건/83검사 통과는 로컬 모델·계약 검사다. 실제 경로·시야·STL 검증이나
36회 집기 성공으로 간주하지 않는다. 현재 코드와 아래 계획의 새 기능을 구분한다.

## 3. 알고리즘 선택

| 문제 | 이번에 사용할 방법 | 사용하지 않을 우회 |
|---|---|---|
| 물체 기하 | 기존 DINO/SAM 마스크 + 보정된 native RGB-D 등록 + plane/clean_cloud | 물체 이름으로 크기/잡을 방향 고정 |
| 사전 정렬 | 실제 SO101 관절 표본의 FK를 역으로 배치하는 sampled inverse reachability | 임의 6D pose를 먼저 고정, 다른 로봇 도달성 맵 복사 |
| 시야 | D415 투영/가림 검사와 실제 새 깊이의 유효 관측 확인 | 화면에 bbox가 있으면 깊이도 정확하다고 판정 |
| 원거리 이동 | 기존 Navfn A* + DWB 전방/횡이동 제어 | 텔레옵 키를 타이머로 눌러 목표 위치 흉내 |
| 탁자 근처 정렬 경로 | 국소 SE(2) lattice A* + 같은 Nav2 DWB의 정렬 설정 | 점 또는 원형 반경만으로 회전 가능 판정 |
| 정밀 집기 | 정렬 후 GraspNet + 기존 5축 contact IK/손가락 STL + MoveIt | 6D 파지를 강제로 수평 회전한 뒤 같은 접촉이라고 주장 |
| 운반 자세 | 기존 `carry_goals` 제한 최적화 + 전체 경로·시야 검사 | 물체마다 저장된 운반 관절값 |
| 놓기 | 상판 빈 공간 격자 + 실제 held transform 기반 놓기 계획 | 잡았던 위치와 무관하게 손끝만 상판에 맞춤 |
| 작업 제어 | 기존 fetch/SequencePort/RobotRuntime | 별도 두 번째 작업 실행기·별도 직렬 소유자 |

새 학습 모델은 추가하지 않는다. GraspNet/DINO/SAM은 설치 모델을 고정해 사용하며
시멘틱 가구 모델 비교는 지도 생성 이후의 별도 평가다. GPU 인식과 20Hz 주행 제어는
프로세스를 분리하고 크기 1의 최신 관측 큐를 사용한다.

## 4. 데이터 계약과 좌표

아래 dataclass/schema를 `tasks/assistant/alignment_contracts.py`에 정의한다.
큰 영상·점군은 파일 참조와 SHA256으로 전달하고 모터 명령 JSON에 넣지 않는다.

| 계약 | 필수 필드 |
|---|---|
| `TaskScene` | task_id, object_id, surface_id, capture_id, 원본 color/depth 시각, boot/clock ID, map/scene/calibration/model revision, 당시 map→base와 관절/리프트, 원점 확인 여부, cloud/mask/obstacle 참조·해시, support plane/hull, visible/unknown 구역, 위치 오차 근거 |
| `ShapeRegion` | region_id, 관측 중심/영역, 가능한 closing 방향 범위, 관측 폭 범위, 지역 법선·관측 지지도, 형상 중앙성, 가려짐. mass/CoM는 unknown |
| `AlignmentProposal` | task/object/scene 식별, base XY/yaw, lift travel from bottom, 사용 팔, region_id, FK witness, 예상 가시성, 비용 항목, 거절 이유, 필요한 검사 목록 |
| `CheckedAlignment` | proposal + 이동/정렬 경로, 운반 자세 hash, 리프트 전환 STL 검사, 센서 시야 검사, 검사된 scene revision, 유효 작업 범위. 팔 집기 실행 권한 없음 |
| `FreshGraspScene` | 정렬 완료 이후의 새 capture ID, 실제 정지·관절/높이 상태, 같은 object_id 확인, 새 목표/장애물/상판. 이전 목표는 provenance로만 참조 |
| `HeldObject` | object_id, 검증한 파지 ID, 측정 FK/RGB-D로 추정한 `tcp_from_object`와 불확실성, 관측 형상/미확인 부분, 방향 조건, 최근 retention evidence 시각, payload/model revision |
| `PlaceProposal` | 목적 상판 ID/revision, 지지 영역, 원하는 object pose, held transform에서 계산한 TCP pose, 베이스/높이, 접근·지지·해제·후퇴 증거 |

지도는 가구를 찾고 베이스를 배치하는 전역 기준이다. 최종 손가락 위치는 정지 후
현재 base에서 새 RGB-D로 계산한다. `map→odom→base→lift→arm→TCP`와 실제 카메라
부모 변환을 촬영 시각으로 조회한다. `ground_z_m`와 리프트 축을 그대로 사용하고
base_link Z를 바닥 Z=0으로 오인하지 않는다. 9.1mm 보정은 기존 보정 프로필에서
한 번만 적용하며, S3의 약8mm 잔여 오차는 원인 미확정 기록으로 유지한다.

정렬 중 지도 loop correction/재위치 추정이 발생하면 계획을 새 map epoch로 재검토한다.
보정이나 Home/range가 바뀌면 캐시와 목표를 폐기한다. 전원 재부팅 후 old capture,
last pose 또는 예전 리프트 적산값으로 작업을 재개하지 않는다.

## 5. 가구 접근과 관측 위치 생성

구현 인터페이스는 아래로 고정한다. 결과 status와 provenance를 포함한 typed result를
반환하고, planning 함수에는 직렬/모터 client를 주입하지 않는다.

```python
observe_scene(capture, measured_state, map_context, target_id) -> TaskScene
propose_views(surface, current_state, visible_map, model) -> ViewProposalResult
propose_alignment(scene, current_state, reachability_cache, height_policy) -> AlignmentResult
check_alignment(proposal, scene, travel_configuration, nav, camera, moveit) -> CheckedAlignmentResult
plan_fine_pick(fresh_scene, measured_state, graspnet, moveit) -> PickCarryPlan
plan_place_regions(destination_scene, held_object, policy) -> PlaceRegionResult
plan_fine_place(fresh_scene, held_object, measured_state, moveit) -> PlaceCarryPlan
```

`AlignmentResult.status`는 `PROPOSALS / REOBSERVE / NO_SAMPLED_SOLUTION`으로 구분한다.
`CheckedAlignmentResult.status`는 `CHECKED / STALE / BLOCKED / UNSUPPORTED`이고,
reason code는 `PARTIAL_EXTENT`, `IDENTITY_AMBIGUOUS`, `NO_DEPTH`, `NO_ROUTE`,
`BODY_COLLISION`, `LIFT_TRANSITION_COLLISION`, `VIEW_OCCLUDED`, `MODEL_CHANGED`를
구분한다. 값이 없는 check는 통과값으로 채우지 않는다. 실행은 기존 port의
`start(goal_id, parameters) / poll(goal_id) / cancel(goal_id)`와 공통 owner를 사용한다.
보유 하중 때문에 취소 뒤에도 유지가 필요하면 `CANCELLED_HOLDING`을 작업 결과에
표시하고 장치 상태는 별도 유지한다. 완료 후 같은 goal_id의 재호출은 상태 조회만 반환한다.

1. 의미 지도의 furniture_id와 관측 외곽/상판 가설을 읽는다. 이름은 탐색 힌트이며
   장애물 형상·상판 정밀 위치를 대신하지 않는다. 가구 종류가 미확정이어도 사용자가
   지정한 해당 가구 ID/영역을 대상으로 진행할 수 있다.
2. 관측된 가구 외곽의 접근 가능한 변을 10cm 간격으로 샘플링하고 바깥쪽 위치를 만든다.
   거리 표본은 D415의 해당 프로필 유효 거리에서 .45/.65/.85m를 **후보 seed**로 사용한다.
   카메라 원점/광축을 고려해 실제 깊이 범위 밖인 값은 제외한다. 베이스-물체 고정 거리
   규칙이 아니다. 팔/카메라 위치가 바뀌면 후보를 다시 만든다.
3. 각 위치에서 yaw는 상판을 보는 방향과 ±20°를 검사한다. 높이는 기존 lookup부터
   시작한다. 실제 카메라가 리프트와 함께 움직이는지는 모델 TF로 계산하고 가정하지 않는다.
4. 상판과 주변 5cm 띠를 카메라에 투영하고 z-buffer/ray 검사로 예상 가림을 평가한다.
   알고 있는 장애물이 가린 후보는 제외하고, 미관측 영역은 예상 가시성으로만 표시한다.
   예측만으로 유효 깊이 또는 빈 공간을 확인했다고 기록하지 않는다.
5. 이동 경로·본체 외형을 통과한 후보 중 상판 관측 면적/이동 비용이 좋은 최대 6개를
   둔다. 실제 촬영은 최대 3위치×2회. 이름이 같은 다른 책상을 자동으로 선택하지 않는다.
6. 실제 영상에서 물체가 충분히 보이면 사전 정렬로 넘어간다. 부분 가림/깊이 결측이면
   가장 많이 새로운 면을 볼 수 있는 다음 위치로 이동한다. 끝까지 불충분하면
   `OBSERVATION_INSUFFICIENT`로 종료한다. ‘물체가 없음’과 구분한다.

가능하면 최초 관측 위치를 그대로 정렬 후보에 포함한다. 이미 집기 범위이면 별도의
보기 위한 이동·원위치 복귀를 만들지 않는다.

## 6. 물체 형상에서 작업 영역 생성

기존 `mask_cloud.measure/clean_cloud`, `target_ownership.associate`, plane 추정을 재사용한다.
지원면 제거·자기 형상 제거 전후의 원본은 보존한다. 계획용 점군만 2mm voxel로 줄이고
충돌 점군의 원본은 삭제하지 않는다. 연결 성분을 분리하고, 여러 성분이 비슷한 크기면
무조건 가장 큰 것을 목표로 선택하지 않고 segmentation ambiguity로 재관측한다.

초기 표본 정책:

- 수평 closing 방향 12개(15° 간격, 부호 대칭은 베이스 역산에서 양쪽 모두 검사).
- 긴 축 PCA는 선호 방향을 정하는 데만 사용한다. 고유값 비가 1에 가까운 물체는
  방향 선호 가중치를 0에 가깝게 만든다. PCA 부호와 180° 대칭 때문에 후보가 사라지지 않는다.
- 접선 방향 25/50/75% 위치와 높이 30/65/90% 위치에서 지역 폭을 검사한다.
  초기 지역 반길이25mm/반높이12mm, 실제 점이12개 미만이면 가설을 만들지 않는다.
  이 값은 초기 계산 설정이며 물체를 잡을 수 있는 물리 한계가 아니다.
- 전역 폭 대신 지역 폭을 사용한다. 너무 넓은 몸통 옆의 좁은 부분은 후보를 남기되,
  컵 손잡이 내부가 실제로 뚫렸는지는 깊이 관측 없이는 주장하지 않는다.
- 관측 폭 + 기존 4mm 열림 여유가 공식 STL 유효 집게 폭에 들어가는지 검사한다.
  닫힘 5mm 설정과 혼동하지 않는다. 뒤쪽/옆쪽이 가려졌으면 관측 폭은 하한일 수 있으므로
  `partial_extent`를 붙이고 이동 후 두 접촉 측면을 확인해야 한다.
- 형상 중앙 근접도를 선호한다. 이를 무게중심이나 안정한 힘의 증거로 부르지 않는다.
  방향별 다양성을 유지해 최대24개 영역을 남긴다.

닫는 축은 수평에 가깝게, 접근은 기존 TabletopGraspPolicy 범위로 시작한다. 현재
선호/최대 기울기(접근30°/50°, 닫는 축10°/20°)를 그대로 재사용한다. 접촉이 좋은 후보
중 편한 자세를 우선하며, 양호한 대안까지 새 각도 하드컷으로 배제하지 않는다.
측면에서만 잡을 수 있는 물체·유연체·불투명한 내부 질량은 첫 범위 밖으로 명시한다.

## 7. 리프트 정책: 변환표 우선, 팔 모델로 확인

사용자가 요청한 기존 높이표를 먼저 적용한다. `LiftHeightRule.setting()`의 h0를 선택하고
**한 번의 정렬·집기 시도 동안 리프트를 고정**한다. 모든 FK 표본마다 자유롭게 높이를
역산하던 prototype은 생산 정책으로 사용하지 않는다.

1. 원본 상판 높이를 기존 표에 넣어 h0를 얻는다. 최근 사용한 preset과 히스테리시스를 유지한다.
2. h0에서 베이스·팔 작업 범위 후보를 먼저 찾는다. h0가 있으면 다른 높이를 단순히
   점수가 조금 낮다는 이유로 고르지 않는다.
3. h0에서 **검사한 후보가 모두 실패할 때만**, h0±1cm → ±2cm → ±4cm의 표 항목을
   가까운 순서로 검사한다. 전체 리프트 범위를 무차별 스윕하지 않는다. 범위 밖/중복 제거.
4. 대안 높이마다 별도의 팔 자세·시야·전환 충돌 검사를 수행한다. 리프트 이동 중 팔/베이스는
   동시에 작업하지 않는다. 이동 전에 접은 팔과 오른팔/고정 가로대/리프트 구조도 검사한다.
5. 출력은 최하단 기준 travel(m). 기존 실측 85,342µm/turn과 엔코더 방향/해당 부팅 원점으로
   모터값을 계산한다. 단일 하강 측정의 반복성 미확정은 그대로 기록한다.

높이표가 특정 상판/카메라 조건에서 부적합하면 해당 실패 자료로 개정하며, Home 손끝을
물체 접촉 중심으로 동일시하지 않는다. 현재 prototype의 FK 기준점은 정확한 손가락
접촉점이 아니므로 다음 절의 ‘작업 영역’ 적합으로만 사용한다.

## 8. 베이스 위치·방향 알고리즘

### 8.1 SO101 전용 도달성 캐시

공식 URDF, 현재 Home·raw range, TCP/stock finger 변환, 팔 mount, lift 축의 hash를 키로
사용한다. 관절 공간은 결정적 Sobol 4,096표본으로 시작하고 첫 검색이 비면 16,384로
한 번 확장한다. 계산은 기존 FK의 배치 계산을 재사용한다. FK 캐시는 환경 독립이다.
자가충돌 검사 캐시를 별도로 둘 때는 검사한 집게 열림·리프트 높이·반대팔 자세 hash도
키에 포함한다. 고정 본체/반대팔/가로대 충돌은 현재 높이와 실제 전환 자세에서 MoveIt으로
다시 검사한다. 다른 높이에서 통과한 collision 결과나 실제 환경을 일반 FK 캐시에 섞지 않는다.

5자유도 팔에 6×6 Jacobian determinant를 점수로 쓰지 않는다. 관절 한계 여유,
손목 기준 이탈, 실제 지원하는 task Jacobian의 특이값을 사용한다. task는 XYZ3축과
접근축 기울기2축으로 정의하고 closing 방향은 별도 FK 기준으로 평가한다. Jacobian은
기존 모델 FK의 유한차분으로 검증하며 단위는 위치0.1m/각도1rad로 정규화한다.
특이값은 선호도다. 단독 임계치로 실행 가능성을 판정하지 않는다.

캐시는 위치2cm·closing 방향15°·접근 기울기15°의 bin별 여러 관절 해를 유지한다.
가장 편한 자세32개만 먼저 잘라 먼/높은 영역과 다른 방향을 잃는 prototype 방식을 바꾼다.

### 8.2 물체 지역을 작업 영역에 맞추기

각 h에서 FK 표본의 실제 손가락 **관측 폭에 해당하는 접촉 구간 중심**을 계산한다.
`StockJaw`의 고정/가동 손가락, `arm.tcp_from_stock`, 기존 stock section 폭 변환을
재사용한다. 이는 coarse contact surrogate이며 실제 접촉 쌍이 아니다. 기존 FK TCP를
그대로 물체 중앙에 놓던 수 cm 편향을 제거하고, 접촉 영역의 높이 불확실성도 유지한다.

지역 closing 방향 d와 표본 closing 축 c의 수평 투영으로 yaw 두 개를 만든다:

```text
yaw = angle(d_xy) - angle(c_xy) + {0, π}
base_xy = region_xy - Rz(yaw) * modeled_contact_region_xy(q, h)
```

고정된 h에서 접촉 영역 Z가 관측 region Z 구간과 만나는 표본을 선택한다. 거친 적합 허용은
초기10mm이고, 부족하면 q를 관절 범위 안에서 제한 least_squares로 보정한다. 이때 목표는
XYZ 영역과 closing/approach의 **허용 범위**이며 임의 6D pose 완전 일치를 요구하지 않는다.
환경/접촉 가능한 정밀 파지를 이미 찾았다고 표시하지 않는다. q는 runtime 팔 목표로 넘기지 않는다.

목표 주변 XY4cm/yaw10° 중복을 줄이고, 접근 면/팔 해의 다양성을 보존해 최대128개
거친 후보를 만든다. 같은 위치를 계속 재시도하지 않도록 object/scene revision과 실패
원인별 후보 이력을 남긴다. 미관측 형상을 추정해 빈 공간으로 만들지 않는다.

### 8.3 검사 순서와 점수

계산 비용 순으로 검사하고 상위 후보만 비싼 계획기로 보낸다.

1. 케이블 작업구역·금지구역·map 범위·높이 범위·베이스 점유 검사.
2. 캐시의 작업 영역 적합·관절 범위·열림 폭·실제 endpoint 본체/팔 STL 검사.
3. 예상 카메라 재관측 시야/알려진 가림 검사.
4. 이동/정렬 경로와 **팔 접기→베이스 이동→리프트 전환**의 몸체 sweep 검사.
5. 상위8개에 정밀 STL/MoveIt configuration 검사. 전부 실패하면 다음8개, 최대24개.

통과한 후보 비용을 아래처럼 고정해 시작한다. 각 항목 원본과 정규화값을 저장한다.
계수는 성능 실험 후 바꿀 수 있지만 후보마다 임의로 바꾸지 않는다.

```text
J = 2.0*shape_obliquity + 1.0*shape_centrality
  + 1.5*wrist_posture + 1.0*joint_limit_cost
  + 1.0*path_length/1m + 0.3*abs(yaw_change)/π
  + 0.5*abs(lift_change)/lift_travel
  + 1.0*view_occlusion_fraction + 1.5*uncertainty_cost
```

`shape_obliquity`는 긴 축의 명확도에 따라 가중한다. 둥근 물체는 0에 가깝다.
불확실성이 높아도 곧바로 전부 금지하지 않고 추가 관측 후보를 만든다. 충돌·미관측
이동 공간·깊이 부재를 낮은 비용으로 상쇄하지 않는다. 현재 위치도 항상 후보에 넣고,
비슷한 비용(차이0.1 이내)이면 추가 이동/재정렬이 적은 쪽을 택한다. 성공 확률을 표시하지 않는다.

## 9. 접근 경로와 마지막 정렬

전역 Navfn A*는 가구 근처의 여유 있는 staging 위치까지 사용한다. 원형 근사 기반
전역 경로의 실패를 ‘로봇이 물리적으로 통과 불가’라고 단정하지 않는다. 마지막 약1m는
현재 관측 구역에서 SE(2) lattice A*로 평가한다.

- 상태: XY2cm, yaw10°. 이웃: 같은 yaw의 8방향 이동, 제자리 ±10° 회전.
- 영역: 시작점과 후보를 포함하는 관측된 국소영역, 최대 3×3m; 최대100,000노드.
- 비용: 거리 + 실제 회전량 + 장애물 근접 비용. heuristic는 유클리드 거리+최소회전 비용.
- 충돌: 기존 높이별 STL footprint를 yaw별로 회전하고 실제 장애물 높이와 맞춰 검사.
  edge sweep는 footprint 끝점 이동이5mm 이하가 되도록 세분화한다. 표본 검사이며
  연속 충돌 증명으로 부르지 않는다. 최종 경로의 중요 근접 구간은 원본 mesh로 재검사한다.
- 목표의 실제 XY/yaw로 잇는 마지막 edge도 검사한다. 격자 칸에 들어갔다고 목표 도착으로 보지 않는다.
- 경로를 Nav2 FollowPath로 보낸다. 기존 DWB를 Transit/Align 두 설정으로 재사용한다.
  Align은 yaw goal·경로 거리·실제 footprint를 평가하고 전방 주행 선호는 사용하지 않는다.
  기존 point/radius `BaseObstacle`만으로 끝내지 않고 `ObstacleFootprint`를 사용한다.
- 높이별 sweep guard는 Nav2 비용지도와 별도로 최종 속도를 검사한다. 이미 footprint가
  적용된 center-space 지도에 Nav2가 같은 폭을 다시 부풀리지 않도록 원시 occupancy와
  center-space 검사 결과를 명확히 구분한다.

초기 실물 상한 후보는 이동0.08m/s, 회전0.20rad/s, 최종정렬0.03m/s·0.10rad/s다.
이 수치는 **계획상 초기 제한**이며 적용값은 기존 제어기 한계와 측정된 정지거리/하중
검사를 통과한 더 작은 값이다. 원본 teleop raw200을 m/s로 추정해 그대로 쓰지 않는다.

도착 기준은 기존 3cm/0.1rad를 시작점으로 유지한다. 이후 fresh RGB-D에서 정밀 집기
경로가 나오면 불필요한 mm급 베이스 정렬을 반복하지 않는다. 리프트는 기존3mm 도착
검사를 사용한다. Nav2 성공 후에도 새로운 실제 정지 증거가 있어야 팔 단계로 넘어간다.

전방 RGB-D가 보지 못한 횡/후진 공간을 라이다만으로 허용하지 않는다. 그 방향의 높이
공간을 먼저 관측하고, 회전 자체도 sweep가 확인된 경우에만 수행한다. 전원선은 자동
형상 인식됐다고 가정하지 않으며 사용자 확인한 작업구역/길이 예산으로 후보를 제한한다.

## 10. 정렬 후 새 관측과 정밀 집기

1. measured stop·높이 도착 후 새 RGB/native-depth와 관절 시각을 묶어 캡처한다.
2. 같은 물체 확인은 object_id + 기존 위치 불확실성 영역 + 크기/형상 + 마스크 영상
   외관으로 한다. 다수 동일 물체가 겹치면 nearest만으로 ID를 옮기지 않고 재관측/선택을 요청한다.
3. 새 점군·상판·주변 장애물에서 기존 GraspNet을 실행하고 실제 손가락 폭·중앙성·
   TabletopGraspPolicy·5축 IK로 후보를 거른다. 기본상위8개, 필요하면16개까지 한 번 확장.
4. 기존 `bind_grasp`, `fit_pregrasp`, `plan_pick_carry`, `MoveItCarryPlanner`를 사용해
   열기→상부 접근→수직 하강→닫기→시험 들기→들기→운반 자세까지 검사한다.
5. 수평 전진은 stock finger STL 최저면이 상판 위에 있는 상태에서 끝낸다. 하강 말단의
   허용 접촉은 별도 contact phase/대상 부품에만 한정한다. 전체 탁자 충돌을 끄지 않는다.
6. 기존 5mm 닫힘 여유를 기본 후보로 유지하되 힘(N)으로 표기하지 않는다. 원래 실물에서
   확인한4mm와 변경한5mm의 검증 범위 차이를 기록한다. 실패 시 자동으로 더 세게 조이지 않는다.
7. 실제 물체가 손끝과 함께 움직이는 RGB-D/FK 관계와 집게 피드백을 확인한 뒤 HELD로 전환한다.

길어진 인식/계획 때문에 최초 영상 나이가 제한을 넘었다면 타임스탬프를 새로 찍지 않는다.
기존 실시간 scene/patch monitor로 마지막 새 관측이 같은 물체·장면·로봇 상태임을 확인하는
`SceneContinuityEvidence`를 전달한다. 상판/목표/관절 변경이면 원래 계획 폐기·새 캡처.
이 검증을 `ManipulationPort` handoff에 연결하기 전에는 기존 freshness 검사를 완화하지 않는다.

## 11. 운반 자세·실제 하중 유지

파지 전부터 그 후보로 **들고 빠져나와 운반 자세로 접는 경로**가 있는지 검사한다.
`carry_goals`의 현재 최적화·OMPL/Cartesian 경로를 재사용하고, 관측한 물체 형상을
`tcp_from_object`로 attach한다. 다른 위치에서 집었다는 이유로 attach transform을 초기화하지 않는다.

추가 평가 항목은 탁자/본체 여유, 팔 뻗음, 관절 여유, 물체 방향 조건, 운반 중 보이는
물체 patch다. 공통 운반 자세는 선호값일 뿐 고정 joint 목표가 아니다. 별도 방향 조건이
없는 물체는 원래 파지 방향 변화를 줄이는 선호를 사용하고, 내용물이 있는 컵의 취급을
물체 이름 하나만 보고 허용하지 않는다.

`PayloadMonitor`의 실제 effort/gap 범위는 빈 집게·물체 유지 기록으로 검증한다.
모터 load raw는 보정된 힘 센서가 아니다. `CarryVisualMonitor`와 measured FK로
물체 상대 위치가 유지되는지 확인한다. 이동으로 patch가 가려질 운반 자세는 먼저
대안을 평가한다. 추적 불가를 HELD로 간주하지 않으며, 정지·하중 유지 후 관측을 회복한다.
하중을 들고 있는 동안 실패/취소로 집게를 자동 개방하거나 팔 토크를 끄지 않는다.

운반 중 사용한 patch가 실제로 관측되는지는 정지 자세만 검사하지 않고, base/lift/팔
전환의 표본마다 카메라 투영과 가림으로 확인한다. 관측 가능한 운반 자세를 찾지 못하면
지금 센서 구성으로 자동 운반이 검증되지 않은 경우로 종료한다. 새 센서를 가정하거나
load raw 하나로 장시간 시각 유실을 덮는 fallback을 넣지 않는다.

출발 시 운반 팔 자세·리프트 높이에서 몸체+물체 envelope를 다시 만들고 주행 guard에
전달한다. lift 이동은 base 정지·팔 전환 완료 후에만 한다. 팔과 base의 동시 작업은 첫 버전 범위 밖이다.

## 12. 목적지 놓기 알고리즘

1. 목적 가구 접근·상판 재관측은 출발과 같은 관측 위치 생성기를 사용한다.
2. 관측된 지지면을5mm 격자로 만들고 점유/가림/미관측 구역을 구분한다. 실제 held object의
   투영 footprint + 위치 불확실성 + 초기10mm 가장자리 여유로 유효 지지 영역을 erosion한다.
   외곽 밖·다른 물체 위·깊이 결측은 빈 자리로 채우지 않는다.
3. distance transform의 여유 큰 위치부터 공간 NMS5cm로 최대12개를 뽑는다.
   물체의 원래 안정적으로 놓여 있던 roll/pitch를 보존하고 yaw를15° 간격으로 검사한다.
   원래 지지 방향이 불명확하거나 물체가 변형되었으면 안정한 놓기 자세를 임의 추측하지 않는다.
4. `map_from_tcp = map_from_object_desired × inverse(tcp_from_object)`로 TCP 후보를 계산한다.
   그 후보가 우리 팔에 맞는 베이스·높이를 같은 정렬 검색으로 선택한다. 놓기에서는
   이미 잡은 물체 관계가 있으므로 자유롭게 손가락 방향을 새로 선택할 수 없다는 점이 집기와 다르다.
5. 이동·높이 조절 후 목적지를 다시 촬영하고 `plan_place_carry`로 접근→지지 위치→
   제한 개방→완전 해제→후퇴→빈손 운반 자세를 검사한다. release 시점까지 attached 형상을 유지한다.
6. 지지는 위치 명령 완료만으로 판정하지 않는다. 새 depth의 물체/지지면 간격과 집게
   피드백 변화로 지지 가능 상태를 확인한다. 첫 제한 개방 후 연속 관측에서 상판 위
   물체가 안정되고 집게와 분리된 것이 보일 때 완전 개방한다. 가림/깊이 오차가 크면 유지·재관측한다.
   힘 센서 없이 확정할 수 없는 접촉 상태는 unknown으로 남긴다.
7. 후퇴 후 목적지 물체 존재·빈 집게·물체 정지까지 확인하고 COMPLETE. 로봇 action
   SUCCEEDED만으로 배송 성공을 기록하지 않는다.

## 13. 제어기·상태 수명과 복구

최초 실물 자동 정렬 전에 공통 binary MobileClient/팔/리프트 경로를 한 제어기에서
인수한다. 기존 native 공통 코어·STM32 모듈을 연결하고 단일 UART worker가 소유한다.
텔레옵 문자프로토콜에 Nav2 속도를 키 입력으로 번역하는 임시 실행 경로는 만들지 않는다.
단계 전환마다 펌웨어 교체·MCU 리셋·모터 전원 순환을 하는 방식도 사용하지 않는다.

새 코드가 유지 상태를 넘겨받을 때 actual joint/goal/mode를 읽고 현재 자세 유지가
확인된 상태에서만 소유권을 전환한다. profile/hash와 부팅 ID가 다르면 이전 목표를 보내지 않는다.
기존 간헐적 오른팔 조회 실패, 실제 정지 검사, lift 모드 좌표 문제를 회귀 항목에 포함한다.

| 실패 종류 | 처리/자동 재시도 예산 |
|---|---|
| 물체 일부 가림/깊이 부재 | 최대3관측 위치×2장. 무한 촬영 없음 |
| 첫 FK 검색 비어 있음 | Sobol4096→16384 한 번. 높이 후보는 표 정책 안에서만 확장 |
| 경로 막힘/가구 변경 | 실제 정지 후 새 scene으로 재계획1회. 이전 목표 재전송 금지 |
| 도착 후 정밀 파지 없음 | 원인별 대안 정렬 최대2회(최초 포함 총3위치), 동일 실패 위치 제외 |
| IK/손목 한계 | 다른 yaw/거리 후보. limit를 늘리지 않음 |
| 탁자 접근 충돌 | 상부 접근 공간/다른 면 후보. collision disable로 통과시키지 않음 |
| 빈 집게/시험 들기 실패 | 원래 지지면과 복귀 경로가 확인되면 내려놓기 후1회 재시도; 그렇지 않으면 유지/사용자 도움 |
| 운반 중 미끄러짐/시각 유실 | 주행 정지·팔/집게 유지. 새 영상으로1회 회복, 실패하면 사용자 도움 |
| 목적지 가득 참 | 동일 상판 다른 유효 자리 최대2개, 없으면 유지/사용자 선택 |
| USB·센서·전원·boot 변경 | 공통 정지/복구. 자동 MCU 리셋·오래된 명령 재생 없음 |
| 취소 | 바퀴 정지, 하중/팔 유지, 상태·저장 완료 표시. 취소가 ‘전원 제거 가능’을 뜻하지 않음 |

수동 teleop에서 지도 갱신 지연은 참고 경고로 처리한 기존 정책을 되돌리지 않는다.
자동 정렬/주행에서는 신선한 위치가 필요하므로 감속·정지하고, 실제 통신/정지 실패와
순간적인 위치 품질 경고를 UI와 로그에서 구분한다. 시험 결과 없이 타임아웃을 전반적으로 늘리지 않는다.

## 14. 파일별 구현 작업과 순서

계산은 비동기 작업으로 실행한다. 초기 예산은 관측/정렬 기하20초, GraspNet30초,
MoveIt 전체 경로60초이며, 이는 제어기 command lease와 분리된 작업 timeout이다.
긴 계산 중에도 UI 상태를 최소2Hz로 갱신하고 제어 worker는 센서/모터 처리 주기를
유지한다. 예산 초과는 정지 상태에서 `PLANNING_TIMEOUT`으로 기록한다. 정상 작업의
소요 시간 분포를 측정해 예산을 조정하며, 입력/ACK/센서 시간 제한을 함께 늘리지 않는다.

새 파일은 기존 책임으로 수용하기 어려운 계약/기하 부분에 한정한다. 아래 순서대로
구현하고 각 작업은 독립적인 로컬 결과물과 통과 조건을 가진다.

| 순서 | 작업/파일 | 구체 산출물·통과 조건 |
|---|---|---|
| A | 새 `assistant/alignment_contracts.py`, 기존 `object_alignment.py` | object/surface/epoch/hash 계약, stale/다른 ID 거부, 설명 가능한 단계별 이유 |
| B | 기존 `stationary_lift.py`, `object_alignment.py`, `StationaryArm` 배치 FK | 고정 높이 우선·실제 stock 접촉 surrogate·bin 다양성·자가충돌 캐시. rotation/translation 불변성 및 독립 FK 대조 |
| C | 기존 `mask_cloud`, `assistant/perception.py`, `SearchSession`; 새 `assistant/view_geometry.py` | 지역 형상/부분 가림, 상판 기반 동적 viewpoints, 투영/가림/실측 view 검증 |
| D | 기존 `navigation_fusion/depth`; 새 `alignment_navigation.py` | 국소 SE2 A*와 높이별 sweep, 기존 Nav2Port FollowPath 추가, Transit/Align 설정. 좁은 통로/회전/뒤쪽 미관측 테스트 |
| E | 기존 `assistant/placement_binding.py`, `mission_catalog.py`, `runtime_factory.py` | `PrealignmentPolicy` 전략 추가. coarse-grasp 의존 제거, 정렬 후 fresh capture 강제, simulation 분기 보존 |
| F | 기존 `carry_contact_ik/planning/moveit/live_inputs`, `ManipulationPort` | 정렬→GraspNet→전체 집기 경로, scene continuity와 단계별 제한 재정렬. S3 보정·접근 회귀 통과 |
| G | 기존 `carry_posture`, `payload_monitor`, `carry_observation`, `navigation_binding` | payload attach/관측 가능한 운반 자세·전환 경로·retention evidence·주행 envelope |
| H | 새 `place_geometry.py`; 기존 `plan_place_carry`, program/execution/scene | 빈 면 erosion/후보, held transform, typed place program, 제한개방/해제/후퇴·독립 결과 검증 |
| I | 기존 STM32 공통 코어, `base_driver`, `runtime_factory`, `build_guarded_navigation` | 한 제어기/한 소유자에서 base/팔/lift 전환. 실제 보드 배포 전 native+host 부하/fault 시험 |
| J | 기존 `fetch`/앱/기록 도구 | 작업 선택→진행→취소/복구, 각 후보 시각화·실패 이유·물체/목적지 결과. 하드웨어 disabled 기본값 유지 |

A→B/C→D/E→F/G/H를 로컬에서 진행할 수 있다. I의 로컬 검사는 병행 가능하나 실제
보드 교체는 준비된 release와 현장 지지 상태를 확인하는 별도 실물 단계다. J를 붙여
전체 모의/실제 ROS 재생이 통과한 뒤 실물로 간다. 처음부터 새 프레임워크/모델을 만들지 않는다.

새 진단/실행 입구는 기존 `review_object_alignment.py`를 확장해 `review`와
`replay-full-task`를 제공한다. 실물 실행은 기존 `home_assistant.py`/runtime 경로로만
연결한다. 후보 JSON을 실행 스크립트에 직접 넘기는 우회 CLI를 만들지 않는다.

## 15. 검증 데이터·실물 인수 기준

### 로컬 / 기록 기반

- 알고리즘: 4기본형상에 비대칭/부분가림/좁은 틈/너무 넓은 물체/빈 깊이 추가.
  학습/튜닝에 쓰지 않은 회전·크기·상판 높이로 비교한다. 물체 label을 바꿔도 같은
  점군이면 같은 결과, map 변환 시 상대 해 동일, 좌우 팔 mount 차이 반영을 검사한다.
- 정차 품질: 현 위치 고정, 고정거리/정면 배치, 새 알고리즘을 같은 입력·동일 충돌
  검사/예산으로 비교한다. 실행가능한 정밀 파지 비율, 이동량, 재정렬, 계획시간,
  false rejection을 기록한다. 후보 수가 많다는 것을 성공률로 쓰지 않는다.
- 실제 ROS: 기존 Nav2/native plant/MoveIt 프로그램에 합성 입력을 연결한다. 속도·
  controller load와 perception 병렬 부하, 전환 중 stop·timeout·clock reset을 넣는다.
- 놓기: held transform이 달라진 경우, 탁자 가장자리/가득 참/가림, 해제 전 취소,
  해제 후 물체 안 보임을 독립적으로 검증한다. 전체 task의 실패가 torque OFF로 연결되지 않아야 한다.
- 시각화: 물체 점군, 작업 영역/closing축, 후보 base footprint/카메라 시야/팔 모델,
  선택·거절 원인, 이동/상부접근/하강/운반/놓기 경로를 같은 좌표에서 확인한다.

### 실물 단계

| 단계 | 사용자가 준비할 것 | 로봇이 스스로 해야 할 것 | 판정 |
|---|---|---|---|
| P0 공통제어 | 팔·리프트 지지와 짧은 주행 구역 | 현재 자세 유지, 짧은 goal 주행·정지, 팔/높이 단계 전환 | 이전 텔레옵+S3 회귀와 실제 stop/hold 통과 |
| P1 정렬만 | 서로 다른 물체/방향 배치, 시작 베이스는 집기 좋게 맞추지 않음 | 관측→후보→이동→높이→새 촬영→정밀 집기 경로 생성 | 손목/관절 여유·전체 STL 경로 통과, 실패는 이유 분류 |
| P2 집기 | 단단하고 관측 가능한 물체4개, 각3방향×2위치=24조건 | 사람이 미세 베이스 보정하지 않고 정렬→집기→들기·유지 | 초기 목표20/24 이상, 실패도 모두 보존. 첫 파지/재정렬 후 성공 분리 |
| P3 같은 구역 배송 | 전원선 안의 출발/목적 면 | 집기→운반 자세→실제 base 이동→새 상판 관측→놓기 | 초기 목표10회 중8회 전체 성공. 물체별 결과를 별도 표시 |
| P4 복구 | 경로 막힘·물체 옮김·목적지 점유·취소의 감독 시험 | 정지/재관측/제한 재계획 또는 설명 가능한 종료 | 뜻하지 않은 이동·개방·토크 해제가 없어야 함 |

계획된 마지막 finger/table 접촉과 접근 중 끌림/충돌을 구분한다. 후자는 실패다.
drop 또는 개입은 성공 횟수에 넣지 않는다. 성공24회 같은 새 절대기준을 기존 S3
완료 판정에 소급 적용하지 않는다. 위 비율은 개발 이정표이며 가정 일반 신뢰성 주장이 아니다.

S4b의 초기 완료는 **검증한 지도·물체·전원선 구역 안의 전체 동작**으로 명시한다.
배터리 없이 방 간 이동이 불가능하면 집 전체 운반은 미검증으로 남긴다. 사용자 결정으로
이관한 자동 탐색만 별도 항목이며, 이 계획 작성이나 로컬 통과를 S4 완료로 표시하지 않는다.

## 16. 결정된 것과 실측할 것

알고리즘/모델/파일 책임/상태전이/인터페이스/초기 표본 예산/검증 순서는 위에서 결정했다.
추가 모델 선택이나 구현 방식 결정을 기다리지 않고 A부터 착수할 수 있다.

실측값은 구현 선택과 구분한다: 실제 속도명령 이득·제동거리, lift 원점/반복성,
운반 자세의 카메라 가시성, grip effort/gap 기준, 깊이 위치 불확실성, 실제 유효 물체
범위는 P0~P3 자료로 채운다. 값이 미확정이면 로컬 replay는 실행할 수 있으나 관련
물리 단계는 활성화하지 않는다. 사용자에게 일반적인 설계 선택을 반복 확인하지 않는다.
