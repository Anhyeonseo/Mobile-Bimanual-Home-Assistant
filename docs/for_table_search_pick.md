## 1. 알고리즘 (확정안)

### 1-1. 고정 조건

- 탁자 높이 = 수납장 높이(약 73 cm). **리프트는 최상단 고정**, 이동 중에도 움직이지 않는다. 계획 높이 모델은 하루 동안 하나로 고정하고 기록한다(2-5 #1).
- 베이스는 **vy(좌우)만**. vx = 0, wz = 0.
- 이동은 **빈손일 때만**. 집기 실행이 시작된 뒤에는 이 흐름을 쓰지 않는다.
- 이동 뒤에는 **이전 촬영·후보·경로를 재사용하지 않는다.** 반드시 새로 찍는다.

### 1-2. 쓰는 값

| 기호 | 뜻 | 출처 |
|---|---|---|
| `s` | 시작점 기준 베이스 좌우 위치 (왼쪽 +) | 바퀴 피드백 적분 또는 시간 × 실측 속도 (B 결과로 결정) |
| `[s_min, s_max]` | 허용 범위 | 탁자 양 끝에서 (로봇 반폭 + 10 cm) 안쪽. 현장에서 재서 기록 |
| `x_obj, y_obj` | 현재 base 좌표의 물체 중심 | 새 촬영 → 기존 탐지·분할·깊이 |
| `R_a` | 팔 a의 검증 영역 (탁자 위 x·y 범위) | 2-2 지도 → C 실물 확인 |
| `e_stop` | 좌우 이동 오차 상위 95% | B |
| `F(s)` | 위치 s에서 카메라가 보는 탁자 y 구간 | 보정 프로필 + 내부 파라미터로 화면 모서리를 탁자 평면에 투영 (2-3) |
| `D_max` | 총 이동 상한 | `2 × (s_max − s_min)` |

### 1-3. 의사 코드

```
s = 0, 본 구간 C = {}, 이동 누계 D = 0, 보정 이동 = 0

loop:
  정지 확인 (바퀴 속도 0, T초 유지) → 촬영
  C ← C ∪ F(s)
  탐지 = 기존 Grounding DINO → SAM → 깊이

  [못 찾음]
    C가 탁자 범위를 다 덮음        → return NOT_FOUND
    s_next = 안 본 쪽 가장 가까운 방향으로 (F 폭 − 겹침 10 cm) 이동
    s_next를 [s_min, s_max]로 자름, D + |이동| > D_max 이면 → return BUDGET_EXCEEDED
    move_lateral(s_next); continue

  [찾음]
    두 장 연속 같은 위치(차이 ≤ 2 cm)가 아니면 재촬영 1회, 그래도 아니면 → return UNSTABLE_DETECTION
    대상 후보 2개 이상                → return AMBIGUOUS   (임의로 고르지 않음)
    이전 이동 뒤라면: 예측 위치 (y_old − 실제 이동)에서 e_stop + 2 cm 넘게 벗어나면 → return REIDENTIFY_FAILED

    for 팔 a in 검증된 팔:                       # 처음엔 왼팔만
        R_a' = R_a를 y 방향으로 e_stop만큼 줄인 범위
        x_obj ∉ R_a'의 x 범위               → 이 팔 제외 (좌우 이동으로 못 고침)
        Δ_a = y_obj를 R_a' 안에 넣는 최소 이동 (이미 안이면 0)
        s + Δ_a ∉ [s_min, s_max]           → 이 팔 제외
    남은 팔 없음                            → return OUT_OF_RANGE (팔별 이유 기록)
    a* = argmin |Δ_a|, 같으면 왼팔

    Δ_a* == 0  → 기존 집기 (capture → candidates → plan → validate → execute) → return 결과
    보정 이동 ≥ 2                          → return STOP_NOT_CONVERGED
    보정 이동 += 1; move_lateral(s + Δ_a*); continue
```

**부호 주의:** 베이스를 +Δ(왼쪽)로 움직이면 base 좌표에서 물체의 y는 −Δ만큼 변한다. 그래서 `Δ_a = y_obj − (R_a' 안의 가장 가까운 y)`이다. 판단 모듈 시험에 반드시 포함한다.

### 1-4. 종료 코드

| 코드 | 뜻 | 사람이 할 일 |
|---|---|---|
| 집기 결과 | 기존 Pick Station 결과 (`UNVERIFIED` → 사용자 판정) | 성공·실패 기록 |
| `NOT_FOUND` | 범위 전체를 봤는데 없음 | 정상 종료. 물체가 실제로 없었는지 확인 |
| `OUT_OF_RANGE` | 찾았지만 어느 팔의 검증 영역에도 못 넣음 (x가 너무 멀거나 범위 끝) | 위치 기록 |
| `AMBIGUOUS` / `UNSTABLE_DETECTION` / `REIDENTIFY_FAILED` | 인지 문제 | 사진 보관, 집기 실패와 따로 집계 |
| `STOP_NOT_CONVERGED` / `BUDGET_EXCEEDED` | 이동 문제 | B 결과와 비교 |

### 1-5. `move_lateral(s_target)`

- **기존 집기 하드웨어 프로세스 안에서** `MobileClient.arm → velocity → stop`을 쓴다. `pick_hardware.py`가 이미 `self.mobile`을 같은 전송로로 만들고 있다(지금은 상태 조회만).
  - 바퀴(7/8/9)는 왼팔·리프트와 **같은 USART1 버스**다. 다른 프로세스로 포트를 열지 않는다.
- 낮은 속도·낮은 가속. **리프트가 최상단이라 무게중심이 높다.** 첫 이동은 사람이 옆에서 받칠 준비를 한다.
- 팔은 운반(쉬는) 자세 유지. 이동 중 팔·리프트에 쓰기 없음.
- 종료 조건: 목표 도달 / 시간 초과(예상 시간 × 1.5) / 피드백 끊김 / 범위 이탈 예측 → 모두 `stop()` 후 정지 확인.
- 반환: 명령 이동량, 바퀴 추정 이동량, 걸린 시간, 정지 확인 결과.

## 2. 출발 전 (데스크탑)

### 2-1. 브랜치

- 집기 코드(`pick_*.py`)는 `main`(PR #31)에만 있다. `yeoeun/extrinsic-calibration`과는 갈라져 있고, 병합하면 3개 파일이 충돌한다(`CURRENT_STATUS.md`, `EXTRINSIC_CALIBRATION_HANDOFF_20261117.md`, `tests/test_measured_calibration.py`).
- **이 작업은 `main`에서 새 브랜치(예: `yeoeun/table-search-pick`)로 한다.** 보정 브랜치 병합은 별도로 처리한다.

### 2-2. 검증 영역 지도 (오프라인) — H1

목적: 탁자 위 어느 물체 위치에서 **편 자세 해**가 나오는지 계획기로 먼저 본다. 자로 잰 상수를 넣지 않는다.

방법: **실제 저장 촬영을 좌우로 평행 이동해서 재계획.**
1. 성공한 촬영(11/20 Pick Station 기록 또는 `pick-no-route-*/prepared.json`)을 입력으로 쓴다.
2. 물체 점군·물체 면·관측된 다른 물체를 base 좌표에서 y로 −20 … +20 cm(2 cm 간격) 옮긴다. x도 몇 단계(앞뒤 3–4개) 옮긴다. 탁자 평면은 y로 무한하다고 보고 그대로 둔다. **수납장 가장자리처럼 y 경계가 있는 장애물은 같이 옮긴다.**
   - `prepared.json`의 구조를 먼저 확인한다. 평행 이동을 넣을 자리가 없으면, 탐지 이후 단계(후보 생성)의 입력 점군에 적용한다.
3. 칸마다 기존 `check_pick_regressions.py`와 같은 경로(`station_plan_options` → `validate_pick_plan`)로 계획하고 기록한다.
   - 경로 유무, 거절 사유 (`pick_recovery` 분류)
   - 해의 어깨(2번)·팔꿈치(3번)·손목 굽힘(4번) 각도
   - 자세 분류: **편** (팔꿈치 −0.5 … 0 rad) / **접음** (팔꿈치 < −1.0 rad) / 중간
4. 출력: `region_map_left.json` + 그림 (x–y 격자, 칸 색 = 없음/접음/중간/편).

판정:
- 11/18 `-40` 위치 (x 375, y 148 mm)가 "편" 칸에 찍히는지 확인한다. 아니면 분류 기준이나 이동 구현이 틀린 것이다.
- **예상:** 5축 팔이라 높이가 고정되면 자세는 주로 어깨로부터의 수평 거리로 정해진다. 편 자세 영역이 어깨 정면이 아니라 고리 모양으로 나오면, "왼팔 정면 정렬"이 오히려 접은 자세를 만든다는 뜻이다. 그림으로 확인해서 발표에 쓴다.
- `R_left` 후보 = 편 칸들의 x·y 범위. C 블록에서 실물로 줄인다.
- 같은 지도에서 **A 규칙(경로만 있으면 됨)과 B 규칙(편 칸)의 정지 위치가 달라지는 물체 위치**를 3곳 골라 둔다. F 블록은 이 3곳에서만 한다(두 규칙이 같은 곳에 서면 비교가 안 됨).

### 2-3. 카메라 탁자 시야 `F(s)` (오프라인)

- 측정 보정 프로필의 `base_from_optical` + 리프트 최상단 모델 높이 + 카메라 내부 파라미터로 화면 네 모서리 시선을 탁자 평면(z ≈ 735 mm)에 투영한다.
- 탐지 신뢰 구간으로 쓰기 위해 화면 가장자리 10%는 뺀다.
- 결과: 로봇 앞 탁자 띠(x 범위)에서 보이는 y 구간 `[y_lo, y_hi]`. 탐색 칸 = `(y_hi − y_lo) − 10 cm`.
- 이 폭이 탁자 길이보다 넓으면 탐색(E)은 거의 필요 없다. 그 경우 E는 "범위 끝 물체"와 "물체 없음" 시험만 한다.

### 2-5. 현서에게 미리 확인

1. **높이 모델:** 웹 기본값은 `encoder_no_sag`이고, 11/20 성공은 `field_effective`(630)였다. 오늘 하나로 고정한다. 어느 쪽으로 할지 정한다.
2. S4 펌웨어에서 `MobileClient.arm/velocity`를 집기 프로세스 안에서 써도 되는지. 바퀴 세션과 팔 STOP·heartbeat가 서로 끊지 않는지.
3. S4 상태 응답에 **바퀴 위치·속도 피드백**이 있는지 (v7 `wheel_feedback` 같은 것). 없으면 `s`는 시간 × B에서 잰 속도로만 추정한다.
4. 리프트 최상단에서 베이스를 움직여도 되는지 (리프트 유지 편차 96 count 정지 조건, 전복 여유).
5. 탁자 길이와 로봇 시작 위치. `s_min`, `s_max`를 같이 정한다.

- [ ] 높이 모델(2-5 #1) 기록
- [ ] 탁자 양 끝 위치에 테이프 표시 → `s_min`, `s_max` 결정·기록

### B. 좌우 이동 정확도 (45분) — H2

**자로 재지 않는다.** 탁자에 고정한 표적지를 보정된 카메라로 찍어서 이동량을 잰다.

1. 표적지 2장을 탁자 위에 테이프로 고정한다. 간격은 어느 위치에서든 1장 이상 화면에 들어오게 한다. **실험 중 절대 건드리지 않는다.**
2. 팔 쉬는 자세, 리프트 최상단, 빈손.
3. 시도마다: `촬영(BASE-xxx-pre)` → `move_lateral(명령 거리)` → 정지 확인 → `촬영(BASE-xxx-post)`

| 명령 | 방향 | 횟수 | 이름 |
|---|---|---|---|
| 10 cm | 왼 / 오 | 각 3 | `BASE-L10-1..3`, `BASE-R10-1..3` |
| 20 cm | 왼 / 오 | 각 3 | `BASE-L20-…`, `BASE-R20-…` |
| 40 cm | 왼 / 오 | 각 2 | `BASE-L40-…`, `BASE-R40-…` |

4. 매번 기록: 명령 거리, 바퀴 추정 거리(있으면), 걸린 시간, 정지 결과.

분석 (`base_steps.py`): 표적지 PnP로 **실제 Δy, 의도하지 않은 Δx, Δyaw**를 구한다.

판정:
- 실제/명령 비율이 방향별로 일정하면 → 그 비율로 `move_lateral` 거리를 보정한다. 오차 상위 95% = `e_stop`.
- 비율이 거리마다 다르면 → 짧은 이동 여러 번으로 나눈다(보정 이동 2회 규칙 유지).
- `e_stop`이 `R_left`의 y 폭 절반 이상이면 → 줄인 영역 `R_left'`가 비어 버린다. 바퀴 피드백이나 라이다 위치를 쓰기 전에는 D로 가지 않는다.
- |Δyaw|가 2° 이상이면 → 탐색 시 다시 찍을 때 x가 틀어진다. 기록하고, 다시 찍어서 처리한다(보정 회전 안 함).

### C. 검증 영역 실물 확인 (60분) — H1

2-2 지도에서 고른 점에 물체를 두고 **베이스는 움직이지 않고** 기존 Pick Station으로 집는다.

| 자리 | 지도 분류 | 횟수 |
|---|---|---|
| C1 | 편 영역 중앙 | 2 |
| C2 | 편 영역 왼쪽 끝 | 2 |
| C3 | 편 영역 오른쪽 끝 | 2 |
| C4 | 접음 영역 (A 규칙이 서는 곳) | 2 |

시도마다: 계획 자세(어깨·팔꿈치·손목 굽힘), 성공·실패, 실패 모습(위에서 닫힘 / 밀림 / 빗나감), 도착 사진.

판정:
- C1–C3가 성공하고 C4가 실패하거나 높이가 틀어지면 → 지도 분류가 실물과 맞다. `R_left` 확정.
- 끝(C2, C3)에서 실패하면 → 그 끝을 잘라 `R_left`를 줄인다.
- C4도 성공하면 → H1의 근거가 약해진다. 그대로 기록하고 F에서 판단한다(결론을 바꾸지 않는다).

### D. 이동 후 집기 (60분) — H2

시야에는 있지만 `R_left` 밖인 물체. **탐색은 끈다**(찾음 분기부터 시작).

| 자리 | 내용 | 횟수 |
|---|---|---|
| D1 | `R_left`에서 왼쪽으로 15 cm 밖 | 2 |
| D2 | 오른쪽으로 15 cm 밖 | 2 |
| D3 | 30 cm 밖 (보정 이동이 필요할 수 있음) | 2 |

시도마다: Δ 계산값, 실제 이동(멈춘 뒤 촬영에서 물체 위치로 역산), 보정 이동 횟수, 같은 물체 판정 통과 여부, 집기 결과, 단계별 시간.

판정:
- 정차 잔차가 있어도 집기가 성공하면 → H2 확인. 정밀 정차는 필요 없다.
- `STOP_NOT_CONVERGED`가 나오면 → B의 `e_stop`과 비교. 바퀴 이동 문제인지, R 영역이 너무 좁은지 구분한다.

### E. 탐색 (40분) — H3

| 시나리오 | 배치 | 기대 종료 | 횟수 |
|---|---|---|---|
| E1 | 시작 시야 밖, 왼쪽 끝 근처 | 찾고 집기 | 2 |
| E2 | 시작 시야 밖, 오른쪽 끝 근처 | 찾고 집기 | 2 |
| E3 | 탁자에 대상 없음 | `NOT_FOUND` | 1 |
| E4 | 대상 + 비슷한 방해 물체 | 대상 집기 또는 `AMBIGUOUS` | 1 |

시도마다: 탐색 칸 수, 총 이동, 칸마다 탐지 점수, 종료 코드, 시간.

판정:
- E3에서 무엇이든 집으려 하면 → 오탐. 탐지 기준(연속 2장, 깊이 유효)을 다시 본다. **이 경우 E1·E2 성공도 보고에서 따로 표시한다.**
- E1·E2가 범위 끝에서 `OUT_OF_RANGE`이면 → 정상 동작이다(범위 제한이 일한 것). 실패로 세지 않는다.

### F. A/B 비교 (60분) — H1 판별

2-2에서 고른 **두 규칙의 정지 위치가 다른 3곳**에서, 같은 물체·같은 시작 위치로 규칙만 바꾼다.

| 규칙 | 정지 기준 |
|---|---|
| A | 경로가 나오는 최소 이동 위치 (`R` = 경로 있는 칸 전체) |
| B | 편 자세 영역 `R_left'` 안 |

- 3곳 × 2규칙 × 2회 = 12회. 순서는 섞는다(A, B, B, A …).
- 기록: 성공·실패, 계획 자세, 손끝이 물체 윗면 근처에서 닫혔는지, 이동량, 시간.

판정:
- B의 성공이 A보다 많거나, A의 실패가 접은 자세에 몰려 있으면 → H1 지지.
- 차이가 없으면 → "자세 기준 정지의 효과를 확인하지 못함"으로 보고한다. 횟수가 적다는 점을 같이 쓴다.

### G. 오른팔 (시간 되면)

- C 블록과 같은 방법으로 오른팔 고정 위치 집기 2곳 × 2회. 성공하면 `R_right`를 지도로 만들고 판단 모듈의 팔 후보에 넣는다.
- 시간이 없으면 보고에 **"팔 선택 규칙 구현, 오른팔 실물 미검증"**으로 쓴다.

## 5. 하지 않는 것

- 리프트 높이 바꾸기, 앞뒤(vx)·회전 이동
- 정밀 정차를 위한 반복 보정 (보정 이동은 최대 2회)
- 물체를 든 채로 베이스 이동
- 이동 후 이전 사진·경로 재사용
- 이동 거리를 줄자로 재서 입력하기
- 한 번 성공으로 결론 내기. 시뮬레이션·계획 성공을 실물 성공으로 세기
- 단계 승인 없이 여러 시도를 자동으로 연속 실행하기
