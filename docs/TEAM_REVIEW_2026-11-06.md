# 팀 주요 회의 기록 · 인식과 로봇 제어 연결

2026-11-06. 기준은 [기존 시스템 설계](MOBILE_MANIPULATION_DESIGN.md)다. 이 기록은 신규 근거와 연결 결정을 추가한다. 제품 범위·합의된 계층·수락 기준을 교체하지 않는다.

## 유지하는 목표

한국어 요청 → 앱을 통한 최초 스캔과 가구·물체 기억 → 방 사이 이동 → 정차·높이 선택 → 관측 기반 집기·운반·놓기 → 실제 결과 확인. 첫 이정표는 고정 베이스·왼팔·검증된 작업대에서 위치와 방향이 달라진 물체를 처리하는 것이다. 리프트도 첫 집기 동안 정지한다. 최초 스캔의 텔레옵/자동 선택은 보류한다. 침대 다리 사이처럼 2D LiDAR만 보면 빈 공간인 곳도 RGB-D와 로봇 전신 높이를 반영해 **지도 생성·저장 시점부터** 차단한다.

## 통합 시 책임

| 담당 | 인계하는 값 | 인계하지 않는 판단 |
|---|---|---|
| 언어·인식 | 요청 슬롯, 선택 기준, 근거가 있는 관측, 보류·거절 이유 | 모터 명령, 화면 좌우를 방 기준 좌우로 추정하는 일 |
| 좌표·기억 | 촬영·원점·보정·장치 식별이 일치하는 좌표, 근거와 상태 | 표면점이나 보이는 중심을 접촉점으로 바꾸는 일 |
| 집기 계획·실행 | 실제 집게 폭과 접촉점, 왼팔 도달성, 장면 충돌, 접근·후퇴, 하중 유지·놓기 확인 | 후보 생성 성공을 실제 집기 성공으로 표시하는 일 |

Qwen+재확인은 비교 후보·기준선으로 활용한다. 기존 DINO/SAM을 폐기하거나 최종 모델을 확정한 것이 아니다. 실험 코드의 executable은 실행 권한으로 사용하지 않는다. Jetson 동시 처리 지연과 불확실한 대상 재관측은 별도 검증한다.

## 첫 집기 시험 순서

1. 컵 두 개를 놓고 **화면 기준 왼쪽 컵**을 선택한다. 동일 촬영의 원본 RGB·정렬 깊이·모터 상태를 보존한다. 보류·거절·겹쳐 구분이 안 되는 후보이면 중단한다. 목표는 로봇 기준 관측점 표시이며 동작하지 않는다.
2. 독립 기준점으로 오차를 확인하고, 측정한 집게 여유를 기준으로 허용치를 먼저 정한다. 실제 집게 접촉점, 지지면, 접근 방향·폭, 왼팔 IK와 전 구간 충돌을 검증한 후 물체에서 여유를 둔 접근 시험을 한다.
3. 검증한 가벼운 물체를 집어 들어 올리고 정해진 자리에 놓는다. 기존 PickPlacePort의 잡힘·부하 유지·해제 확인을 사용한다. 물체 위치/방향을 바꿔 저장 자세 재생 없이 반복하고 실패·취소도 기록한다.

**상태:** 관측 인계의 오프라인 개발을 시작했다. 실제 새 촬영, 독립 접근 오차, 실제 집기·놓기 성공은 미확인이다. 현재 조회 전용 제어기로는 팔을 움직일 수 없다.

### 재현 방법: 움직이지 않고 첫 대상 좌표 표시

새 **호스트** 패키지의 `capture_s2_observer.py`에 `--rgbd --home-and-bottom-confirmed --snapshot-root <새 세션 폴더>`를 추가한다. 기존 5초 검사와 동일한 장치/프로필 검사를 적용한다. 모터 전원과 지지 상태, 양팔 기본 자세·실제 최저점·베이스 정지가 확인된 경우에만 원점 확인 옵션을 사용한다. STM32 펌웨어 변경은 필요 없다. 이미지 저장에는 Pillow가 필요하다.

성공한 조회에서 선택된 프레임 한 건을 `<세션>/rgbd-<번호>/`에 color.png·depth_aligned.png·metadata.json으로 저장한다. PNG 기록은 모터 조회 루프 뒤에 수행한다. 조회 보고서에도 해당 sequence와 세 파일의 SHA-256을 남긴다. 촬영물과 장치 정보는 로컬 진단 자료다.

인식 파트에는 해당 폴더와 요청 대상(첫 시험: 컵)을 넘기고 **그 프레임에서** 산출된 `{"observations":[...]}`를 받는다. 프로필·카메라·시계는 로봇 측에서 검증하며, 발표 데이터의 이전 결과를 재사용하지 않는다. 현재 #26의 평가용 CLI는 정답 물체 목록으로 프롬프트를 구성하므로 무라벨 새 촬영의 사용자 요청 입력기로 사용하지 않는다. 실험 파트의 실제 요청→관측 호출은 후속 연결이다.

```sh
python3 tools/diagnostics/review_s3_capture.py \
  --snapshot <세션>/rgbd-<번호> --report <같은-조회-보고서.json> \
  --observations <해당-프레임-관측.json> --profile <릴리스>/profile.json \
  --label cup --screen-side left --output <새-결과.json> --preview <새-프리뷰.png>
```

이 도구는 **저장 자료용 표시기**다. 종료된 세션의 점을 현재 모터 목표로 보내지 않는다. 화면 기준 좌/우와 요청한 정확한 라벨만 지원하며, 박스가 겹치거나 깊이가 보류되면 재질문/재관측한다. 측정 표면점과 보이는 표면 중심은 각각 별도 필드이고 어느 쪽도 접촉점이 아니다.

**로컬 인계 상태:** 호스트 패키지 `s2-coordinates-85cc2c70b27e`를 생성해 파일 해시와 두 CLI의 실행 도움말을 확인했다. S2 프로필과 STM32 펌웨어 해시는 기존 실물 검사 때와 같다. 새 연결부·좌표·카메라·집기 순서·하중 확인 관련 로컬 검사 125개가 통과했다. 사용자 요청으로 젯슨 설치·배포와 실물 촬영은 보류했다. 재개 시 Pillow 설치 여부, 장치 연결, 물리 원점과 정지 상태부터 확인한다.

후속 리팩토링: 현재 로컬 관측 패키지는 `s2-coordinates-39a5492e02f2`다. 실물 배포 상태는 바뀌지 않았다. 경계·실패 단계·과거 기록 재생법은 [S2 인계의 코드 경계 절](S2_HANDOFF.md#코드-경계와-장애-재현-2026-11-06)을 따른다.
