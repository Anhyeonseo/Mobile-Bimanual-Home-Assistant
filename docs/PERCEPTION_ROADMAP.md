# 인식·언어·의미 지도 개발 로드맵 (여은 파트)

작성일: 2026-11-01 · 갱신: 2026-11-04 · 상태: 개발 계획안. 아래 기간·수치는 추정과 초기 목표이며, 진행 기록에 적은 것 외에는 달성 결과가 아니다.

## 범위와 역할

- **여은:**
  - L5: 한국어 요청 → `TaskRequest`, 스캔·대화 앱
  - L3A의 인식 부분: RGB-D → `ObjectObservation`
  - L3B: 의미 지도·`WorldEntity` 기억

  인터페이스를 먼저 정의하고, 로봇 동작과 별개로 녹화 데이터로 개발한다.
- **현서:** RGB-D·rosbag·보정 촬영 제공, 로봇 제어(L0–L2, L3C/L3D), 카메라 → 몸체 외부 보정(S2).
- 계층·계약의 기준은 설계 문서 v0.4(4·5·7절)다. 계약은 `home_perception/contracts.py`에 있고, 현서 쪽 코드가 이 계약에 맞춘다.

## 포트폴리오 스토리

> 실제 가정용 모바일 매니퓰레이터에서, 자연어로 지목한 물체를 찾아 3D 의미 지도에 기억하고, 비슷한 물체 중 "내 것"까지 구분하는 인식·기억 시스템을 만들고 실데이터 벤치마크로 검증했다.

1. **자체 실데이터 벤치마크:** 로봇 D415로 촬영하고 라벨링한 데이터셋.
2. **비교 실험으로 증명:** zero-shot은 기준선으로 유지하고, 추가 학습·개인화와 같은 test 세트에서 비교한다.
3. **실패 분석:** 깊이 누락, 유사 물체 오인 등을 원인별로 분류한다.

## P0. 계약과 데이터 준비 · 1주

**할 일**
1. `contracts.py`에 4개 타입과 실패 코드(`NOT_FOUND`, `AMBIGUOUS_TARGET`, `INVALID_DEPTH`, `STALE_OBSERVATION`)를 정의하고 JSON 직렬화·단위 테스트를 작성한다. **완료.**
2. 현서에게 촬영을 요청한다. **요청서 작성 완료**(공유 문서 "현서에게 부탁할 촬영 목록"). 세트별로 나눴다.

   | 세트 | 내용 | 쓰는 단계 | 시점 |
   |---|---|---|---|
   | A | 같은 종류지만 구분되는 물체를 한 장에 하나씩 바꿔 가며 연속 촬영 + 이동 기록 | P3 연관 | 1차 방문 |
   | B | 체커보드 원점 + 줄자 위치. 1차는 0.7m·밝음만, 이후 거리·조명·가림 | P1 위치 오차 | 1차 방문(최소판) |
   | C | 로봇 장착 카메라 다중 시점 + TF·리프트 높이·rosbag | P3 지도 좌표 | S2 이후 |
   | D | 같은 종류 리모컨 3개 중 "내 것" | P5 | P5 시작 시 |
   | E | A·B와 다른 날·배치의 시험용 세트. 최종 평가 전까지 열지 않음 | 최종 평가 | A·B와 함께 |
   | F | 방 전체 손 스캔 (RGB+뎁스 `.bag`) | P6 | 1차 방문 |

   1차 방문 최소판은 A1(색이 다른 컵 2 + 리모컨) 8장, A3(같은 검은 컵 2) 4장, A 시험용 8장, B 최소판 5장, 약 25장과 방 스캔이다.
3. 라벨 규칙(박스, SAM 생성 후 수정한 마스크, 줄자 실측 위치)을 정하고, dev/test를 물체 인스턴스·촬영 세션 단위로 분리한다. test는 최종 평가 전까지 보지 않는다.

**촬영 순서 제약:**
- 카메라는 한 대이고 로봇에 약 45° 아래로 장착할 예정이다.
- 거치대·손으로 찍는 촬영(A, B, F)은 카메라를 로봇에 장착하고 외부 보정하기 **전에** 끝낸다. 보정 뒤 탈착하면 보정을 다시 해야 한다.
- 외부 보정 전까지는 카메라 위치를 바꿔도 된다. 다만 세트 A는 한 묶음 안에서 고정하고, 세트 B는 카메라를 옮길 때마다 체커보드부터 찍는다.

- **산출물:** 스키마, 촬영 요청서, 라벨 가이드
- **완료 기준:** 스키마 머지, 첫 녹화본 수령
- **강의 기술:** 4강(노출·블러 → 촬영 조건), 5강(D415 능동 IR 스테레오의 한계 → INVALID_DEPTH 사유), 12강(disparity ∝ 1/Z → 깊이 오차 ∝ Z², 불확실성 필드 근거)
- **포트폴리오:** 벤치마크 설계와 데이터 누수 방지

## P1+. 자동 라벨 → 경량 모델 증류 → Jetson · 2~3주

**왜 하나:**
- Qwen3-VL-4B + SAM은 GPU 메모리를 최대 9.2GB 쓰고 장면 하나에 초 단위가 걸린다. 그래서 PC·서버에서 돌리고, 로봇은 네트워크로 결과를 받는다.
- 로봇이 이동하며 반복해서 봐야 하는 순간(스캔, 접근 후 재관측, 집기 직전 확인)은 온보드 경량 모델이 맡는 것이 자연스럽다.
- 역할 분담: YOLO-seg는 Jetson에서 자주 쓰는 물체를 빠르게 계속 찾는다. Qwen3-VL은 PC·서버에서 새 물체를 말로 찾기, 재확인, 모호성 판단을 맡는다. YOLO는 정해진 물체 종류만 찾으므로 VLM을 대체하지 않는다.

**우선순위:** P3·P5 뒤로 둔다. 로봇이 멈춘 상태에서만 인식하고 네트워크가 안정적이면 PC·서버 추론으로도 충분하기 때문이다. 진행 여부는 현서 쪽 실물 구성(이동 중 인식이 필요한 작업이 있는지, 네트워크 안정성)이 정해진 뒤 결정한다.

**할 일**
1. P1 파이프라인으로 dev 녹화본을 자동 라벨링(`tools/run/export_yolo_dataset.py`)하고 약 20%를 사람이 검수. 깊이 공백으로 held인 컵도 마스크는 쓸 만하므로 `--include-held`를 쓴다.
2. YOLO-seg nano/small 학습
3. ONNX → TensorRT(FP16) 변환, Jetson에서 지연·메모리 측정. TensorRT 엔진은 Jetson에서 직접 만든다.
4. 학습에 쓰지 않은 인스턴스·세션(세트 E)으로 평가

- **산출물:** 학습 스크립트, 가중치, Jetson 벤치마크
- **완료 기준 (초기 목표):** 원본 대비 mAP 손실 ≤10%p, Jetson ≥10fps
- **선택:** Grounding DINO 또는 Qwen-VL에 LoRA 도메인 파인튜닝. 반드시 미사용 인스턴스·세션으로 zero-shot과 비교
- **포트폴리오:** 📊 표 2. 속도·정확도 trade-off (자동 라벨링 → 증류 → 엣지 배포)

## P3. 다중 시점 의미 지도 + 3D 장면 그래프 · 4주 (핵심 기여)

**할 일**
1. 촬영 시각 TF로 map 좌표 변환: `p_map = T_map_base(t) · T_base_cam(t) · p_cam`.
   - `T_base_cam`은 현서의 S2 외부 보정과 리프트 높이로 정해진다.
   - S2 전까지는 고정 카메라 좌표를 지도 대신 쓰고, 결과에 그렇게 표시한다.
2. `geometry/registration.py`: 마스크 안 SIFT → 매칭 → 3D → RANSAC 강체 추정 → ICP로 두 시점 상대 자세를 구해 TF와 교차 검증
3. `memory/association.py`: 3D 거리 + CLIP/DINOv2 외형 유사도(+ FPFH 형상)로 동일 물체 판단.
   - 헝가리안으로 짝짓고, 최선과 차선의 차이가 작으면 `unconfirmed`로 보류한다.
   - **촬영 세트 A 대기.** 11-01 데이터의 두 컵은 사람도 구분 못 하는 같은 컵이고 이동 기록이 없어 검증할 수 없다.
4. `memory/world_memory.py`: 상태(observed / unconfirmed / stale / occluded / carried / placed), last_seen, 위치 불확실성. 안 보인다는 이유로 삭제하지 않는다. **종류+거리 연관까지 구현.**
5. 가구 마스크를 누적해 바닥 영역·높이를 만들고 높이 장애물 지도(M10)로 전달
6. three.js 3D 장면 그래프 뷰: 점군 위 가구·물체 노드와 "책상 위 → 리모컨" 관계선, 클릭 시 마지막 관측 사진

- **산출물:** 의미 메모리 모듈, 장면 그래프 뷰어

2026-11-02 기본 VLM을 Qwen3-VL-4B로 바꿨다(비교는 `docs/QWEN3_VL.md`). 요청 해석 프롬프트가 색·`내` 꾸밈말을 떼던 문제를 프롬프트만으로 고쳐, 4B 요청 해석은 개발셋 92/93, 홀드아웃 40/40이다.

- 문장 → 물체 선택 연결(`tools/run/run_sentence_eval.py`, `config/perception_sentence_cases.json`): 한국어 문장을 `TaskRequest`로 해석하고, 꾸밈말을 포함한 target으로 검출·크롭 재확인한 뒤 위치어로 하나를 고른다. dev 촬영 7장, 21문장에서 21/21이다. 문장과 정답 박스는 같은 dev 촬영에서 만든 회귀 세트이며 일반 정확도가 아니다.
- `흰 컵`(검은 컵만 있음), `검은 리모컨`(흰 리모컨만 있음)은 검출기가 박스를 냈지만 재확인이 거절해 `NOT_FOUND`가 됐다. 꾸밈말이 효과를 내는 경로는 검출이 아니라 재확인이다.
- 같은 새 프롬프트에서 2B는 개발셋이 83 → 78로 떨어졌다. Jetson 등에서 2B로 돌아가면 프롬프트를 다시 평가한다.
- 아직 다루지 않음: `내 컵`처럼 소유를 뜻하는 꾸밈말(P5 개인화 전에는 화면으로 판단할 수 없음), `excluded`를 후보 제거에 쓰는 것.
