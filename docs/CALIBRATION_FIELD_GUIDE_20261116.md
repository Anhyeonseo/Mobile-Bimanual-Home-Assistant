# 카메라 + 팔 외부 보정 현장 가이드 (2026-11-16)

대상: 오늘 로봇 앞에서 촬영하는 사람(여은)과 도와주는 팀원 · 브랜치 `yeoeun/extrinsic-calibration`

오늘 목표는 **집기 오차를 줄이는 데 필요한 값을 한 번에 측정**하는 것이다.

- 카메라: pitch·roll·높이, 그리고 왼팔 기준 x·y·yaw
- 팔: 어깨·팔꿈치·손목 굽힘 영점, 중력 처짐, 명령값 대비 실제 위치, 유격
- 기타: 오른팔 장착, 리프트 배율·기울기, 집게 끝 위치, 렌즈 왜곡

이 문서는 [11/15 투어 가이드](CALIBRATION_TOUR_FIELD_GUIDE.md)를 대체한다.
배경과 앞선 결과는 [인계 문서](EXTRINSIC_CALIBRATION_HANDOFF.md)에 있다.

## 1. 11/15 가이드와 달라진 점

| 바뀐 점 | 이유 |
|---|---|
| **보정에는 토크를 켠 자동 촬영 사진만 쓴다.** 훑기 때 찍힌 사진(`SW*`)과 11/13 사진은 계획과 비교에만 쓴다 | 토크를 끈 채 손으로 잡으면 매번 하중이 다르다. 11/13 오차의 큰 원인으로 의심된다 |

| 광각 1280×720 + 고정 노출 16ms로 평면을 찍는다 | 지금 집기 촬영 설정과 같다. 자동 노출은 탁자 높이가 약 6mm 달라진다 |

| **손목 회전 영점**을 경사계로 잰다 | 마커 사진으로는 이 값이 구해지지 않는다. 집게 닫힘 선의 기울기와 직결된다 |
| 오른팔 받침이 흔들리는지 먼저 확인한다 | 11/13에 오른팔 받침 보정이 23mm·6°로 크게 나왔다 |
| 자동 촬영 때 **명령값과 실제값**을 둘 다 남긴다(도구가 이미 기록함). 반복 방문을 늘린다 | 서보 추종 오차와 유격이 "8mm 아래"의 유력한 원인이다. 오늘 처음으로 따로 잴 수 있다 |

## 2. 출발 전 준비

### 2-1. 인쇄

모두 **배율 100%로 인쇄하고, "용지에 맞춤"은 끈다.** 인쇄 후 100mm 눈금을 자로 잰다.
99.5–100.5mm가 아니면 다시 인쇄한다.

| 파일 | 장수 | 용도 |
|---|---|---|
| [`calibration_arm_markers_A4.pdf`](calibration_arm_markers_A4.pdf) | 2 | 팔 마커. 한 장에 왼팔 id 4 ×2, 오른팔 id 5 ×2가 있다(예비 포함) |
| [`tcp_touch_target_A4.pdf`](tcp_touch_target_A4.pdf) (가로) | 2 | 집게 끝 표적지. id 1, id 2와 십자 표시 |
| [`calibration_checkerboard_A4.pdf`](calibration_checkerboard_A4.pdf) (가로) | 1 | 렌즈 확인용. 10×7칸, 25mm. 11/13 체커보드가 현장에 있으면 그걸 써도 된다 |
| 이 문서 | 1 | 7·10·13장은 현장에서 계속 본다 |

### 2-2. 마커 판 만들기 (팔마다 하나, 예비 하나)

1. 점선을 따라 90×90mm로 자른다. 검은 네모 바깥의 **흰 테두리 1cm를 남긴다.**
2. 약 10×10cm 폼보드나 아크릴에 **양면테이프로 평평하게** 붙인다. 기포나 주름이 없어야 한다.
3. **검은 네모의 네 변을 캘리퍼로 0.1mm 단위까지 잰다.** 기록표에 적는다.
   70.0mm에서 0.3mm 넘게 다르면 예비로 다시 만든다.
4. 판 뒷면에 `L id4` 또는 `R id5`라고 쓴다.

- [ ] 양면테이프, 박스테이프, 마스킹테이프, 펜
- [ ] 노트북과 충전기

### 3-1. 노트북에서 Jetson에 접속이 안 될 때 (2026-11-16 현장 확인)

증상: 같은 와이파이(`SK_WiFiGIGAE498`)인데 노트북에서 `ping 192.168.35.2`와 `ssh`가 응답이 없다.
Jetson에서 노트북으로 보내는 ping도 안 된다. 현서 오빠 PC(`192.168.35.164`)에서는 된다.

원인: Jetson은 **2.4GHz**(2452MHz), 노트북은 **5GHz**에 붙어 있었고, 공유기가 두 대역 사이 통신을 막는다.
Jetson 쪽 방화벽은 없다(iptables 전부 ACCEPT).

해결: 노트북을 2.4GHz로 고정한다.

```bash
nmcli connection modify "SK_WiFiGIGAE498" 802-11-wireless.band bg
nmcli connection up "SK_WiFiGIGAE498"
ping -c 3 192.168.35.2
# 끝나고 되돌리기
nmcli connection modify "SK_WiFiGIGAE498" 802-11-wireless.band ""
nmcli connection up "SK_WiFiGIGAE498"
```

다른 방법: 오빠 PC를 거쳐 접속(`ssh -J an-hyeonseo@192.168.35.164 hyper@192.168.35.2`), 랜선, Jetson USB-C 직결(`192.168.55.1`).

## 4. 실측 (로봇 안 움직임, 토크 끔, 펌웨어 상관없음)

### 4-1. 오른팔 받침 흔들림

오른팔 어깨 아래 장착부를 손으로 앞뒤·좌우로 가볍게 흔든다. 장착부가 리프트 판에 대해 움직이거나 틈이 보이면,
**팀원과 상의해서 보정 전에 조인다.** 조였으면 기록표에 적는다. 보정 뒤에 조이면 오늘 결과를 못 쓴다.

### 4-2. 팔 링크 길이 (팔마다, 각 2번)

관절 회전축의 중심 사이 거리를 잰다. 서보 출력축(혼) 중심에서 다음 서보 출력축 중심까지다.
캘리퍼 끝을 혼 중심의 나사 머리 가운데에 댄다.

| 구간 | CAD 값 | 의미 |
|---|---|---|
| 어깨 굽힘(shoulder_lift) 축 → 팔꿈치(elbow_flex) 축 | 116.0mm | 위팔 |
| 팔꿈치 축 → 손목 굽힘(wrist_flex) 축 | 135.0mm | 아래팔 |

1mm 넘게 다르면 사진을 찍어 둔다. 11/13 분석은 "팔이 2.1% 길다"고 했는데, 이 측정으로 확인된다.

### 4-3. 체커보드 칸 크기

칸 5개 길이를 자로 재서 5로 나눈다. 가로와 세로를 각각 잰다. 소수 첫째 자리까지 적는다.

### 4-4. 탁자 높이 (줄자)

바닥에서 상판 윗면까지 잰다. 촬영할 자리에서 3곳을 잰다.

- **80cm 탁자**(11/13의 그 탁자): 분석 코드가 TB·TF 사진의 탁자를 80.0cm로 가정한다. 다른 탁자를 쓰면 높이를 반드시 적는다.
- **수납장 낮은 탁자**(집기 장소, 기록상 31.8cm)

## 5. 광각 카메라만 촬영 (현재 펌웨어 그대로, 약 30분)

제어기에 접속하지 않는 도구다. 그래서 **펌웨어를 바꾸기 전에** 지금 S4 release에서 찍는다.
도구는 깊이 노출을 16ms로 고정하고 3초 기다린 뒤 10초 동안 여러 장을 저장한다.

```bash
# Jetson (2026-11-16 확인: S4 파이썬은 s4-jazzy)
cd /home/hyper/robot/releases/s4-unified-pick-20261116
mkdir -p ~/cal_20261116
PY4=/home/hyper/robot/shared/venvs/s4-jazzy/bin/python
W() { "$PY4" tools/diagnostics/capture_height_window.py --output ~/cal_20261116/"$1" --camera-mode wide --seconds 10; }
W W-F-1                 # W 와 이름 사이에 한 칸 띄운다
```

결과가 `HEIGHT_WINDOW_RECORDED`면 성공이다. `RETRY_CAPTURE`면 이름 끝에 `b`를 붙여 다시 찍는다.
실패하면서 폴더만 생긴 경우(`File exists`)는 `report.json`이 `CAPTURE_FAILED`인지 보고 지우거나 새 이름으로 찍는다.

**실시간 화면으로 구도 맞추기** (노트북 터미널 하나로 서버와 터널을 같이 켠다):

```bash
ssh -t -L 18766:127.0.0.1:8766 hyper@192.168.35.2 "cd ~/realsense-grounding && HF_HUB_OFFLINE=1 .venv/bin/python tools/diagnostics/realsense_web.py --profile near --port 8766"
# 브라우저: http://127.0.0.1:18766   (8765는 이미 쓰는 중이었다)
```

화면은 640×480이라 광각 사진보다 좌우가 좁게 보인다. **찍기 전에 화면을 꺼야 카메라가 풀린다**
(`Device or resource busy`가 나오면 아직 켜져 있는 것). Jetson 창에서 끄고 바로 찍는 한 줄:

```bash
pkill -f realsense_web.py; sleep 2; W W-T80-1
```

찍은 결과는 첫 프레임을 PNG로 뽑아 확인한다:

```bash
"$PY4" -c "
import numpy as np, sys, glob
from PIL import Image
f=sorted(glob.glob(sys.argv[1]+'/*.npz'))[0]; Image.fromarray(np.load(f)['color_bgr'][:, :, ::-1]).save(sys.argv[1]+'/preview.png')" ~/cal_20261116/W-F-1
```

`W-T80`은 80cm 탁자(분석 코드가 80.0cm로 아는 기준면), `W-T32`는 약 31.8cm 낮은 협탁(집기 장소)이다.
카메라는 몸체 고정이라 **리프트 높이는 바꾸지 않아도 된다.** 접힌 팔이 상판을 가리지만 않으면 된다.
체커보드(`W-IN-*`)는 상자나 의자에 **기대 세워** 손을 뗀 상태로 찍는다(13초 동안 움직이면 안 된다).
화면 위쪽 모서리 = 로봇에서 먼 곳, 아래쪽 = 가까운 곳이다.

| 이름 | 장면 | 로봇·리프트 |
|---|---|---|
| `W-F-1` ~ `W-F-3` | 빈 바닥. 장마다 로봇 앞 물건 위치를 조금씩 바꾼다(다른 바닥 영역) | 리프트 지금 높이 |
| `W-T80-1` ~ `W-T80-3` | 80cm 탁자: 평소 자리 2장, 15cm 멀리 1장 | 같음 |
| `W-T32-1` ~ `W-T32-3` | 수납장 낮은 탁자(집기 장소) | 같음 |
| `W-IN-01` ~ `W-IN-08` (선택) | 체커보드를 화면 네 모서리에 하나씩, 50–60cm, 그다음 20–30° 기울여서 | 같음 |

- 촬영하는 13초 동안 **화면 안에서 아무것도 움직이지 않는다.** 사람도 화면 밖으로 나간다.
- 체커보드는 상자에 기대 세운다. 손으로 들면 흔들린다.
- 각 장면을 휴대폰으로 한 장씩 찍어 둔다.

## 6. 펌웨어를 S3(0x24911)로 교체 (팀원이 수행)

촬영 도구(`sweep`, `tour`, `rawshot`, `pose`)는 S3 펌웨어 0x24911만 받는다.
11/13에도 같은 release로 바꿨다. 현서 오빠 동의를 받고, 되돌리는 방법(14장)을 먼저 확인한 뒤 한다.

**안전 구조**: `flash.sh`는 펌웨어 해시를 검사하고, `program.cfg`가 **지금 펌웨어 전체(512KB)를 먼저 백업**
(`dump_image ... preflash-full.bin 0x08000000 0x80000`)한 다음에 쓰고 검증한다. 백업이 실패하면 쓰기로 넘어가지 않는다.
설치는 ST-LINK로 하므로 중간에 실패해도 다시 쓸 수 있다. 모터 전원이 꺼져 있어 로봇은 움직이지 않는다.

**스크립트가 메시지 없이 멈추는 조건** (먼저 확인):

## 8. 마커 부착

1. 마커 판을 집게의 **움직이지 않는 쪽 손가락(고정 손가락) 바깥면**에 양면테이프로 붙인다.
2. **박스테이프로 두 바퀴 이상** 감는다. 검은 네모와 흰 테두리는 가리지 않는다.
3. 판을 손가락으로 툭 쳐 본다. 흔들리면 다시 감는다.
4. 마커가 집게 끝보다 위쪽에 오게 한다. 집게를 닫았을 때 움직이는 손가락과 부딪히지 않아야 한다.
5. **왼팔 id 4는 `TL1`, 오른팔 id 5는 `TR1`이다.** 다시 붙이면 번호를 올린다(`TL2`). 기록표에 적는다.
6. 붙인 모습을 팔마다 두 방향에서 사진으로 찍는다.

**훑기부터 집게 끝 대기까지 마커를 떼지 않는다.** 판이 붙은 채로 훑어야 자동 촬영도 판까지 포함한 공간 안에서만 움직인다.

## 10. 손으로 훑기 (토크 끔, 로봇 안 움직임)

### 토크는 어떻게 되나 (오늘 전체)

| 상태 | 뜻 |
|---|---|
| 모터 전원 ON | 서보에 전기가 들어온다. 값을 읽을 수 있다. **팔은 힘이 없다** |
| 토크 ON | 서보가 자세를 잡는다. **오늘은 자동 촬영 도구(`tour`)만 토크를 켠다.** 사람이 따로 켜지 않는다 |
| 토크 OFF | 팔이 중력에 떨어진다. 훑기, 손목 영점, 집게 끝 대기는 토크 OFF여야 한다. 켜져 있으면 도구가 거부한다 |
| Ctrl+C / 비상 정지 | 펌웨어가 **토크를 끈다. 팔이 떨어진다.** 그래서 토크가 켜진 동안에는 항상 한 사람이 팔을 받칠 수 있는 자리에 있는다 |

### 순서

리프트 높이 5개 × 팔 2개 = 10번이다. 한 번에 3–4분 걸린다. **`--camera`는 붙이지 않는다**(손으로 잡은 사진은 보정에 쓰지 않는다).

| 순서 | 리프트 | 명령 |
|---|---|---|
| 1, 2 | 0.05 | `sweep SW05-L left 0.05` / `sweep SW05-R right 0.05` |
| 3, 4 | 0.17 | `sweep SW17-L left 0.17` / `sweep SW17-R right 0.17` |
| 5, 6 | 0.30 | `sweep SW30-L left 0.30` / `sweep SW30-R right 0.30` |
| 7, 8 | 0.42 | `sweep SW42-L left 0.42` / `sweep SW42-R right 0.42` |
| 9, 10 | 0.55 | `sweep SW55-L left 0.55` / `sweep SW55-R right 0.55` |

- 리프트는 팀원이 옮긴다. 명령의 높이는 **옮긴 목표 높이(m)**다. 실제 엔코더 값을 기록표에 적는다.
- 어떤 높이에서 팔이 화면에 거의 안 들어오면, 그 높이는 빼고 0.05–0.60 사이에서 다른 높이로 바꾼다. 바꾼 값을 자동 촬영에도 똑같이 쓴다.

### 한 번 훑는 방법

1. 양팔을 휴식 자세에 둔다. 명령을 친다. `logging ...`이 나오면 시작이다.
2. 훑는 팔을 천천히 꺼낸다. **손 한 뼘을 2초쯤에** 움직이는 속도다.
3. 아래를 모두 지나간다. 순서는 상관없다.
   - 어깨 회전: 카메라 앞에서 쓸 수 있는 범위의 왼쪽 끝 ↔ 오른쪽 끝
   - 멀리 ↔ 가까이: 쭉 뻗은 곳과 몸 가까이 접은 곳
   - 높게 ↔ 낮게: 카메라 화면 위쪽과 아래쪽. **리프트 0.05에서는 집기처럼 앞쪽 아래(수납장 상판 높이쯤)까지 내려간다**
   - **집기 자세**: 집게를 아래로 30–60° 숙이고, 닫힘 선을 수평으로
   - 손목 굽힘: 위 ↔ 아래, 무리 없는 데까지
   - **손목 회전: 좌우로 크게.** 11/13에 손목 회전이 부족해서 카메라 x·y·yaw가 정해지지 않았다
4. 다 훑었으면 **휴식 자세로 돌아온 뒤** Ctrl+C로 끝낸다.

### 꼭 지킬 것

- **훑은 곳은 전부 "로봇이 가도 되는 곳"이 된다.** 몸체, 카메라 받침, 다른 팔에 닿을 듯한 곳은 지나가지 않는다.
- 다른 팔은 휴식 자세에서 움직이지 않는다.
- 화면의 `range margin`이 `WARN`(5° 이하)이면 그 방향으로 더 가지 않는다. 범위를 벗어나면 제어기가 잠긴다(STM32 리셋이 필요하다).

## 12. 자동 촬영 (로봇이 움직인다, 토크 켬)

### 12-0. 역할

- **A(키보드)**: 명령을 친다. 화면 안내를 읽는다. 위험하면 Ctrl+C.
- **B(팔 옆)**: 움직이는 팔 옆에서 손을 뻗을 수 있게 서 있는다. 멈추면 바로 팔을 받친다.

### 12-1. 리허설 (로봇 안 움직임)

```bash
tour ~/cal_20261116/tour.json rehearsal05 0.05 TL1 TR1 --simulate --max-steps 6
```

`COMPLETED`와 `토크 꺼짐 확인`이 나오면 된다.

### 12-2. 실행 (리프트 높이마다)

시작 전 확인:

- [ ] 리프트가 훑기 때와 **같은 높이**인가
- [ ] 주변이 훑기 때와 같은가(앞 공간 비움)
- [ ] 양팔이 휴식 자세인가(7-3 사진과 비교, 5° 이내)
- [ ] 마커가 그대로인가(`TL1`, `TR1`)
- [ ] B가 팔 옆에 있는가

```bash
tour ~/cal_20261116/tour.json T05 0.05 TL1 TR1
```

| 화면 | 할 일 |
|---|---|
| `준비됐으면 yes 입력` | 위 확인이 끝났으면 `yes` |
| `Enter = 양팔 토크 켜고 휴식 자세 유지 시작` | B가 팔을 받친 상태에서 Enter. **여기서 양팔 토크가 켜진다** |
| `다음: left → T05-L-03 (6.2s)` | 경로에 사람이나 물건이 없는지 보고 Enter |
| `saved T05-L-03  settle error (raw) ...` | 사진과 명령값·실제값이 저장됐다. 다음으로 넘어간다 |
| 처음 몇 번 지켜보고 괜찮으면 | `a`: 이후 이동은 자동 |
| 끝내고 싶을 때 | `q`: 확인된 경로로 휴식 자세까지 돌아간다 |
| `휴식 자세 도착. 양팔을 손으로 받친 뒤 Enter = 토크 끄기` | **B가 양팔을 받친 다음** Enter |

- 위험하면 바로 **Ctrl+C. 토크가 꺼지고 팔이 떨어진다.**
- 리프트 높이 5개를 같은 방식으로 한다(`T05`, `T17`, `T30`, `T42`, `T55`). 높이를 바꿀 때마다 끝에 토크를 끄고, 리프트를 옮기고, 다시 시작한다.
- `settle error`가 계속 크게 나오는 관절이 있으면 기록표에 적는다. 그 값 자체가 오늘 재려는 "명령값 대비 실제 위치"다. 그것만으로 멈출 필요는 없다.

## 13. 집게 끝 대기 (토크 끔, 로봇 안 움직임, 약 30분)

자동 촬영이 다 끝나고 **토크가 꺼진 뒤** 한다. 마커는 붙인 채로 둔다.

1. 리프트를 **0.30**에 둔다.
2. 표적지를 상자나 탁자 위에 테이프로 평평하게 붙인다. 카메라 화면 **가운데쯤**이다. 이 자리가 `A`다.
3. 왼팔 집게를 **완전히 닫는다.**
4. 손으로 팔을 움직여 **닫힌 집게의 맨 끝을 십자 가운데 동그라미에** 댄다.
5. 끝을 그 점에 댄 채로 손목과 팔 각도를 바꿔 가며 **8번** 찍는다. 각도가 서로 많이 다를수록 좋다:
   위에서 수직, 앞으로 30°, 뒤로, 왼쪽, 오른쪽, 손목을 돌려서 등.

   ```bash
   rawshot TCP-L-A01 0.30     # A01 ~ A08
   ```

6. 표적지를 화면 **오른쪽 앞**으로 옮겨 같은 방법으로 8번 찍는다: `TCP-L-B01` ~ `B08`.
7. 오른팔도 같은 방법으로 한다: `TCP-R-A01` ~ `A08`(가운데), `TCP-R-B01` ~ `B08`(화면 **왼쪽 앞**).
8. **(가능하면)** 리프트를 0.05로 내리고, 표적지를 **수납장 상판 집기 자리**에 붙인다.
   표적지 양옆 마커 중 하나라도 화면에 보이면 왼팔로 `TCP-L-C01` ~ `C08`을 찍는다(`rawshot TCP-L-C01 0.05`).
   실제 집기 위치에서의 검증이다.

- 찍는 동안 끝이 점에서 **1mm도 미끄러지지 않게** 누른다. 미끄러졌으면 다음 번호로 다시 찍는다.
- 표적지 양옆 마커를 둘 다 가리지 않는다. 하나만 보여도 된다.
- 팔이 3 count 넘게 움직이면 도구가 거부한다. 손을 멈추고 다시 찍는다.

## 17. 문제가 생기면

| 나오는 말 | 뜻 | 할 일 |
|---|---|---|
| `identity/state mismatch` | S3 펌웨어가 아니거나 release 폴더가 다르다 | 6장 check, `helpers.sh`의 폴더 확인 |
| `torque is on` | 토크가 켜진 팔이 있다 | 훑기, 집게 끝, 손목 영점은 토크 OFF에서만 한다. 팀원에게 끄는 방법을 묻는다 |
| `current arm pose outside recorded range` | 관절이 범위 밖이다 | `pose`로 보고 범위 안으로 옮긴다 |
| 훑기 중 기록이 갑자기 멈춤 | 범위 밖으로 나가 제어기가 잠겼다 | STM32 리셋 후 그 기록만 새 이름으로 |
| `lift ... outside 0.05..` (계획) | 리프트 명령값이 0.05 미만이다 | 0.05 이상으로 훑는다 |
| `rest pose is within 25 counts of a range limit` | 휴식 자세가 범위 끝에 가깝다 | 7-3 다시 |
| `arms are N deg away from the tour rest pose` | 휴식 자세가 다르다 | 사진처럼 놓고 다시 |
| `arm_ranges.development.json differs` | 계획 때와 범위 파일이 다르다 | 노트북과 Jetson의 release가 같은지 확인하고 다시 계획 |
| `팔이 멈추지 않아 건너뜀` | 촬영 순간 팔이 떨렸다 | 그대로 진행. 많으면 기록 |
| `move did not finish in time` / `terminal settle error` | 목표에 도달하지 못했다(걸림, 과부하) | 자동 정지된다. 팔을 받치고 원인 확인 |
| `정지 미확인` | 정지가 확인되지 않았다 | **양팔과 리프트를 받치고 모터 전원을 끈다** |
| 오른팔 무응답, `TRACKING_FAULT` | 오른팔 통신 문제(기존 문제) | 오른팔은 빼고 왼팔만. 계획을 왼팔 훑기만으로 다시 만든다 |
| `RETRY_CAPTURE` (광각) | 정지 프레임이 부족하다 | 화면 안에 움직이는 것을 없애고 새 이름으로 |
| `REJECTED: arm moved during shot` | 찍는 순간 팔이 움직였다 | 손을 멈추고 다음 번호로 |

## 18. 하면 안 되는 것

- 훑기에서 몸체, 카메라 받침, 다른 팔에 닿을 듯한 곳을 지나가지 않는다.
- 자동 촬영에서 리프트 높이나 주변 배치를 훑기 때와 다르게 하지 않는다.
- 자동 촬영 중 팔 옆을 비우지 않는다. 처음부터 `a`(자동)를 쓰지 않는다.
- 토크가 켜진 팔을 손으로 억지로 움직이지 않는다.
- 펌웨어 교체와 복구는 팀원 없이 하지 않는다.
- 사람이 찍힌 사진을 저장소에 올리지 않는다.
